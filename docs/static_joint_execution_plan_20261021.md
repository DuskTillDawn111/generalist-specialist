# 静态联合部署研究执行计划

计划制定日期：2026-10-21（北京时间）。设计依据见 `static_joint_workflow_design_20261021.md`。
本文安排后续实施和实验；不表示六项目标、DFS 改造或 GPU 实验已经完成。

执行状态更新：CPU 阶段的实际实现、验证和限制见[2026-10-21 交付](static_joint_cpu_delivery_20261021.md)。
实际冻结正式 H=1800s、校准 H=600s；以下为实施前计划，参数冲突时以冻结的 `study-contract.json` 为准。
用户已明确 GPU 暂不可用，本轮仅准备 GPU 作业，未执行校准或确认。

## 研究目标与执行顺序

在已定七模型、四任务及各配置池内，针对同一固定负载联合优化模型、副本和分流。
质量进入总效用，移除绝对质量门槛。纯通、纯专、混合由最优化结果决定。
验证三项结论：声明域内最优、相对强竞争方案的实测表现、相对 DFS 的搜索效率。

顺序为：冻结问题 → 六项评价 → 同域算法与 CPU 验证 → 少量混合校准 → 正式求解与效率 → 独立实测与报告。
每阶段产物是下一阶段输入；证据或预测器变更后，依赖它的分数、切割和证书重新计算。

## 阶段 1：冻结问题和可追溯数据

工作：

- 将已有保留决定、实际 worker 配置、任务能力和配置池成员转为新清单，不能套用历史池身份。
- 导入 16 条模型—任务路径、61 档完成画像、失败档位和未测状态，保留原始来源。
- 导入逐输入质量结果；记录 QA、OCR 等尚缺或参考未冻结的条目，不将资源画像有效性当作质量值。
  去掉绝对门槛不意味着质量缺失可填零；需要的缺失质量记录补齐后才给完整六项分数。
- 冻结任务输入/参考、静态绝对请求率、GPU、H、预热、排空、到达过程、种子和版本哈希。
- 实验身份按实际部署与运行条件绑定，跨池相同条件复用，避免完整候选 catalog 改变导致重复实测。

计划默认参数：

| 项目 | 首轮安排 |
| --- | --- |
| 目标 | 六项等权，各 1/6；质量权重敏感性作为补充 CPU 分析 |
| 质量损失 | QA：1-EM；图像：1-accuracy；OCR：CER；ASR：WER |
| 显存 | 49140 MiB；安全系数沿用本轮 1.110854 |
| 延迟参考 | QA 1000 ms、图像 250 ms、OCR 10000 ms、ASR 3000 ms |
| 能耗参考 | 整卡 450 W，启动摊销 A=3600 s |
| 负载 | 先固定一个四任务负载；具体 λ 在搜索前记录，所有池和候选使用相同绝对需求 |
| 到达 | 固定种子 Poisson；每个比较块使用相同输入及到达轨迹 |
| 正式窗口 | 从 H=600 s 起评估样本量，冻结前统一确定 H，不据候选表现分别调整 |
| 开发/校准与确认 | 使用分开的种子清单；正式三次运行预留独立种子，例如 43/44/45 |
| 搜索域 | CPU 正确性先小域；正式扩展到声明的本轮副本域，路由先 K=4，再检查 K=8 |
| 域一致性 | 首轮关闭额外容量见证，使用分母 1..K 的共同有理数网格 |

实际输入池、λ、配置池清单及窗口长度由本阶段物化为配置，不能在看到胜出结构后修改。
旧闭环饱和吞吐只辅助设定初始问题，不能宣称已认证混合开环容量。
低频任务样本不足时，应在实验前统一加长 H 并更新预算；请求重复不增加质量样本的独立数量。

产物：`study-contract.json`、`pool-manifest.json`、`profile-index.json`、`quality-index.json`、输入与轨迹哈希。
验收：模型身份、任务路径、数据来源、评分参数和失败/未知记录均可追溯；同一条件在各池评分一致。

## 阶段 2：实现六项评价与质量证据契约

代码范围：`config.py`、`prediction.py`、`evaluation.py`、`evidence.py`、运行前检查及 profiling 系统入口。
建议新增质量计算模块，预测、搜索与实测调用同一套算术。

工作：

- 允许 Q>0，使用明确的新效用版本，移除新研究路径上的绝对质量阈值判定。
- `supported_tasks` 在新契约下表示已验证可执行路径，不能残留旧质量阈值过滤后的路径集合。
- 预测质量按路由回放查离线结果；OCR/ASR 汇总编辑错误数和参考长度。
- 处理缺失质量、输出波动、参考版本不一致；不在最终 U 中隐式补零或重新归一化权重。
- 完整输出六项原始指标、归一化值、贡献、总效用和证据状态。
- 质量证据检查继续核验检查点、输入、协议和报告身份；历史实验保持原版本语义。

验收案例：低精度可执行路径仍能参选；改变质量差异或权重可以改变最优模型/路由；
同一批记录的预测侧与评价侧算术一致；缺质量或能耗时不产生完整 U。

产物：六项评价实现、独立算术核对结果、新研究配置与必要的回归测试。

## 阶段 3：实现同域 MILP/DFS，验证主动分流

代码范围：`milp.py`、`optimizer.py`、`system.py`、性能接口和新增共享域/完整方案评价接口。

工作：

- 域清单统一模型状态、路由比例和证据版本；DFS 独立遍历，避免把同一列生成错误复制到两边。
- 两边共享完整六项评分契约，支持任务相关副本画像和完整共驻评价；不把单任务容量当成硬件混合容量证明。
- 更新 MILP/DFS 的质量成本下界、反馈约束、剪枝、缓存与最优性证书。
- 评价接口区分已评分、有效不可行、需补测、测量未解决；实现去重队列、检查点和证据版本失效规则。
- 小域用完整 DFS 校核，较大域增加带有效界的 DFS 作为更强基线。

核心验收：

- 两边完整求解时最优 U 在数值容差内一致，允许并列最优部署不同。
- 全池自由结果不劣于各可行受限解；嵌套域满足分数单调性。
- 构造专用接近拥塞、通用有余量的用例，主动选出总效用更好的分流。
- 构造通用质量损失过大或已有任务繁忙的用例，算法减少或拒绝接流。
- 未知证据、预算耗尽与数值问题不误报全域最优。

产物：同域正确性报告、分流权衡案例、可运行的 CPU 求解和实验准备入口。
此阶段用合成数据及已知证据核对逻辑，不能将它们作为新池真实 GPU 结论。

## 阶段 4：少量混合校准并冻结评价模型

初始预算：全池共用 6–8 个去重探索条件，每条件先做一次完整运行。
选择规则在运行前冻结，具体部署由资源条件和 CPU 初步搜索产生：

- 通用模型多任务共享；通用/专用共驻同时接流。
- 对有竞争力的部署比较接近拥塞时的不分流与分流。
- 覆盖主要任务组成、活跃进程数和声明副本状态，不为每个组合分别建参数。

GPU 作业串行执行，记录整卡功率、启动电量、驻留与峰值、请求队列、端到端延迟及输出。
探索运行用于校准少量参数的服务/干扰与能耗模型；已有单模型画像不重复采集。
服务尾部使用适用的输入相关样本或明确标注的分布模型，不能把均值当作实测 P95。

校准后冻结评价器。留出的运行用于检查预测误差和排名，而非同时用于拟合与最终确认。
若误差足以影响候选排序，优先选择最可能改变最优解的条件补点，并登记新增作业及版本。
6–8 条不是任意复杂干扰模型的充分样本保证；证据不足时保留适用范围和未决候选。

产物：混合校准清单、原始运行、冻结评价器及其适用范围、误差记录。
验收：完整能耗不能靠独立模型相加，服务/能耗未知条件不伪装为已测；所有新增运行能追溯到选择理由。

## 阶段 5：正式求解、强竞争方案与效率实验

在阶段 4 冻结的同一评价器版本下重新运行两种算法，旧代理上的证书不转移。

求解与比较：

- 各配置池执行自由联合求解，优化模型、副本和路由，不限制胜出结构。
- 再求不同部署的最强竞争解、同部署最佳替代路由、禁止分流的全域最优。
- 对 K=4 与 K=8 的嵌套域检查结果；小域数值一致性默认以绝对 1e-6 为起点，
  精确容差写入配置，不将求解数值精度等同于实测分辨率。
- 记录最优 U、有效上界、gap、状态和完整候选域身份。

效率实验：

- 增加模型数、副本档位、分流精度；同一个问题两边共享输入、评价器和可行性规则。
- 记录包括建模的总墙钟时间、首次可行解、达到最终最优值及完成证明的时间、评价次数与峰值内存。
- 小中规模重复计时，例如五次；更大规模设置相同时间预算，比较最好 U 与 gap。
- 冷缓存各自启动；热缓存另报，避免后一算法无偿继承前一算法的搜索缓存。
- DFS 未完成的规模报告限时状态；若 MILP 未更快，如实记录，不删掉反例。

产物：各池计划、竞争方案清单、MILP/DFS 正确性表、效率与扩展性结果。
验收：完成的小域最优分数一致；效率优势必须有对应的时间/调用数证据和适用规模。

## 阶段 6：独立 GPU 对照与最终报告

每池每个固定负载点最多选择四个初始方案，另留一个自适应方案名额：

1. 自由搜索胜出方案。
2. 最强替代部署，其副本与路由重新优化。
3. 相同部署的最强替代路由。
4. 禁止分流的全域最优；若要直接隔离分流收益，可在同一名额中优先选胜出部署的最佳不分流路由。
5. 必要时验证仍可能击败当前方案、有效上界最高的候选；只有预测排名时明确标注为启发式选择。

相同方案合并；最多五个不同方案，每方案三次配对独立运行，共至多 15 次。
三次重新加载分别核算启动电量；每个比较块共享输入与到达轨迹，顺序按预定规则随机化。
不只比较纯通/纯专，不需要竞争方案之间做全部两两实验。
不同负载、种子、预热或代码条件不能以“同部署”为由直接共用记录。

胜出与强竞争方案的保留运行不用于拟合。若其结果使模型或排名改变，返回阶段 4/5，
更新评价器并另立确认运行，已使用的确认数据转为开发证据。
前三次运行是初始重复预算，差异无法区分时报告不确定性或按明确理由增加运行，不强行宣布显著胜出。

最终交付：

- 每池的部署、副本、任务分流、六项原始指标和效用贡献。
- 冻结预测器与声明域下的最优证书、有效 gap 及未决证据。
- 胜出与强竞争方案的配对实测结果和排名稳定性。
- 分流前后质量、排队、尾延迟、能耗的净收益解释。
- MILP 与 DFS 的正确性、效率、失败及预算状态。
- 配置、数据/代码哈希、原始运行和重现入口。

最优性表述分别标记“冻结评价器下有限域最优”“实测比较支持的优势”。
进一步声明实测全域最优，需要未测候选的有效界；不能仅依据少量对照或 DFS 一致性升级结论。

## 作业总预算与停止规则

设正式比较涉及 P 个配置池、一个静态负载点，校准运行数 C∈[6,8]。
初始 GPU 完整运行上限为 C+15P，再减去跨池实验身份完全相同的去重记录；
加载失败、重试和新增补点单独登记，均计入实际作业数和 GPU 用时。

单池为最多 21–23 次初始完整运行。只有当各运行均采用 H=600 s 时，
正式测量窗口合计约 3.5–3.83 小时，另加加载、预热、排空和重试。
实际 H 必须由阶段 1 的请求样本量检查确定，不能将上述时长当作完成承诺。

预算达到后保存最佳已知结果、误差和未决 gap；不通过忽略未知候选制造最优证书。
后续按证据决定是否扩展负载点、副本域或测量，不在首轮铺开整个负载矩阵。

## 本次计划之后的第一项工作

从阶段 1 和阶段 2 开始：整理新池/质量清单，实现质量效用与质量证据契约，
先交付能在 CPU 上完整评分的新研究配置；随后接入同域 MILP/DFS。
实时队长感知的动态卸载另设后续策略实验，本轮先完成静态最优分流。
