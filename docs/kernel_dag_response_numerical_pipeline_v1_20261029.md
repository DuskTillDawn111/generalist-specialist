# Complete repeated-kernel CPU numerical plan

The new `kernel_dag_response_numerical_pipeline_v1.py` leaves the running native
continuation and its entire frozen closure unchanged. The prepared plan is
`artifacts/predictor-kernel-dag-response-numerical-pipeline-v1-20261029-cpu02-prepared/plan.json`.
It binds the independently reviewed continuation, its exact three capture IDs,
the canonical future native final, repeated design and repeated report, and the
complete numerical implementation closure. Preparation reads no future labels
and performs no real numerical fit.

The data sealing step requires the complete native final, all twelve CPU stages
and all sixty measured requests. It reruns the unchanged repeated adapter, which
reauthenticates each native SQLite intake and producer execution claim. Complete
equivalence proofs, catalogs, captures, active-set paths and reports must match.
Only temporary receipt locations can be substituted, after the corresponding
complete proof/export contents compare equal. Caller-rehashed timing, path,
dependency or static proof changes therefore cannot become authenticated data.
Temporary exports close normally after each reconstruction. No native files are
deleted, and no native collection or automatic retry is available here.

The immutable data seal points at the full original exports and retains the
complete sixty-request registry, per-request kernel counts, ordered full kernel
registry digest, accepted/UNKNOWN denominator and complete structural rank.
The original `compile_paths` sweeps every native peer and retains all six feature
columns. Any incomplete supported kernel cohort or structural path-contrast
rank below six stays UNKNOWN. A derivative rank failure at beta zero is not a
structural impossibility gate.

The separate explicit fit command reconstructs the native data again, recompiles
the entire cohort and requires an exact seal match before calling the unchanged
`kernel_dag_response_training_v1.fit_paths`. This uses the independently reviewed
`kernel_dag_response_fit_v1` exact likelihood, endpoint Jacobian, original starts
0/+0.25/-0.25, exact Hessian trust solver and independent gradient-root solver,
original tolerances and the conservative nuisance-adjusted certificate at the
actual fitted root. No variance floor, subset, column drop, optimizer rewrite or
threshold relaxation is added. A solver failure retains its started claim and
stops without retry. Any exception, including a final source guard failure after
a successful solver return, explicitly revokes numerical/native qualification.
The raw solver result is preserved only under
`unauthenticated_response_fit_diagnostic`, with `usable_as_qualification=false`.
All numeric outcomes are training diagnostics; independent
accuracy, physical SM-service identification and prospective qualification are
not inferred.

Once the actual continuation has published, the CPU commands are:

```bash
CUDA_VISIBLE_DEVICES='' OPENBLAS_NUM_THREADS=1 OMP_NUM_THREADS=1 MKL_NUM_THREADS=1 /root/miniconda3/bin/python -m tools.predictor_validation_20261027.kernel_dag_response_numerical_pipeline_v1 seal --plan artifacts/predictor-kernel-dag-response-numerical-pipeline-v1-20261029-cpu02-prepared/plan.json --output artifacts/predictor-kernel-dag-response-numerical-pipeline-v1-20261029-data01
CUDA_VISIBLE_DEVICES='' OPENBLAS_NUM_THREADS=1 OMP_NUM_THREADS=1 MKL_NUM_THREADS=1 /root/miniconda3/bin/python -m tools.predictor_validation_20261027.kernel_dag_response_numerical_pipeline_v1 fit --plan artifacts/predictor-kernel-dag-response-numerical-pipeline-v1-20261029-cpu02-prepared/plan.json --seal artifacts/predictor-kernel-dag-response-numerical-pipeline-v1-20261029-data01/seal.json --output artifacts/predictor-kernel-dag-response-numerical-pipeline-v1-20261029-fit01 --fit
```

These commands have not been executed on actual repeated native data. Sealing
and fitting each temporarily reconstruct the repeated exports. During native
intake reconstruction the outer repeated exports have not yet been written;
the peak additional temporary disk scenario is the larger of one intake rebuild
and one complete repeated export, rather than their sum. No arbitrary CPU disk
reserve is imposed. Actual free space should be checked after the native chain
and before starting these CPU jobs; this numerical task does not gate the
matching → kernel → resource GPU chain.

Fourteen CPU tests cover rehashed export/proof/role tampering, a rehashed seal
denominator, full sixty-response retention, structural rank HOLD, the beta-zero
counterexample, a real sixty-row synthetic likelihood, actual fitted-root
certificate fields, a solver exception that preserves started evidence and a
real source change-and-restore after a synthetic qualified solver return.
The native SQL reconstruction itself is covered by the earlier real SQLite
reauthentication evidence; no actual new native dataset exists at preparation.
