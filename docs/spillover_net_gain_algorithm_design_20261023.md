# 分流的收益、代价与下一版算法设计

本文件分析已完成的五项等权实验，并设计下一版算法；尚未实现新路由或启动新GPU实验。原运行包、权重、稳定性规则和原始记录保持不变。

## 现有算法的不足

当前实现并非单纯的“专用排队且通用空闲就分流”：它会比较同一已观察前缀下的候选Q/T/L/E，并检查mean、p90情景、暴露预算和漂移冷却。但是，这个比较的边界太窄，无法支撑完整任务流的净收益判断。

1. forecast只把当前已观察队列推到完成；没有后续到达，持续文本负载造成的后续竞争被遗漏。mean/p90是两个资源情景，不是已验证的收益置信下界。
2. 同卡各模型共享GPU。G2队列为空只表示该worker当前没有排队，不表示存在独立可免费使用的计算资源。分流既改变该请求的处理时长，也可能拖慢两个专用副本，并占用后续图像/ASR的服务位置。
3. 在线质量使用冻结族级损失代理，物理峰值M变化未知；局部条件效用不能冒充完整实测五项U。
4. 当前漂移反馈用首次active上下文的全量service尺度与实际整个handler service作比，时长语义不一致。下一版应分别比较transition积分active时长、完整completion预测与对应观测，并区分未来到达误差和基础模型误差。

所以，升级目标是比较“现在这一次分流，对当前与后续所有受影响任务的总效用增量”。增加复杂度本身不保证正确，必须有匹配的资源证据和预测验证。

|---|---:|---:|

|被分流请求：关闭臂平均等待|496.129ms|423.302ms|

这说明绕开等待、将部分任务移到另一执行路径确实有局部改善机会。它不等于专用总计算量按相同比例降低，也不证明GPU利用率、系统吞吐或系统平均延迟提高。

同样，不能只挑更快子组来评价策略。分组由开启臂的选择决定，实际对照来自另一轮运行，包含执行波动；这些是可复核的配对描述，不是同次执行未选路径的真实反事实，也不能据此拟合每个输入必然受益的标签。

## 这些改善为什么没有变成系统净收益

|被分流子组的平均变化（开启−关闭）|seed401|seed402|
|---|---:|---:|
|worker等待|-495.471ms|-422.679ms|
|handler service|+1101.469ms|+1206.978ms|
|最终E2E（包含其他阶段）|+603.104ms|+784.451ms|

等待减少约半秒，但处理时间平均多一秒以上，因而被分流子组自身也净变慢。未分流的专用文本子组平均E2E分别增加13.442ms、35.679ms；没有观察到对其余文本的平均收益。不能据这些相关变化唯一归因GPU核级干扰，但必须把这种外部代价纳入预测和验证。

全系统方面，两主配对的T/M完全相同；没有取得截止窗完成率收益。401的正式归一E略改善，效用贡献仅+0.000034251；这来自该次启动能耗较低的摊销，实际测量窗运行能耗反而增加36.532J，含排空的能耗诊断增加约47.38J，不能据此宣称分流节能。402的E恶化，贡献−0.001519392。质量与平均延迟的代价导致主配对ΔU分别为−0.006940297、−0.011201624。

完整记录表明：分流有局部等待收益、部分请求完成更快，但本轮没有系统净效用收益、吞吐收益或已证实的节能收益。

## 新算法：带未来负载与误差约束的滚动决策

以当前固定驻留为起点，先建立可验证的路由内层，再回到部署外层搜索。保留Q/T/L/M/E各0.2、P95权重0，保留原稳定性规则。

### 1. 状态与预测对象

状态包含每个副本的等待任务、执行任务及其条件剩余工作量，实际开始/进展可观测性、文本/图像/ASR/OCR的到达率与输入特征分布、共享执行上下文和过去已发生的峰值显存。不能只用队长代替剩余工作；不可观测部分用带范围的状态估计表达。

服务模型在每次到达、完成和活动集合变化时更新所有活跃路径进展，功率按整板只积分一次。G2承接文本对专用服务速率、后续图像/ASR队列的影响都要计算；质量使用独立画像的条件损失估计，不读取当前请求正确答案。

### 2. 使用相同的未来情景比较候选动作

候选是当前请求交给text#0、text#1或G2。对每个未来情景，三种动作共享相同到达流、输入和底层随机工作量；各分支的实际处理速率仍由自己的共享执行上下文决定，不能强制处理时间相同。

每个分支只改变当前动作，其后使用同一个事先冻结的延续策略，即相同的状态到动作映射；分支状态不同，后续动作也可以不同。随机工作量按情景、任务和到达序号等固定身份寻址，不能按分支事件发生顺序取随机数，否则共同随机数失去配对语义。未来到达从决策时可用的负载分布采样，不能偷看真实后续到达。每次真实事件到来再滚动重算，重新估计剩余状态。单次相对固定延续策略的条件期望改善，不自动证明不断重算后的整段策略改善，最终仍需整轮验证。

### 3. 比较与最终U一致的系统增量

每个分支对相同任务cohort计算Q/T/L/M/E，沿用原任务权重、参考值、截止窗及启动摊销。纳入当前请求、原队列和后续到达任务，计入两专用被拖慢、G2背景任务被阻塞以及相应质量和能耗变化。

优先计算到原600秒全局测量截止并处理有界排空，使T的截止边界、L的最终完成时延和E的窗口边界保持原定义。为了节省计算而使用短预测窗时，必须给窗后两分支剩余成本差提供可验证的界；任意添加一个积压惩罚并不等于原效用，不能据此声称同目标最优。无法给出尾部界时，短窗结果只作启发式，不作收益证书。

物理M应为历史峰值与预测未来峰值的max，而非把同驻留直接视作ΔM=0。若工作区影响缺证据，应保留UNKNOWN或采用有依据的保守差界；同样，缺共享功率/服务上下文时不能补零或者epsilon。

### 4. 只有净收益证据足够时才分流

定义每个情景的收益为`ΔU=U_G2−U_专用`。先比较两个专用动作，再与G2比较；使用同时有效的比较界，控制选候选再比较造成的选择偏差。

概念性的准入式为：

`净收益下界 = 平均配对ΔU − 模拟采样误差界 − 模型/状态误差界 − 截断误差界`。

仅当下界大于预声明实用阈值、保留原容量先验且通过预声明预测风险筛查、决策计算预算允许时，才选择分流。有限rollout和rho先验不构成物理稳定性证书，末段增长与可恢复性仍按原规则在真实运行后分类。没有可靠收益界则返回条件预测/UNKNOWN并使用专用回退，不把一个mean/p90点估计当作保证。

模拟采样界仅覆盖随机模拟误差，不能覆盖服务模型系统偏差；模型误差需要独立校准和适用范围验证。若采用自适应追加情景，必须使用适合连续查看的区间或预分配误差预算，不能反复看普通区间直到显著；误差预算还要覆盖多候选和整段在线重复决策。L、CER、WER等若没有已知上界，不能直接套用有界变量集中不等式或静默截断，需要经验证的尾部假设和相应方法，否则保留UNKNOWN。即使这些界成立，结论也依赖所声明负载分布与模型适用条件，不能承诺每次分流必然更快。

### 5. 限制算法本身的成本

先用可证明的粗界排除无论如何都不可能获益的候选，只对接近的候选增加配对情景；缓存共享状态和前缀充分统计，避免每次重扫全部完成历史。缓存键要包含状态、负载、资源版本和随机情景，不能误合并。

固定计算预算用完且仍不能判定时回退，明确记录未判定原因。截取版本化状态后在运行锁外预测，提交前验证状态版本及动作资格；过期时按冻结规则回退或有限次重算，不能长时间阻塞完成收集来维持旧快照。实际调度延迟和计算负担必须进入端到端实测，不把预测计算开销视为免费。具体预测视野、情景数和时间预算先在独立开发数据上选择，再冻结，不在当前两组结果上调到正收益。

### 6. 区分避免坏分流与创造真实收益

预测更准确能够减少错误分流，但不会自动让原本处理成本更高的G2变快。要取得正收益，必须实际找到等待节省和队列外部收益足以覆盖服务、干扰与质量成本的状态。

先在不改变七模型来源池的条件下，研究请求特征与共同调度：用决策时可见的输入长度、任务类型等预测工作量与质量损失，选择G2相对代价较低的请求；不能事后根据实测快慢或正确答案选请求。若持续后续并发会吞掉收益，可在明确的新动作域内联合选择路由和待启动请求的并发准入，使G2文本执行期间的后续竞争可控。这里不假设能抢占已运行的GPU kernel，也不等同于硬件物理隔离。

延后启动专用或G2背景任务也有代价，必须连同其队列等待、吞吐和能耗一起比较。实现准入应在submit之前保留待启动队列，因为当前enqueue后可能立即发给worker；人为等待仍计入原scheduled到completion，不改变到达/cohort、不丢弃晚到或过期任务。并发控制是新实验因素，应加入同样具备该能力的禁分流控制及单独消融，禁分流只关闭text→G2，不能同时剥夺其并发控制能力。新增动作域后，旧24策略DFS证书不再适用，必须在同一新域重新验证。

## 如何验证新算法确实解决了问题

1. **先补当前驻留的受控动态证据。**覆盖两个文本专用与G2文本/图像/ASR、OCR的相关共享上下文，尤其持续后续到达。分别检查条件剩余时间、transition积分active时长和完整completion预测；按未来竞争和输入长度分层，报告独立验证的误差与覆盖率。不能用当前已选路径样本同时训练并验证。
2. **再做小规模反事实校准。**在明确状态分布下随机化当前动作、按块/运行保留后效应，交错运行顺序并保持输入负载匹配；以整个受影响区间评价净收益。单条请求跨运行匹配只提供描述，不能证明同次执行个体反事实。
3. **冻结后比较路由及对应控制。**核心比较包含现有无未来预测、新未来负载滚动预测、其自身禁分流控制；延迟启发式可作为横向基线。若要声明现有策略或延迟启发式各自的分流效应，还须加入它们各自的禁分流控制。同种子配对、随机/平衡顺序，报告所有任务的等待、service、E2E、质量、窗口完成、显存、能耗和ΔU，不只报告被分流请求。
4. **最后验证完整搜索。**在同一有证据的有限部署/路由域上，让优化搜索与真正枚举DFS使用同一预测器、相同情景及同一目标，比较全部最优集合和实际评估次数。共享模拟器中一致只证明求解器一致，不证明物理系统最优；仍需独立GPU验证。

若新模型认为本配置下不分流最好，正确结果就是主动不分流。外层部署搜索应比较每个部署在相同路由策略族下的最优可证效用，不能为了展示混合分流而强制其获胜。
