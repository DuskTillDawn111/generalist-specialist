# Text2.6之后：七模型池校准、独立验证与同域搜索闭环

四条text2.6运行只能提供一个局部开发切片。到“七池自由搜索＋DFS同最优”，还缺少跨模型／任务／副本的可识别校准、冻结后的独立预测验证，以及新模型下界的证明与同域求解。**不存在不限定预测器结构就能给出的固定最少GPU次数。** 下面给出可生成条件、核验秩、按失败补点的闭环；不是新的执行授权、已通过验证或固定耗时承诺。

配套[机器可读需求清单](/root/autodl-tmp/generalist-specialist-project/docs/seven_pool_recalibration_requirements_20261022.json)包含实际路径缺口和条件生成规则。本文只读已冻结配置、既有设计与CPU扫描，不读取text未完成raw、ASR未完成raw、61/62结果或71–73结果，不启动GPU。失败的零迁移模式继续FAILED，不激活、不重封；新预测器必须另建模式和版本。

## 0. 先固定能声明什么

第一轮只校准固定负载text2.6、image/ocr/asr各.01、原七模型池、原副本档、rho≤.8、49140MiB、原六权重和参考值、相同原生输入／解码／质量合同。校准可改变开发用流量与部署以识别响应，正式搜索负载和效用合同不因此改变。H600与H1800分别验证；只验证H600不能自动支持H1800的排队尾部及正式确认预测。

K=8实际是分母1..8的路由网格并集，包含4/7。每任务可在全部支持路径之间分流，不能局限“一个专用＋一个通用”；允许闲置驻留模型。MILP和DFS必须共享这整个域。若第一轮只验证较小域，只能写该子域的结论，不能叫全七池。

原配置共有31个非零模型副本状态、16条模型／任务路径、61条已有路径／副本画像。按原始安全驻留代理枚举得到1230个非空部署，最多五个模型族共驻；这是**旧驻留代理下的域统计**，不是1230个真实可行部署或新模型剪枝证明。全部21个模型族二元对、102个跨族任务路径对、18个通用worker内任务对都可能需要解释；它们不能由只含ChatQA/G2/OCR的四点识别。

还有9条“某状态执行某任务”没有服务画像：G1 text n3/n4、image n4、OCR n4；G2 text n4/n5、image n5、OCR n5；G3 OCR n4。保持原池不变就不能静默删除这些路径。先核对已有停止／失败证据的精确适用性；单任务饱和闭环失败不自动证明低频或不同活动组合永远不可行。没有确切服务或适用于声明域的不可行证据时，完整预测应unknown，阻止全域证书。不得用零服务填完整预测；零只可用于乐观搜索界。

## 1. 四条件结束后的第一步：检查结构，不先加参数

四个条件为n2专用份额4/7、n2份额1/2、n1份额1/2、n3份额4/7，均G2n1+OCR1、seed51/H600。完成且原生核验通过后，统一抽取每请求sample、alias、开始／服务／结束时间、质量、输入token、生成token、板卡功率、驻留及峰值，保留失败和排空。

分别核对逐路径服务总量、同输入service比值、服务分位数和自相关，再用**实际逐请求服务序列**独立重放FIFO验证延迟记账，比较“实际服务重放”与“历史输入表乘路径均值倍率”。若前者仍对不上，先解决时间线／队列语义，不能靠拟合服务倍率吸收记账错误。实际服务序列仅用于开发诊断，不能送入待预测候选的评价器。

这四点能检查n2的一个局部路由变化，以及n1/n3的两个扩容对照。不能独立识别副本、份额、总忙度、其他模型驻留和任务混合的效应：n1→n2同时改变驻留和服务基线，n2→n3也不是全份额交叉设计；G1/G3/image专用/ASR专用完全没有新观测。即使每请求很多，四次整板运行也不是几千个独立干扰条件。

背景每任务平均仅约6请求／H600，不能覆盖32条输入。先用精确trace计数确认缺口。若做背景服务校准，单独增加平衡采样的开发条件或延长到实际覆盖门槛；不能给未见输入拟合独立倍率。平衡校准的输入编排另声明，只复用同一冻结payload，不能改正式SamplePool、质量数值或路由选择来改善结果。正式目标负载运行仍使用原有输入编排。

## 2. 新模型先选择最小可检验的结构

建议第一版优先尝试**静态全方案上下文、逐输入服务、别名FIFO**，不引入实际overlap或自洽忙度。举例可预声明如下最小共享结构作为待检验假设：

```text
log S(p,n,i | x,R) = log b(p,n,i) + alpha_family(p)
                    + beta_self * A_self
                    + beta_other * A_other
                    + beta_resident * M_resident
                    + beta_mix * H_self
                    + beta_shape * centered_log_b(p,n,i) * A_other

A_m = sum_t q(t,m) * mean_pool b(m,t,n) / (1000 * capacity_factor(m,n))
A_self = A_m; A_other = sum_{j!=m} A_j
M_resident = raw standalone resident sum / fixed budget
H_self = task-route-share entropy at model m, 0 for a single active task
```

这里b是核验身份后的原始逐输入基线，不含旧全局倍率；n状态基线已包含同族多副本影响，不再重复乘副本数。7个family截距＋5个共享系数，共12参数；这只是一个**需先冻结后检验的低复杂度起点**，不是已经成立的物理模型。它假定族间干扰可由聚合忙度解释、n状态残差可共享、输入形状随预知历史b变化；任何一个假设失败，都要报告并针对失败分层，不能全池强行套用。

特征仅来自方案、固定任务流量和冻结输入表，因而没有循环定义；实际生成token／overlap只能诊断。输入token是预先可知，但跨tokenizer不能直接混用未标准化值。若训练显示特定family/path/n的系统残差，再预声明新增项，重算设计矩阵秩和独立验证预算。若必须采用动态交互模型，应先规定唯一解、收敛、未知语义及所有调度状态的界；这不属于最低成本第一版。

原始每请求观测可用于拟合，但秩和覆盖必须在“路径／输入设计矩阵”与“独立运行块”两层报告。每输入重复可识别shape效应，不会补出缺失的模型族截距或驻留／活动混淆。还需记录奇异值／条件数、每模型族与每副本档的留组误差，不能只报满秩或总R²。

## 3. 可执行的分阶段条件设计

所有下列条件先做CPU生成／身份与代理容量检查；实际运行仍受原稳定性、rho、显存和排空规则约束。基于原基线的设计负载是实验起点，不是已知实际rho；实际超限应保留失败、降低该开发条件并重新声明，不能放宽.8。

| 阶段 | 条件生成规则 | 解决的识别问题／停止门槛 |
|---|---|---|
| A：基线身份与缺口 | 逐项核对61条基线和9条缺口；每模型任务、每n至少覆盖全部冻结输入。已有身份等价证据可复用；否则只补缺失／不等价项 | 缺口不能完整评分又不能合法排除时，全七池门禁保持关闭。已有61档不必机械全重测 |
| B：单族开环锚点 | 7族n1，通用以text为代表、专用以自身任务为代表；每族两档原基线压力.15/.35。流量 `q=r*n*1000/mean_b`，其余路径关闭（校准子协议）；相同输入完整覆盖 | 14个候选条件提供self压力变化与family截距；同一族的其他任务基线仍需A的输入身份检查。n1固定驻留时不能单靠这14点分开resident系数与family截距 |
| C：固定驻留、分开活动 | 对21个族对各先指定代表路径，固定两者常驻。victim压力.15，另一族依次0/.15/.35；G2相关族对先做，其余按秩缺口选取 | 63个候选条件而非承诺全执行；0是空闲常驻，不是卸载。与B的单族条件对照分离resident和active。两条路径同一运行均有输出时可识别方向残差；不能因此假定所有102个任务路径对等价 |
| D：同worker任务混合 | 三个通用各6个任务对，共18对；每对总基线压力.35、先取1/2:1/2，再取1/4:3/4；只对秩／残差需要的对实施，保留每条路径全输入覆盖 | 单任务及混合对照识别H_self；text+OCR、text+ASR、text+image均不可只用text结果替代。低频OCR完整覆盖可用专门开发请求编排，禁止从6个背景请求硬拟合 |
| E：副本与多族压力验证 | 七族原有31个非零状态都列入覆盖矩阵；在原驻留代理可容纳且有同n基线的上下文，替换n1→各n，取同族总压力.15/.35、保持一个固定partner压力.15。再从3–5族可容纳部署中选A_other、resident、mix特征极端与中点 | 校准n-state基线残差是否共享，检验两族规律能否迁移三族以上；不能以n1配对覆盖替代高n或多族验证。状态若无法在给定partner下共驻，换低驻留partner，不能从原池删除该状态 |
| F：目标负载完整方案 | 固定text2.6/.01，先加入全部可用通用族text候选、G2/G3互分、背景路由到专用／通用、闲置常驻，以及各可行副本状态的近容量／低容量竞争者；按预测不确定性与强竞争性分批选 | 训练阶段候选可自适应选点，但所有选择和失败入账。只选择n2目标结构会缺少纯通、n1和其他通用竞争者，不满足全池覆盖 |

这里给出的是候选生成器，不是直接运行14+63+36+全部状态的固定队列。执行顺序建议B先7族低档、再补self高档；C先G2与其他六族的固定驻留三条件；随后CPU合并设计矩阵，逐次选择增加秩或最大降低条件数／覆盖最大残差的点。每轮选择冻结后再运行；每轮结束记录“为何选、覆盖了什么、还缺什么”。显存／活动强耦合无法靠一个新点解决时按完整小块补测。

最低数据量由实际模型的参数秩和全域覆盖要求决定。若共享12参数模型失败并转为任意路径对效应，仅n1就有102个跨族任务路径对，单纯测21族对代表路径不足；若再允许每n独立效应，预算会继续增长。必须让用户看见这项成本，不能保留原少量实验预算却升级全域声明。

**每条校准路径建议最低完整输入覆盖门槛**为每个sample至少3个成功观测、覆盖至少2个独立执行块；该门槛是拟议采样设计，不等于精度保证。需要先根据服务时长、别名分配和payload计算可行时长。一个到达任务率.01的H600目标运行不能达到该要求，不能把H600固定测量窗口误当全部校准条件的硬上限。受预算限制达不到时保留缺口，不假装完成。

## 4. 能耗、显存与质量不能顺便“校准成功”

新能耗必须有真实整卡积分。固定text2/G2/OCR的worker数恒为4时，intercept与每worker系数不可分；四条件虽改变n，却仍与模型身份、忙度混淆。先尝试非负的低维整板公式，仅保留秩可识别的截距、总原始需求与worker项；B/C/E提供不同需求、驻留和worker数，再用独立部署验证。每族idle增量或模型相关功率系数若未增加独立加载／活动条件，不应加入。启动能耗按已有合同独立记录，与正式窗口能耗分开；不把旧越域功率系数当新证据。

M保留真实驻留与采样峰分开，拟议最低完整预测可用 `M=max(c*raw_residency, seen_exact_context_peak)`，c明确是新冻结函数的一部分，不是物理安全证明；是否保留原safe_factor也须与原合同一致。少量已见峰值不会为未测高n组合提供物理上界。容量和显存预测误差导致约束错误时须判验证失败，不能靠宽松效用阈值掩盖。

Q继续原逐输入质量与实际输出评分，不设绝对质量准入。每条执行都核对actual Q与冻结重放Q的差；若并发／负载引起系统输出变化，原Q可分模型不再通过验证。不得改质量数值使n2胜出；应新增质量模型／不确定性或收窄可声明域。32输入×固定份额的周期覆盖在每个条件单独报告。

## 5. 冻结、独立验证及失败分支

开发可用54–59等新开发种子，但只是拟议分配，prepare前需核对元数据未占用；不读取保留结果。新独立验证建议81/82，71–73继续保留最终确认，旧61/62不用于新模型“再验证”。模型公式、特征、参数、域、逐输入表、评分／rho／稳定性／M/E/Q合同、代码与阈值全部冻结之后才产生新验证运行。

验证不能只有目标text四条件重复。先确定三个panel，并写入机器清单：

1. 同结构新trace：冻结的text2.6四条件，81/82配对，用于检查排序／误差及n1/n2/n3比较。
2. 结构留组：预留从未参与拟合／调结构的G1/G3、通用多任务、n状态替换和三族以上组合；用覆盖算法选方案，直到每族、每支持任务、每非零n状态及模型声明的特征区域都有独立覆盖。被合法完整证据排除的路径单列，不能当作验证覆盖。所需方案数由覆盖计算输出，不声称两条独立运行即可验证全池。
3. 搜索相关挑战：冻结预测器下的自由搜索incumbent、最强其他部署、同部署替代路由、最优n1限制、最优no-split（可行才有）与未决上界最高候选，物理方案去重。开发算法可在未验证模型上产出明确标注的候选，但正式gate保持关闭，不能提前给validated搜索证书。

同一验证数据若用于修模型，就转为开发，下一版必须新验证种子／结构条件。验证panel的选择只能依据冻结模型和开发数据，不能看验证结果挑“能过的条件”。七族相关参数共享时尤其需要按族／副本留组，逐请求随机拆分训练与验证会泄漏同一运行干扰。

原服务／E／M／mean／P95／Q／U阈值不得因失败放宽。它们是基本误差门槛，**不是排名可分辨率**：旧U绝对误差容限.10无法支持约.00013的优势。新排序主张还需预声明实际比较的最小有意义差δ、成对误差范围及配对重复；未明确δ之前只允许说“误差门槛内”，不能说“可靠选出真实最好”。rho临界、稳定性、错误和排空单独判断；预测可行但实测失败即失败，不以平均U补偿。

H600通过后若最终结论要用H1800，至少在新冻结版上用独立H1800 trace复核排序、尾部和六项误差；只通过H600时继续限定H600。独立验证是对已声明模型适用域的经验支持，不能证明所有未测真实GPU身份的最优性。

## 6. Bounds与MILP／DFS闭环

详细证明见[路由相关服务下界评估](/root/autodl-tmp/generalist-specialist-project/docs/spillover_route_load_search_bounds_assessment_20261022.md)。新模式不能复用FAILED迁移适配器或旧参数下界。

| 项 | 何时仍成立 | 新模型第一版处理 |
|---|---|---|
| Q task列 | 原冻结逐输入质量和路由／输入映射不变 | 数学上仍精确；实际质量复现另验证 |
| 服务／L/P/T | 对新完整函数的全上下文逐输入下包络ell可证明，FIFO alias分配相同 | 无证取0。log模型可用有界特征区间作保守log下界再exp；不能以实测最小service当域下界 |
| rho容量 | 完整rho仍用同输入池mean S，下界压力用mean ell | 仅下界rho>.8才剪枝；完整候选用新S检查.8。下界0不改变真实约束 |
| M | 完整新M明确定义含有可证明的加和分量 | 仅用该函数分量，未证取0；旧learned memory剪枝不继承 |
| E | 非负完整整板公式可拆常量／状态／route贡献 | 只保留证明成立的分量；上下文耦合剩余取0 |
| 完整身份residual cut | 基础成本B≤新完整成本C | 可保留，不要求C可分／凸；不能把身份反馈跨部署转移 |

服务下包络必须覆盖所有兼容部署、路由和允许输入，未观测但模型声明有定义的组合也包含在内。特征区间松弛允许取各项不可同时达到的最小值；它只是数学乐观界，不能当物理稳定性保证。dynamic模型还需覆盖所有调度状态，否则禁用对应界。未知候选保留未决上界，不能当不可行删掉；零界不足排除负效用incumbent时，全域gap应保持未闭合。

实现阶段需同时适配performance、prediction逐输入FIFO、validate_plan、M/E辅助接口、SearchSession、MILP／DFS全部capacity/memory预筛及cache。仅返回surrogate=None会触发旧模式推断和默认剪枝，不足以安全集成。不得改冻结v5；另建新source快照。

先在小完整子域逐身份验证B≤C、每个分支上界覆盖所有后继、所有剪枝合法，比较MILP、带界DFS、plain DFS同最优；随后全七池K逐级扩大。三算法完全共享模型版本、输入trace、rho、稳定性、域、容差和预算。DFS未完成就报告限时与gap，不能以“目前incumbent相同”称同最优。并列最优允许不同身份、同最优值。效率统计包括构造与证明时间、完整评价次数、RSS、冷／热缓存，不能继承旧效率倍数。

最终可以同时得到“新冻结预测器下有限域全局最优、MILP与DFS一致”和“独立GPU强对照支持或不支持收益”两个结论；前者不推出真实GPU全域最优。若预算只能完成局部校准，就交付局部模型和未覆盖清单，不升级为全七池闭环完成。
