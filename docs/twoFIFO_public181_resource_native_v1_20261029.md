# Exact public181 native resource training producer v1 (2026-10-29)

This new implementation prepares and executes only the eight training attempts from the reviewed `public181_resource_campaign_v1` cpu02. Existing matching collectors, fresh validation plans, campaign source, and their evidence are unchanged. Preparation and the author tests use CPU only. No GPU execution or independent prediction qualification is claimed by this document.

## Collection contract

Each attempt starts four fresh resident workers, runs all eighteen original priming inputs, and retains the actual processed START/phase/RESULT/handler-READY history and actual worker specification. A maximum ten-second asynchronous READY settle check occurs before the pre-cohort anchor; an unfinished or unproved prefix fails rather than being coerced into an empty queue. The settled snapshot defines the anchor; the first cohort arrival is exactly 300 seconds later. Priming, settling, and this wait all belong to the same startup energy interval. The 300-second budget is a declared collection budget, not an empirical prediction-speed result.

All 181 original requests are registered before startup and enqueued at their original chronological arrival times without waiting for previous RESULT/READY. There is no new global admission cap, batching, resource partition, or weight-sharing behavior. The measured interval lasts exactly 90 seconds, followed by a fixed 120-second drain. Late or unfinished offered rows remain explicit; they cannot be deleted to improve the denominator. An incomplete request is retained as an outcome, while a failure to authenticate the fixed observation stops the campaign before another attempt can launch.

All full history copies and raw checkpoints finish before the first arrival or begin after the fixed drain. The reviewer checks the complete separately durable activity ledger. Monitoring begins before startup and ends while workers remain live; cleanup closes workers only after the final owned sample. The reviewer independently reconstructs the actual executed registry, stdout protocol and all clocks, READY lifetimes, ownership, lifecycle, original arrivals, durable claim and supervisor command/source binding. An explicit partial-protocol adapter checks every retained sender and START/PHASE/RESULT/READY prefix, allows unfinished observed phases and missing outcomes, and checks every present successful output through the original CPU reparser. Available complete successful responses still run the full existing verifier. A partial response never becomes a successful label. Forced shutdown reports are preserved, while the supervisor must still prove all owned descendants exited; a completed earlier fixed observation is not automatically rejected because a later worker needed forced cleanup. Caller role flags alone do not qualify an execution.

## Resource and quality intake

`twoFIFO_public181_resource_execute_v1.py` creates new source-bound execution identities and a frozen complete executor/reviewer/intake/worker source closure. The original quality catalog `artifacts/static-study-v6-20261021/inputs/catalog.json` is explicitly bound to the source transfer and every new plan. Every prepared reference is checked against exact task/input identity and all union22 input payloads.

`twoFIFO_public181_resource_review_v1.py` derives one intact tuple per actual attempt: startup joules, startup-to-cohort owned sampled peak P0, measurement-through-drain owned sampled peak, and measurement board joules. Startup includes priming and the 300-second wait, occurs once, and is not amortized in the producer. Measurement energy excludes drain; drain joules are diagnostic. Memory retains all residents and combines P0 and future peak by maximum. Samples after the fixed drain cannot enlarge that memory peak. Safety factors and once/3600 startup amortization remain downstream scorer operations.

`twoFIFO_public181_resource_intake_v1.py` requires all eight distinct training-native reviews and source plans before any labels, re-runs each complete native review and requires exact reproduction, then builds two complete four-candidate resource blocks. It projects only resource fields into the frozen closed tuple catalog interface, preserving the same-attempt tuple. It accepts at most eight distinct provided source reviews, and always retains all eight planned rows: missing or unqualified resource observations stay UNKNOWN. It creates the complete catalog only when every planned attempt has a rederived resource tuple; it never removes unknown attempts or reweights survivors. Incomplete or late requests do not by themselves reject a valid fixed-window M/E observation. It infers no queue/resource probability coupling.

`twoFIFO_public181_quality_labels_v1.py` explicitly adapts the new native training schema to the unchanged `prepared_references`, `score_result`, and `sample_totals` kernels. It preserves all 181 raw output references as JSON pointers and sums original errors/reference units per task before division, then uses original offered rates to weight Q. Failed, absent, or late outcomes leave Q unknown. It never uses old frozen expected Q as actual Q. The pure helper authenticates no native evidence; the intake completes that authentication before invoking it. These are training labels and a future quality-model interface, not a fitted quality predictor.
