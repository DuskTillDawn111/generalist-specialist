# 静态搜索修复与验证

本轮修改实际实现，保持历史源代码、观测与质量门槛不变，没有运行 GPU 实验。

| 原问题 | 修复 | CPU 验证 |
| --- | --- | --- |
| 分流改变到达数，吞吐分母出现伪损失 | 固定任务请求轨迹，分流只选接收副本，吞吐使用 N_off | 0.02 QPS 下纯路由与多种分流均为同样 3 个请求、T=0 |
| 字典顺序改变到达相位与部署结果 | 按任务名称生成种子与排序，不用任务下标当身份 | 交换 text/image 字段顺序，部署、路由、分数一致 |
| 联合搜索只支持 K=1 | 同时枚举已测副本与所有任务路由 | 含多个副本、多个模型和分流的独立完整枚举 oracle 一致 |
| K=3/5 丢掉 K=2 的合法解 | 网格为分母 1..K 的并集，补容量边界见证 | K=2..6 保留 50/50；非网格容量边界也能找到合法分流 |
| 固定全局上界几乎不剪枝 | 上界包含当前路由的服务成本和部署显存 | 固定双模型、双任务 K=10 有实际 bound_pruned，完整预测少于原 121 个叶子 |
| nominal 被当成稳健方案 | 显式 nominal/robust 策略 | rho=.8 的名义方案在倍增服务压力下被 robust 拒绝 |
| 规划与运行时长、到达过程不一致 | 计划保存 problem；运行继承或重预测，标明最优性是否转移 | 真实 mock 子进程记录的轨迹哈希与对应预测一致 |
| 运行提前终止缩小 cohort | 发送前登记所有正式请求 | 注入中止，未来请求仍记为 incomplete，原分母保留 |
| 能耗缺失仍可能产出总效用 | 五项等权，未知能耗 U=null，整方案画像匹配 | 缺失、其他部署、其他压力场景均不复用能耗；fixture 验证积分和公式 |

## 上界和证书

最大化负成本 U 时，无排队服务延迟提供 L/P 成本下界，T 与整卡 E 的零值提供其非负成本下界，已部署显存是精确成本。分流后的服务样本通过固定轨迹和共同路由器获得，因此不会用理论流量比例代替有限请求的实际路由计数。该上界与模型之间是否有非可加能耗无关。

完整枚举 oracle 独立实现周期到达、轮询、FIFO 和分位数算术，避免仅比较两段调用同一预测器的代码。历史 `tests/reference_plans.json` 保留原分数；这些分数由旧语义生成，修复后的代码不再以复现错误分数为测试目标。

预算耗尽、能耗未知、覆盖任务没有请求观测、有限域无解、名义可行和稳健可行是不同状态。稀疏任务无观测返回 `INSUFFICIENT_COHORT`，应事先为所有对照统一延长 H，而不是为某个候选补请求或填零延迟。

## 能耗使用方式

当前真实模型池没有完整整方案能耗画像，静态入口会返回诊断候选及 `U=null`。demo 中的画像是明确标注 `synthetic_fixture` 的 CPU 算术数据，不能用于真机结论。

预测画像存于 `catalog.energy_profiles[energy_key(..., catalog=catalog)]`。key 绑定模型/副本、正流量路由、负载、H、seed、到达过程、服务压力倍数及模型服务/容量/显存参数。记录包含 `kind`、`scope=whole_gpu_board`、`coverage_valid`、`run_joules`、`startup_joules` 和来源。未匹配的方案保持未知，不从别的方案或单模型独立电量外推。

后续授权真机测量后，运行结果中的 `energy_evidence` 保存匹配 key、功率序列与加载/预热加正式窗口的区间积分。先完整测量再建立画像；预测证据与观察到的正式 U 分开报告。改变画像、硬件或质量政策后需要新的对照，当前 CPU 验证不能消除同卡干扰、服务尾部分布和历史测量转移的不确定性。
