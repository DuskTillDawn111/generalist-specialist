# 收益波动与自主搜索／DFS闭环

当前目标保持为：在冻结七模型池、原六项质量／吞吐／均延迟／P95／显存／能耗总效用及原稳定性规则下，自由选择部署、副本数和路由，检验是否主动选择专用多副本向通用分流。不得预设混合部署或分流必须胜出。

这意味着应继续选择和验证，而不是因收益反转停止搜索，也不能依据这两个种子反复选一个有利路由。

## 本轮实际执行的搜索问题

新独立工具`development_oracle.py`读取已冻结开发模型与真实画像，以原make_trace→SamplePool→expanded SWRR→逐alias FIFO计算原六项诊断效用。服务、显存、能耗模型尚未独立验证，正式U始终UNKNOWN；域外数值外推单独输出。GPU原生质量须另行实测，历史逐输入质量重放不能冒充并发native输出精度。

`search_development.py`用同一评价器驱动现有MILP、有界DFS、plain DFS；每次独立进程及新缓存，不预先填入全域效用表。允许G2为0/1副本，text为0/1/2，image及OCR为0/1，ASR为0/1/2。文本使用原K2并集加分母32的所有可执行family pair；背景使用K2。共40个覆盖四任务的部署、7508个完整部署／路由标识，每种子相同。纯通、纯专、混合、不分流及一文本副本都在域内。

G1、G3及更大副本数仍存在预测缺口；本轮有限开发域最优不得扩大成七模型池最优。`diagnostic_planning_feasible`只反映开发点服务算术平均形成的rho≤.8、预测M预算和FIFO drain；实际稳定性仍UNKNOWN，没有替代原native稳定性规则。

分别搜索107/108，并用同一plan的mean(U107,U108)选出跨开发种子的静态方案；逐run U不变，均值目标明确单列。未知种子不能跳过后取均值。两种到达种子的平均仍未覆盖服务漂移和能耗误差，不能当作稳健收益保证。

## 剪枝、正确性与效率

零下界版本是保守起点。开发服务函数为S=b exp(αfamily+βself Aself+βother Aother)，其压力与斜率非负，故逐输入b exp(αfamily)是该数学模型的下界。减少服务并删除其他任务只会减少FIFO等待，可得到每任务均延迟／P95／窗口外请求数的下界。原逐输入路由质量精确重放，NNLS内存中非负驻留／worker项形成加性下界，未证明的能耗项先用零。

这些是显式开发函数的数学下界，不是物理GPU性能界。保留原无效下界和未完成尝试，不通过单画像mean对耦合共驻组合做不成立剪枝。

效率报告同时给完整评价次数、总墙钟、是否完成及gap。限时MILP不能与已完成DFS直接计算“同证明工作量加速比”。一次运行不冒充五次独立重复的稳定效率结论。
