# v59 exact-cutoff simulated lifecycle engine

This isolated engine connects the v49/v24 scheduler checkpoint component to an actual main DAG lifecycle loop. It does not modify v21, frozen v58/forecast/profile sources, routes, admission policy, owner FIFO, utility weights, or stability rules. It is CPU predictor continuation, not native GPU observation assimilation.

`ResumableLifecycleDagPhaseModel.forecast(requests, original_now, original_deadline, drain_deadline_ns=original_drain, pause_at_ns=cutoff)` returns a JSON-safe checkpoint at the exact requested integer cutoff inside the original measurement window. Cutoffs at/after the measurement deadline are explicitly unsupported. A fresh instance with the same original public request list, immutable DAG/provider/source contract, and original windows can pass that envelope as `checkpoint=` and optionally pause again later.

The saved state retains the complete future arrival cohort, current owner FIFO queues, original running DAG/dependencies, active reference work, absolute host release heap, node completion clocks, pending parent receipts and worker READY events, `owner_last_ready`, all original accounting/resource transitions, diagnostics, consumed event budget, scheduler/oracle/mark history, and sealed cumulative SAVE budget. Parent RESULT time and worker READY time remain distinct. No global cap of one or two requests is introduced.

An arbitrary cutoff can lie inside a previously accepted constant-rate event interval. The engine preserves both that interval's original decision time and its next absolute event boundary. Scheduler state stays bound to the original decision time; it is not relabeled as a new observation at cutoff. Remaining work and resource/queue integration are computed from that interval's saved origin. On continuation, the same accepted interval finishes before the next dispatch/scheduler call. This avoids changed integer completion rounding, redundant lifecycle observation, extra hazard integration, and budget redraw. Resource transitions and diagnostic integration preserve their original interval segmentation across repeated JSON pauses.

Import uses pure structural and provider consistency checks, not the old v10 checkpoint import (which re-executes the prefix). It validates detached engine, queue sidecar, scheduler, absolute clock, future cohort, resource prefix and six-term prefix state before changing destination objects. Scheduler/oracle/mark/diagnostic replacements are staged and rolled back if commit raises. The caller must exclusively own paused instances; this is not a threadsafe live scheduler update.

The six-term prefix stores original identities/routes/arrival times and received result times, full-cohort task membership, completed-by-original-deadline IDs, nonoverlapping measurement energy and peak memory through cutoff. It deliberately does not average partial P95s, reestimate quality from outputs, apply memory safety factor twice, or amortize startup twice. The existing scorer continues to own original Q/T/L/P/M/E arithmetic and equal weights. Forecast completion still returns the full original cohort and whole original measurement energy so it can be scored at original `now`; callers must not add the same prefix energy again.

Supported scope is intentionally explicit: exact v49 scheduler and component-supported real v24 hazard/mark/prior/handoff classes; exact v6 `DagQueueDiagnostics` or none; declared deterministic stateless providers with no mutable RNG execution state. The v24 keyed `SEEDED_UNIFORM` configuration and already sampled sealed budget are retained; there is no process-global Python/NumPy RNG restoration claim. Different queue sidecars, unknown extra component fields/classes, unsupported initial pre-service state, and old/new schema mixing are rejected. The original all-idle/same-holder UNKNOWN paths remain UNKNOWN. Hidden mutable provider globals are outside the declared contract.

At an inclusive drain cutoff, zero-duration diagnostic finalization supplies the full active-key rate domain with zero rates. It consumes no work and calls no scheduler. This avoids v21's v6-sidecar failure from passing an empty rate map when active work remains at drain; v21 itself remains unchanged.

Validation results and source receipts are recorded separately in the CPU report. Passing these tests certifies serialization/continuation semantics for tested supported fixtures, not physical interference accuracy, native online assimilation, or deployment qualification.

This change validates simulation checkpoint equivalence only. It deliberately retains v21's held-context-to-binary-reference-progress approximation for compatibility; physical context ownership still does not identify SM service. The newly planned stage-response provider is not connected here, so this work does not fix that main predictor's scientific limitation. The stateless-provider requirement is a caller declaration, not proof that hidden mutable globals do not exist.
