# 四独立 CPU 进程的新鲜预测封存（v16）

`learned_campaign_seal_v16.py` 是 v16 编译表示的生产入口。它复用独审完成的 v15 数值预检、完整训练索引、声明历史边界的操作训练闭包与原 v5 封存门；不运行 GPU，也不把预检预测用作待封存预测。

入口首先要求相同计划、配置和原四候选的完整 57 请求数值预检，检查 v16 表示、原图未丢节点/边、拟合值未改。原六项等权效用、原稳定性和阈值、到达、窗口及 deadline/drain 沿用原计划。所有运行源、训练来源、公共输入/路由、预检证据及四份 worker spec 均在新预测前冻结。

冻结后，`learned_campaign_parallel_v16.py` 同时启动四个独立 Python 进程。每个进程先核验冻结源，再新建实际 `learned_availability_forecast_v16.LearnedAvailabilityForecast`，确认其实际使用的 availability raw SHA 都在完整索引中，执行所属候选的完整请求队列，最后再次核验冻结源。每个候选最多处理 5,000,000 个事件。输出文件已存在会拒绝运行；UNKNOWN 或不完整结果不能借用预检填充。

监管进程使用有限正数超时；启动异常、非零退出或超时均失败，并逐一尝试终止和回收已启动进程。父进程再核对回执与监管记录的 PID、候选/spec/protocol、完整 cohort、实际训练 raw 和编译保持声明，随后才执行 `_cells`、`check_complete` 和原 `seal_predictions`。最终源核验失败会将已写的 `predictions.json` 隔离为 `rejected-predictions.json`，同时写失败回执。生产输出目录必须新建。

CPU 验证包含原 v11 采集前门兼容性、冻结后四次新建、预检未复用，以及缺失 raw、源变更/删除、PID 不符、图被修改、UNKNOWN、旧输出、监管失败和末次核验失败等拒绝路径。监管测试启动真实的四个小型独立 CPU 子进程，并测试超时、非零退出、部分启动失败和清理异常。数值生产夹具替换了模型，因此这些测试不能证明真实预测精度，也不代表已执行完整生产封存。

实际完整 v16 数值预检和生产封存由主对话安排；本实现任务不启动 GPU，不声明独立验证精度或分流收益。独立审阅完成前不应运行生产封存。
