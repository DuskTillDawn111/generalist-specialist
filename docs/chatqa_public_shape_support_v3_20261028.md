# Public ChatQA shape support (2026-10-28)

`tools/predictor_validation_20261027/chatqa_public_shapes_v3.py` implements a CPU-only public-input path through the frozen ChatQA formatter and tokenizer. It loads tokenizer JSON assets with `AutoTokenizer`, local-files-only, PyTorch/TensorFlow disabled, and an empty GPU visibility environment. It does not load model weights or create a CUDA context. It verifies actual formatter Python, worker configuration, protocol, classmap and tokenizer files against the frozen training source receipts before using them.

The native formatting is the actual pinned plain System/User/Assistant prompt, with the explicit BOS token and `add_special_tokens=False`, preserving the full context and question. The tool does not replace it with a generic chat template or truncate the public input. Token ID hashes and tokenizer/library versions are retained.

The final artifact is `artifacts/predictor-chatqa-public-shapes-v3-20261028-final02/report.json`. It checks both real captures in metadata, light and natural domains: all 24 ChatQA request input-token counts agree with the CPU tokenizer. These are eight requests per domain across two captures, two replicas and **two unique public text inputs**, of lengths 414 and 4,514. Replicas/domains do not create extra unique inputs or independent capture runs.

From real metadata prefill records, the tool derives 673 module shape rules and verifies 5,384 actual module observations. For 672 modules, operator positions equal the public input-token count; `lm_head` retains the last position only. Each rule requires consistent implementation, declared dimensions, selected named weight logical bytes, tensor dtypes/element sizes and output relation at two distinct measured lengths. Actual logical bytes and declared dense GEMM FLOPs must equal the projected values. Batch remains 1. Unsupported relations are UNKNOWN.

The complete light prefill templates each contain 3,829 actual kernel launches, including non-affine kernels, with exact observed kernel names, order, grids, blocks, resources and other signature settings. At each measured length the sequence agrees across both captures and replicas. These are retained as exact observed training-shape templates, with source SQLite/parsed/raw receipts. Host-gap durations are not copied into a new natural timing prediction.

The two lengths have a union of 2,401 affine execution configurations. For each measured length, 1,793 configurations have projected feature vectors inside the corresponding exact regression-group convex hull, and 1,343 additionally have an accepted duration fit. The union count is not the kernel count of a single template. Every configuration retains independent feature-support and model-acceptance fields; failed residuals and incomplete target samples remain UNKNOWN.

`--queries <json>` accepts a list of `{pool_id, sample}` records with the same public sample schema as the frozen formatter. It computes token counts and prefill affine covariates without running the model, then checks each exact training group for affine-subspace and convex-hull support. It also reports whether the exact token length has an observed prefill template. It compares public task/dataset/context/question content independently of IDs or reference answers, so renaming an existing input cannot produce heldout independence. Exact replay-template availability requires matching the same pool/content pair.

A new public content value at a measured token length can have an observed-shape template candidate and supported affine covariates. This does not prove its complete launch sequence is identical. The tool explicitly keeps unseen-content sequence and launch-grid transfer UNKNOWN. A new length between 414 and 4,514 may be inside some affine feature hulls, but dispatch thresholds between the two lengths are not established, and its complete kernel order/grid remains UNKNOWN. Dispatch settings that differ between the observed endpoints stay separate exact groups; the tool does not interpolate them.

Decode count, EOS/output length, complete non-affine feature models, host gaps, and natural timing are not derived from a previous training response. Thus this is a public-token/shape implementation with exact observed template support, not an end-to-end heldout request predictor. The next training additions should measure genuine independent inputs at targeted intermediate lengths around each observed configuration change, retain separate algorithm regions, and independently check any proposed public-shape-to-template dispatch rule before it can instantiate a new length.

Focused validation: 50 tests pass across public-shape, real-intake, frozen baseline and exact bridge suites. Eleven public-shape CPU tests cover shape consistency, byte/FLOP evidence, fixed last-position heads, batch/extrapolation rejection, joint hull constraints, and pool/content identity. Fixtures are software checks only; the 24 token and 5,384 shape matches above are the separate real training evidence.
