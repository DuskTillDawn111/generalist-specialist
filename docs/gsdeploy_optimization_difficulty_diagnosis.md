# GSDeploy 优化问题难度与一次预测认证诊断

2026-11-02。**低 K 下的快速认证确有数学和枚举证据：有效部署域较小，原 Master 的逐路由质量、服务和资源下界足以排除竞争方案。它并非对所有规模都容易。当前预测器又缺少随路由负载变化的 GPU 执行干扰，因此不能把这一结果推广到强动态共驻场景。**

## 3. 实验 B：一次完整预测怎样完成认证

### 原 Master 的含义

`gsdeploy/milp.py` 保持不变：每模型副本状态 one-hot，每任务选择一个路由/副本候选列；连接约束保证正流量模型按同一副本数驻留。加上总显存必要界和跨任务聚合 rho≤0.8，最小化 epigraph θ，**成本定义为 −U**。

全局成本下界 B(z) 包括：驻留显存成本、启动/worker能耗、逐路由精确冻结质量、非负路由能耗和板级截距、同任务孤立 FIFO 的 Mean/P95及窗口未完成数。当前每任务请求不足1024，原 `floor()` 确实重放该任务的逐输入队列；删除其他任务使同一worker等待不会增加，所以是安全下界。超过1024的原分支才转为无等待逐输入服务界。

这意味着“仅一次完整预测”仍先做了8/28/1307等次列级质量与局部 FIFO 计算，不能把完整预测次数当作全部预测计算量。

### 两轮 Master 的实录

五模型单副本 K1和K4均得到相同流程：

| 步骤 | 成本值 | 发生的操作 |
|---|---:|---|
| 第一次 Master | 下界0.294378327952438 | 选中 G2+image+OCR 的纯路由 |
| 唯一完整预测 | 实际成本0.309302874267479 | 确认全部硬约束及完整六项U |
| Predictor Feedback | 非负残差0.014924546315041 | 对**这一个完整部署+路由身份**加入 residual identity cut |
| 第二次 Master | dual bound 0.309302874267479 | 与已有赢家成本相等，返回前停止，不再调用完整预测 |

停止条件是 `lower >= -incumbent.score - tolerance`。不是把服务下界当真实性能，也不是只看第一次候选“似乎够好”。反馈切面对其他完整整数身份的校正非正，由既有全局 B(z) 支配；不会假定不同路由也具有同一精确 FIFO 成本。

`route_feedback_cuts=0`：所选 v2 模式不进入原 `independent` 模式的路由级跨驻留反馈分支。可行候选用 identity residual，不可行候选用 no-good；性能/资源未知候选另记未知下界，不能作为已知不可行。当前这个例子没有 no-good、未知候选或数值排除。

### 独立枚举验证“别的方案为什么不用预测”

把原列下界投回独立枚举的66个完整方案，逐个重建 B(D,r)，均不超过相应完整成本。赢家以外65个方案的**最低**成本下界为 **0.320874596621326**，已比赢家实际成本高 **0.011571722353847**；具有竞争性下界的其他方案数量为0。这提供了区别于“赢家/次优实际差距”的直接证据。

该最低竞争下界来自 G2+OCR，而非实际排名第2的部署：下界排名与实际排名不同。反馈只需把赢家自己的松弛补齐，第二次 Master 就不可能返回成本更低的其他身份。

赢家成本分解如下，数值均为加权成本：

| 原下界成分 | 值 |
|---|---:|
| 驻留显存 | 0.084682957 |
| 启动/worker能耗 | 0.002090616 |
| 精确路由质量 | 0.025266859 |
| 路由能耗与板级截距 | 0.033512442 |
| 无等待服务及不可避免迟完成 | 0.148171975 |
| 同任务孤立 FIFO 额外成本 | 0.000653480 |
| 完整预测反馈残差 | 0.014924546 |
| 合计完整成本 | 0.309302874 |

这里反馈残差主要补齐共享任务队列等原松弛未涵盖项；不能统称为动态 GPU 共驻干扰，因为当前服务律没有该能力。

### 受控下界消融

单独在私有 SearchSession 包装 `floor()`，只削弱搜索下界；完整预测仍使用原 Q/T/L/P/M/E 和全部硬检查，不比较放宽后硬问题的最优值。五模型单副本 K4，12s求解限额：

| 搜索下界设置 | 完整预测 | Master | 认证 | 最佳有效U |
|---|---:|---:|---|---:|
| 原下界 | 1 | 2 | 是 | −0.309302874 |
| 去掉孤立 FIFO 增量，保留无等待服务 | 1 | 2 | 是 | 相同 |
| 去掉质量下界 | 9 | 10 | 是 | 相同 |
| 去掉路由能耗/截距下界 | 19 | 20 | 是 | 相同 |
| 去掉全部延迟/窗口下界 | 95 | 95 | 否，预算到期 | 相同incumbent |
| 全部任务列成本下界置零 | 155 | 155 | 否，预算到期 | 相同incumbent |

95/155是预算内已调用数，不是完成认证所需总数；诊断分解自身增加 Python 工作，不拿消融wall声称生产速度。结论是：**基础服务、精确质量和能耗下界共同关键；低K这一案例不依赖孤立 FIFO 增量才能一次预测认证。** 不应因原实现包含 FIFO 界就直接认定它是全部提速来源。显存和资源的贡献同时由原域过滤及上表成本分解确认；本轮没有移除完整预测的硬约束。

## 6. 对 RQ1–RQ6 的结论与下一阶段选择

1. **为什么快？** 五模型低K的主要直接证据是强全局成本下界和明确赢家优势，独立66方案枚举证实全部竞争下界已输。显存对高副本域压缩强，对五模型单副本压缩弱。反馈补齐赢家一次后第二轮便能认证。
2. **是否够难？** 当前低K五模型有限域对现有Joint不难；次优之间有接近和精修排名反转，不能说没有决策权衡。高K路由构列、松共享队列界的两模型域均已出现明确计算难度。尚未验证高负载双模型同时受压及强动态干扰下的难度。
3. **为什么纯路由？** 原网格赢家可以由端点表达；若干S速度/质量占优且接收全任务后仍空闲；其他S的局部收益未支付固定驻留成本。当前证据不支持“动态共驻干扰抵消分流”解释。
4. **是否覆盖路由相关执行干扰？** 当前主实验v2不覆盖。服务取固定逐输入中位数×统一系数，路由影响FIFO、输入子集和期望资源项；`route_load_replay_v1`仍未实现。第二份报告提供函数链、控制实验与测量缺口。
5. **连续路由价值？** 已在受限Text部署观察超越K8的内部收益和次优排名反转；尚未提高原Joint的系统最佳值，也未证实普遍跨轨迹收益。共享请求映射、尾延迟与激活感知值得保留研究，不能宣称连续全域已最优。
6. **下一步优先级？** 研究前提优先 **C+D：补齐路由/负载相关共驻画像及独立验证，扩大有效负载范围**。工程上保留低K Joint；若近期确有高K需求，**A：按需构列/列缓存及更强共享队列界**有实测瓶颈支持。B只作为有支付激活成本潜力的受限精修研究；E可继续优化已确认的session建立和构列成本。暂无证据支持优先开发GP-BO/MADS或扩大外层DE预算。

证据边界：已证明的是冻结有限域认证和所列控制对照；合理但未验证的是更强物理干扰可能改变赢家及连续收益；需要新测量才能回答的是服务随G/S活动变化的函数、热点高负载排序和物理效用收益。三者不能互换。
