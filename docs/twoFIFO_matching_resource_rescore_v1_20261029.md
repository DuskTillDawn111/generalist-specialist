# Matching exact15 resource-to-sixscore bridge

`twoFIFO_matching_resource_rescore_v1` completes the matching numerical chain
from archived response forecasts through the matching resource provider to the
unchanged original Q/T/L/P/M/E scorer. This is a new explicit derivative; the
old source-rebound bridge, its physical identity and its 8/4 attempt assumptions
are retained without edits. Only generic ensemble replay, causal memory contract,
query binding, resource timeline and original score/distribution math are reused.

The new public `run_all` authenticates the matching generated design, saved
response fit, resource design, exact same continuation/intake and producer plans.
Every one of the three folds retains all ten donor attempts and five heldout
attempts. A matching `FoldResourceTrainingProvider` is authenticated once per
heldout block and reused for its 57 cases. The complete output retains171 cases,
390 requests and all1368 fixed draw slots. Archived compact worlds are restored
and checked against their hashes before resources are attached; all request,
timing, world and probability identities remain fixed.

For each generated world the bridge explicitly calls
`twoFIFO_matching_resource_v1.predict_timeline`. Its board timeline includes idle,
active and drain slices. The provider's matching physical identity and10+60
domain checks apply before resource lookup. The original scorer alone amortizes
startup energy by3600 seconds and applies the memory safety factor once. Missing
explicit prior allocator history leaves M and fullU UNKNOWN; it does not reset
history to priming. Unsupported90+120 resource horizons retain full unknown
exposure. The bridge evaluates the original six terms and does not evaluate the
separate deployment stability decision.

Optional past memory uses the existing closed causal contract and full
`block|attempt|case` mapping when case names repeat. Future cutoffs are rejected.
Resources are never inferred from the heldout case's resource labels.

The optional measured label adapter accepts the matching raw schema directly,
without relabeling documents. Resource predictions are persisted before reading
that case's evaluation labels. It then computes observed fixed-window energy and
startup-through-drain sampled owned memory through the original score bridge.
Frozen quality expectations remain the quality input on both sides; this is not
native quality qualification. `--skip-measured-labels` opens no heldout raw label
file at this bridge stage. Provider authentication still rechecks source intake.

of integration correctness, not measured interference accuracy or routing gain.
Real response and resource fits, independent prediction validation, physical
USHER/Roomie mechanisms and original90+120 horizon transfer remain separate work.
