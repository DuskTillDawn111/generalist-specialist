## 最终算法

优化目标保持用户原文的 `max_r V(r)`、`V(r)=max_D U(D,r)`，最终返回预算内最佳已知合法部署与路由，不要求连续全局最优。

1. 显式维护正流量激活集合与各任务连续 simplex，保留零比例和纯路由端点。
2. 统一初始化后，由 BO 的 GP/EI 提出全局候选，MADS 风格的网格局部轮询精修候选；两者共用预算与评价账本。
3. 对每个路由，先重新评价兼容的历史部署结构，形成可行效用下界。
4. 结合有效上界、内层状态与计算预算，决定是否启动或继续固定路由部署/副本 MILP；路由局部账本保留已评价身份。
5. 新部署进入共享池，当前最优联合方案独立保留。新路由不会复用旧路由的效用；缓存要求完整输入身份一致。
6. 只用已认证固定路由值训练 GP。未认证值保留 LB/UB/UNKNOWN 并按需精化，不当作精确 `V(r)`，也不因预算耗尽而虚假认证。

MADS 部分是项目内的随机方向 mesh-adaptive poll，不冒称标准 NOMAD/OrthoMADS 实现或经典收敛证书。零流量允许模型不部署，但不强制卸载驻留模型；这与共驻资源效应及原目标的合法部署定义一致。

默认效用为四组 v3：`U=−[Q+(T+L+P)/3+M+E]/4`。保留明确的归一化参考、完整性要求和质量诊断，未恢复绝对质量门槛。

## 可运行入口

新增[通用 v3 入口](../experiments/solve_bilevel_v3.py)允许在配置明确声明的合法部署及副本域内运行完整双层算法：

```bash
python experiments/solve_bilevel_v3.py \
  --config configs/paper_fifo_reference_v2_cpu_fixture.json \
  --output /path/to/new-output-directory \
  --method BO-MADS --seconds 300 --predictions 64 --routes 32 --milp-calls 128
```

上例是已有 CPU fixture，非真实硬件配置。`--method` 支持 `BO-MADS`、`BO-only`、`MADS-only`；默认组合算法。入口要求 ready reference-v2 数值契约和 nominal 策略，在独立副本中应用 v3 权重，逐项核对预测评分，并把目标版本加入 oracle/cache 身份。原配置与冻结源码不变；未提供的预测证据仍为未知，不会凭配置开放而自动获得物理资格。

当前真实五模型范围继续使用[冻结范围 v3 搜索入口](../experiments/search_scoped_utility_v3.py)。它固定全驻留、各一副本，不能用通用入口的能力宣称其真实域已经扩大。以上命令是复用说明，本阶段无需再次运行。

## 共同初始化对照：组合没有额外收益

复用三次已存档 BO–MADS 运行，新增 BO-only/MADS-only 各三个种子，共九份结果；没有重跑组合。全部采用相同预测器、v3 目标、两条开发历史和七个初始化候选，逐条核对候选、LB/UB、认证状态及累计预测/外层/MILP 计数一致。

初始化也计入每次 300 秒、64 次完整预测、32 次路由评价、128 次 master 的上限。单算法分支关闭对应搜索机制，其余激活感知与渐进内层调度保持一致。

|方法|最终预测 U（三个种子相同）|超过初始化的改善|完整预测调用：11 / 29 / 47|
|---|---:|---:|---|
|BO–MADS|−0.5179219273|0|44 / 44 / 46|
|BO-only|−0.5179219273|0|52 / 52 / 52|
|MADS-only|−0.5179219273|0|42 / 42 / 42|

九份结果全部选纯专用路由，均在初始化中获得最终最优值。BO-only 有实际 EI 提案，MADS-only 有实际局部轮询；不是相同程序更名。本场景 MADS-only 调用少于组合，不能宣称组合比两个单分支更有效。

此前组合比原 Joint-K2 高 0.06566 的结果仍然有效，但含初始化差异：原 Joint 在有限预算内没有访问纯专用。这只能支持完整流程覆盖好候选的优势，不能归因为 BO/MADS 协同或连续精修。本次未运行共同初始化的 Joint，不能冒称新 Joint 对照已有实测；仅初始化基线已经达到最终最好值。

结果：[outer-comparison.json](../artifacts/bilevel-final-acceptance-20261105/outer-comparison.json)。已有组合与本次单分支不同时运行，时间仅作预算审计，不进行严格速度比较。没有因为零增益而继续调参或扩预算。

## 多部署、多副本与渐进内层验收

使用已有 `continuous_fixture.json` 的 low、text_hot 两种负载：2 任务、3 模型，每模型 0/1/2 副本，共 27 个笛卡尔状态。固定路由包含纯 G、纯共享 S、任务专用、两个非网格比例以及一次重复访问；按正流量约束过滤后，每条路由有 12 或 18 个合法结构候选。

参考值通过独立 `itertools.product` 穷举所有合法部署并调用同一 FIFO oracle 得到，不使用被测 MILP、候选池或界。两种负载共 12 个路由访问单元（包含重复访问）：

- 原固定路由 MILP 与共享池精确求解共 **24 个结果**，全部与独立枚举一致，包括不可行结果。
- 预算内层共 **12 个结果**，上下界全部正确；本例找到的可行最好值也与枚举相同，但全部保留未认证状态，不把事后相等追认为求解证明。
- 双副本状态实际参加枚举。另有针对性测试以 `g=2` 为唯一最好部署，验证副本选择；本批主要 FIFO 场景的最终胜者均为单副本，未人为调参制造双副本收益。

|负载|内层策略|完整预测调用|MILP 调用|已认证访问数|
|---|---|---:|---:|---:|
|low|原固定路由 MILP|72|77|6/6|
|low|共享池＋有效界，精确求解|8|75|6/6|
|low|共享池＋有效界，按需预算|7|16|0/6|
|text_hot|原固定路由 MILP|72|77|6/6|
|text_hot|共享池＋有效界，精确求解|7|73|6/6|
|text_hot|共享池＋有效界，按需预算|5|20|0/6|

这些计数表明组合的内层机制在软件场景里能够减少完整预测；预算策略也减少了 master 调用。**不能把全部节省单独归因于候选池**：对照同时涉及有效候选界、复用和调度。两者均允许完整身份一致时缓存；重复访问不是新的独立场景。此 fixture 的更强数学界依赖其已知合成规律，没有把它移植到真实冻结预测器。

在同样的非退化部署域中，还完成两次完整双层 CPU 运行：

|负载|选中部署|预测 U（原 CPU fixture 目标）|运行中部署池大小|

|low|共享 specialist 一副本承担两任务|−0.1363523585|10|

两次最终所选路由下的部署效用均与独立枚举最优一致；这不等于证明外层连续全局最优。与此前部署池只有一个结构不同，此处实际选择了不同部署、发现并复用了多个结构。

这部分沿用**原合成 CPU fixture 的目标与 FIFO oracle**，用于验证通用机制，不能把这些 U 与真实 v3 U 比较，也不能解释成真实 GPU 或 v3 的节能/精度收益。另有新入口测试在 ready reference-v2 多部署 fixture 上核对 v3 贡献、求解输出与版本隔离。

## 验收、边界与最终决定

**87 个不同测试通过**：原机制及本次验收 84 项一次运行通过，新 v3 入口 3 项单独通过；没有声称单次运行了 87 项。已核查全部来源收据、九份初始化、24 个精确结果、12 个部分结果、预算以及双副本枚举。详见[verification.json](../artifacts/bilevel-final-acceptance-20261105/verification.json)、[测试日志](../artifacts/bilevel-final-acceptance-20261105/tests.log)和[预定协议](../configs/bilevel_final_acceptance_20261105.json)。

最终交付保留组合算法及两个单分支选项，供不同受支持场景使用。当前真实范围的方案仍为纯专用路由；其原有 OCR 精度限制、第二轮 OCR 0/24 按时及 image 3/24 按时问题都保留，不能宣布业务 SLO 达标。

此次有限任务已收尾：实现正确性和限定算法验收完成，组合协同未显示额外收益这一负结果也已完成报告。真实跨部署/多副本收益、未见输入泛化和全局最优不属于已证明结论；不以这些边界为由自动恢复预测器排查或追加实验。
