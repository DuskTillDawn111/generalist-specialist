# Prospective shape sidecar and absolute-memory prototype

This new module is isolated from joint-law v4, the reviewed runner and both
resource providers. It supplies a testable generated-event/shape path and a
strict empirical absolute sampled-memory candidate. It has not fitted the
native campaign or qualified memory prediction.

Exact interval/poll support makes this a strict reference, not the final memory
support solution. The separately predeclared case-level statistical candidate
in `twoFIFO_case_memory_regression_candidate_v2_20261028.md` addresses trainable
support without requiring each short macro to contain a poll.

`selected_shape_sidecar` takes each selected complete vector and its public
owner/task/input arrival ordinal. It calls the existing v4 compiler and saves
every node's forward shape and every source/generated mark identity with its
macro identity. The sidecar does not make the saved shapes visible. It retains
the selected vector digest and donor block; no raw request ID is a lookup key.

`generated_shape_intervals` joins that sidecar to the full v5.2 generated world.
Only `processed_notification.available_ns` applies a phase shape or clear/READY;
latent occurrences, reader availability and pending notifications do not update
the shape state. The complete offered public slots must match. The adapter
checks owner, public slot, generated mark, action, phase and macro identity.
Changing a future decode shape cannot alter an earlier processed state. Missing
initial shape history remains an explicit unknown axis. Adjacent identical
states are coalesced, independently of reporting-query times.

The absolute training adapter labels structural intervals with the maximum
contained **absolute owned-memory sample**, never a positive increment. A poll
touching/crossing an interval boundary makes each touched interval UNKNOWN;
intervals without a contained poll remain UNKNOWN. Every interval, case and raw
poll assignment is retained. Existing native priming job identity is preserved;
only a temporary compatibility view can annotate an absent job axis, and the
table reports that scope explicitly.

The public `train_absolute_campaign` entry uses the existing complete-native
loader before any new target extraction or fitting. It requires twelve attempts
in three complete blocks and writes all tables plus the full and all three
whole-block models. Each fold uses eight attempts from two donor blocks. Pure
table helpers exist for CPU contract tests and do not authenticate native data.

`rollout` predicts an empirical absolute demand `D` only for an exact supported
shape state, interval duration and poll geometry. Two whole blocks must support
that key. An observation plan must explicitly declare future query brackets and
sample coordinates; it contains no realized memory values. This is a caller
declared hypothetical sampling schedule, not an inferred or independently
authenticated future monitor schedule. Changing the schedule can remove support.
Without an observation plan, the current evidence cannot support a sampled-peak
forecast and the result is UNKNOWN.

The memory origin must explicitly name a training donor after original priming.
Its initial shape history and prefix peak come from that donor, whose block must
match the selected request-vector block and belong to the model's training fold.
A settled queue seed does not provide allocator history. No held-out past poll
corrects subsequent predictions. Later-case continuation requires a separately
generated prior shape/memory prefix; this prototype does not infer one from a
fresh-donor origin.

For every structural interval the recurrence is `P_next = max(P_previous, D)`.
Reporting queries merely read this precomputed path. Inserting or duplicating
queries neither splits training units nor adds demand again. Missing support
anywhere keeps the full peak UNKNOWN, while a clearly labeled partial known
peak may be retained. The predicted demand for an interval is a forecast of its
sampled maximum, not a measurement already observed at the beginning of that
interval.

The shape/high-water state does not identify allocator bins, reserved pools,
KV residency, workspaces or release state. Exact sampling support is restrictive
and does not establish transport to another duration or monitor process. A
mean/max empirical demand scenario is not a calibrated joint startup/shape/
memory probability law or a bound on between-poll physical peaks. The supplied
low-level model is not independently rederived during rollout. All provider,
resource, probability, capacity and final-gain qualification flags stay false;
the original memory safety factor remains unapplied here.
