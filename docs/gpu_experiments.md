# 四任务 GPU 实验记录

2026-10-17 当前状态：旧配置未通过模型池要求；显存优化代码与两套独立待测配置见
[显存优化与待测入口](compact_memory_optimizations.md)。本次修改没有启动 GPU，以下为首轮历史记录。

GPU 实验已于 2026-10-16 启动。设备为 NVIDIA GeForce RTX 4090，NVML 报告
49140 MiB 显存、450 W 功率上限；启动前无其他 GPU 计算进程。

原 CPU 就绪报告和首批失败记录保持为历史证据。CPU 准备通过不代表原生 GPU 接口兼容，
也不代表候选满足模型池准入条件。

## 冒烟阶段的修正

- Qwen 固定版本的加载器即使关闭 Talker 也读取 `spk_dict.pt`。补充固定版本资源，
  与 Hub 元数据中的 SHA-256 核验一致，纳入新资源清单。显式使用原生 SDPA。
- Phi 原生语音模块缺少 `backoff==2.2.1`，已补充依赖并更新哈希锁和 CPU 环境审计。
  INT4 量化排除 `lora_A`、`lora_B`，使原生视觉/语音适配器保持浮点精度。
- Whisper 使用原生 30 秒特征补齐，显式禁止截断；保留 `language=en`、
  `task=transcribe` 与已知解码前缀，不触发自动语言检测。
- 三个通用的生成式分类共同使用完整 1000 类编号的 token trie 约束。
  自由生成在校准冒烟样本上出现目录外编号/类别名称；新规则在独立质量评价前冻结，
  不读取样本参考类别、不删减候选类别，错误的合法类别照常计错。
- Phi 的浮点注意力掩码保持原精度，避免 BF16 求和舍入改变视觉 token 计数。
  MiniCPM 的分类约束兼容只有 `inputs_embeds`、初始解码序列为空的原生接口。

这些修正会生成新的实验包及源码哈希。不同实验包的成功回执不能相互充当前置证据；
不覆盖原有失败目录，也不沿用不同精度配置的质量评价。

## 串行队列和阶段门槛

执行器为 `scripts/run_compact_gpu_queue.py`。当前实验包、结果目录及进程信息见
`artifacts/compact-gpu-results/latest.json`；结果目录内的 `queue-state.json` 和
`controller.log` 提供实时进度，每个作业另有日志和回执。

1. 完成全部七个 smoke，任一失败则停在冒烟阶段，先处理兼容问题。
   另核验全部 12 个专用/通用实际驻留显存比；超出原定 [0.5,2] 则在独立质量评价前停止。
2. 完成七个独立 quality 作业，每个质量样本仅一次；保留失败请求并核验固定质量门槛。
   任一路径未达到最低质量，不自动进入容量和成本采集。
3. 质量门槛通过后运行 21 个 profile 作业，通用和专用均尝试 n=1/2/3，每配置三轮。
   n2/n3 依赖成功的 n1，显存超预算和其他失败保留，不推定副本增容。
4. 继续 48 个同负载、同轨迹的 600 秒成本窗口，核验每个专用相对三个通用的约束。
   完成后生成模型池筛选报告。队列不会自动把未准入的模型用于系统实验。

`profile` 是饱和闭环容量画像，不能替代正式开放到达的系统比较点。
完整多负载系统矩阵仍需先冻结共同容量参考，且必须使用相同绝对需求比较所有方案。
空闲常驻、均衡递增、单任务升温、固定总流量改变比例、容量归一化高负载、拥塞附近分流
均按已讨论的方案单独准备；未采集的共驻容量、整方案能耗和五项效用保持未知。

## 结果解释

冒烟每任务只有三条校准请求，成功只能证明接口与小样本输出完整，不能认证质量或容量。
Qwen 已完成的一次冒烟观测到约 23.9 GiB 预热后整卡驻留显存；这是包括实际分配器缓存的
观测，不是参数显存。模型池设计目标不能替代此类真实记录，正式准入仍以匹配负载采集为准。
