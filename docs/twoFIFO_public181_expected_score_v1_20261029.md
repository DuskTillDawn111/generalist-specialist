# Source-authenticated expected-score producer v1 (2026-10-29)

This new producer composes the original additive expected six-term utility from separate authenticated queue and resource marginals. It does not patch frozen native-v3 or its queue-only prediction seal, start a GPU, or declare a measured full-pipeline CPU budget. A source-authenticated training hypothesis is distinct from native launch permission, transfer qualification, prediction accuracy, and final gain.

## Interfaces and source lifetime

`twoFIFO_public181_expected_score_v1.prepare(target_manifest_path, target_plan_path, resource_manifest_path, resource_review_paths, output)` creates a separate configuration and full source freeze. `audit_preparation` reconstructs its complete declaration, including all source references, exact frozen closure, target identity, original score contract, and execution limitations. Its target registry is concretely the new native-v3 auditor; an old fresh schema, arbitrary callback, or Boolean cannot impersonate it.

`open_session(preparation_path)` authenticates the exact target/saved matching fit through typed-v3 `open_target_session` and separately opens an authenticated resource session. The latter reruns resource intake before startup, keeping all eight plans even if their native observations are absent or unknown. Both caches are protected by active source-change guards, immutable content hashes, and lifetime checks. A native collector would need separate producer and auditor sessions opened before worker startup. This module has no collector integration; the existing queue-only v3 collector does not call it.

`produce(session, gate_path, output)` reads the actual immutable prefix and public gate through the concrete typed-v3 auditor, replays the original queue producer, and computes all six marginals. `audit_report(other_session, report_path)` independently repeats the complete twelve-world queue and six-marginal computation and requires exact output equality. Neither interface has an execute operation or emits an enqueue-authorizing full-U seal.

## Mathematical contract

The queue side retains all three matching blocks and four slots per block: twelve original worlds, all 181 original requests, and every unknown probability mass. T/L/P are the unchanged original per-world scores; P95 is scored within each world before expectation.

The resource side retains all eight plans in two complete four-candidate blocks. Each candidate has one donor in each block with weight one half, even when that donor is unknown. M uses each donor's `max(P0, future_peak)` before averaging; E uses original measurement-only board energy and its same-attempt startup energy amortized once at 3600 seconds. The original `whole_score` computes M/E with exact encoded rational clocks. Q uses each donor's actual native-output per-task summed errors/reference units and original offered-rate weights; it never copies frozen expected Q as actual Q. A missing quality outcome keeps Q unknown without discarding an otherwise valid M/E observation.

The root-reviewed `twoFIFO_expected_marginal_score_v1.combine` forms the unconditional additive expected U only when all six original term expectations have known mass one. It requires no invented pairing between the two resource blocks and twelve queue worlds. No unknown mass is removed or renormalized. This does not determine a joint utility distribution, probability of positive ΔU, stability, confidence interval, or final routing gain.

## Explicit transfer gap

Physical comparison checks actual worker context and derived command/env/spec/checkpoint bindings, runtime knobs, resident and routing policies, original input pool, priming semantics, candidate calendar, objective/score normalization, measurement/drain, declared lead, actual prefix-to-origin gap, and READY-settle limit. Source closure/protocol hashes remain provenance, not evidence that physics is equal or different.

The frozen resource producer and native-v3 currently differ in material ways. Resource origin is exactly `snapshot_time_ns + 300 seconds`, while native-v3 chooses a later host clock after snapshot return and adds its lead. This producer quantifies the actual snapshot-copy anchor excess. Resource READY-settle budget is ten seconds; v3's is thirty seconds. Resource startup wait is passive, whereas validation prediction/audit introduces substantial CPU activity while board energy and P0 are being counted. That collector observation overhead and startup-activity transfer has not been empirically bounded.

These differences are explicit UNKNOWN resource/quality transfer gates in this first version. Even equal 300-second declarations or identical worker context do not qualify Q/M/E. Queue predictions can retain source provenance while full U stays unknown. A later explicit collector version must align anchors/settle behavior and either align relevant startup activity or validate its transfer hypothesis. No frozen artifact should be edited to create that agreement.

The actual combined live producer, independent audit, prefix/gate persistence, complete score output, and durable acceptance checkpoint still need a new source-bound timing benchmark. The existing queue-only budget cannot qualify that total pipeline. No full-U native preparation is produced by the author CPU tests.
