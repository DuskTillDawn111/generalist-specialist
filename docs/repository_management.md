# 仓库管理与第一轮整理

## 已建立的边界

- Git 管理源码、说明、配置和选定的研究元数据。
- 权重、数据集、环境、缓存与大规模观测材料保留在研究工作区。
- 保留所有历史算法路径；结果目录中的源码不能按普通输出整体清理。
- Gate 是实验结论，和“目录已归档/阶段已结束”等维护状态分开。
- 基础库、冻结算法、未指定主线的研究实现分别列出；最新实验不自动晋升为正式算法。

第一轮交付包括根 README、架构说明、实验索引、复现说明、机器可读清单、基础包描述和索引工具。没有迁移或修订历史算法，也没有重新运行 GPU 实验。

## 日常工作流

1. 新工作先创建分支：`git switch -c <topic>`。
2. 新实验名称同时表达阶段与意图；在后续迁移前沿用既有源码布局也可以，但避免新增共享能力对编号模块的依赖。
3. 更新说明和清单：`python tools/repository_inventory.py --write`。
4. 检查 `git diff --stat` 与 `git diff --cached --stat`，确认只提交预期源码及精选元数据。
5. 做与变更相称的 CPU/记录回放验证，再提交和上传。GPU 实验另行按冻结协议执行。

当前 `.gitignore` 默认仅放行源码、文档和配置类型，结果 JSON 采用具体路径列表。新增文件类型或结果元数据需要显式调整跟踪规则。源码副本和备份也应按是否被复现依赖有意管理，不批量删除。

首次上传使用已连接 GitHub 接口。当前服务器的原生 Git 网络传输曾超时，shell 也未配置写入凭据；配置可用网络和 GitHub 认证后可使用常规 `git fetch/push`。本地 `main` 与 `origin/main` 已按远端实际提交同步，不保存访问 token。

## 下一轮整理顺序

| 顺序 | 内容 | 验收条件 |
| --- | --- | --- |
| 1 | 提取指标、稳定性、效用和通用读写 | 同一批记录重算结果一致；冻结定义保留 |
| 2 | 提取 worker 管理、队列、测量、遥测 | 协议、时间戳、失败与排空语义一致 |
| 3 | 统一模型目录、路径配置、容量证据 | 不改变能力准入及已测副本边界 |
| 4 | 提取部署、路由、预测和在线策略接口 | 公共库不依赖实验包；算法身份分开 |
| 5 | 实验目录与产物归档 | 旧入口/路径映射明确，依赖已核对 |

计划目标为 `src/gsdeploy/{domain,catalog,optimization,prediction,policies,runtime,evaluation}` 和 `experiments/`。现阶段不创建空目录冒充迁移完成。

已有冻结文件往往验证源码哈希，部分还保护 size/mtime。新实现应在新路径建立，再用相同输入对照；历史文件可由独立快照及兼容入口保留。不能为迁移方便重写原 Gate、准入条件或保护哈希。

## 第一轮验收

- README 能找到主要算法入口，并覆盖结果目录内的 Module32–35。
- 实验索引能列出源码、主要入口、跨实验依赖和已记录 Gate。
- 更新工具不加载模型或算法模块，不写历史实验目录。
- 原有算法文件 SHA256 与源码基线一致。
- Git 中没有权重、环境、数据集、缓存和超大原始文件。
- 本地与 GitHub 分支提交及文件树一致。
