# Text 高负载分流：CPU 后备可行性筛选

建议保留 `text2+G2n1+OCR1` 为 ASR 小分流未成功时的后备。它的单机画像速度差比 ASR 更有利于分流，显存也留有空间；目前不能断言真实总效用收益，更不能断言是全池最优。没有运行 GPU，没有改动当前 ASR 计划、生产数学、冻结模型或验证协议。

证据与可复现脚本：[report.json](/root/autodl-tmp/generalist-specialist-project/artifacts/static-spillover-study-20261022/cpu-discovery/text-backup-readonly-v1/report.json)、[protocol.json](/root/autodl-tmp/generalist-specialist-project/artifacts/static-spillover-study-20261022/cpu-discovery/text-backup-readonly-v1/protocol.json)、[assess_text_backup.py](/root/autodl-tmp/generalist-specialist-project/tools/spillover_discovery_20261022/assess_text_backup.py)。有限回放共54个：3种负载×6个指定路由／部署×3个种子，不运行优化器。状态为 `EXPLORATORY_STANDALONE_REPLAY_NOT_VALIDATED`；不计算能耗或总效用，生产 U/E 均为空。

G2n1/text 的逐输入池均值为 text n2 的约60.4%；ASR对照中 G2n1/asr 803.056ms 与 ASR n2 818.656ms 的比例约98.1%。所以 text 分流除了减轻专用排队，还有较明确的历史服务优势；不过 text 专用与 G2 的 EM 差为6.25个百分点，比 ASR WER 约0.224个百分点的差大。若按同分布、忽略输入与路由的关联，12.5%／25% 分流预计付出约0.78125／1.5625个百分点的 text EM 代价。此处只是聚合差值，不替代逐输入实际评价。

## 4. 输入形状与共驻风险

当前32条text池是原80条输入中按上下文／问题长度选出的子集，不是服务恒定或质量分层的样本。实际执行是原生ChatQA及G2生成，`max_new_tokens=128`，贪心、单beam、自然EOS停止；不是旧通用profiling adapter中的512窗口／64token流程。ChatQA历史输入token范围414–4866，G2为389–4981；tokenizer不同，不能直接比较两个模型的输入token绝对数。历史生成token范围分别2–27、2–44，均未因为这里的128上限截断为固定长度。

逐输入服务具有明显长尾：text n2 的min/P50/P95/max为250.04/669.74/1465.78/2181.80ms；G2n1为162.53/416.78/1045.23/1545.06ms。原始text n2请求的输入token与service Pearson相关约.744，生成token与service约.635；G2n1约.771/.802。这些相关性仅是历史观测，生成token不可从待预测运行读取作为预测特征。text prefill/解码、KV与量化内核会与G2竞争显存带宽和计算，n2..4 text服务的恶化及G2n2吞吐下降已经说明不能假定独立副本并行加速。G2 image/asr请求还会阻塞同一worker的text队列；背景降到 .01只减频率，不消除阻塞。

**尤其注意输入循环与路由周期对齐。** text专用和G2仅在4/32条输入上EM不同：3条专用胜、1条G2胜。固定32输入循环与1/8、1/4的确定性路由周期会让每个种子反复把同样的4条／8条输入给G2。当前text2的三个种子恰好都分配到EM相同的输入，所以12.5%／25%探索回放的text EM未降。这不能说明分流一般没有精度代价，更不能靠挑种子复现这种结果。保持正式路由／输入契约，开发后用新种子、独立验证和实际输出重新算Q；报告同时披露路由覆盖。若未来要修改池轮转策略，应独立预声明新合同，不能在本轮为改善排名改动。

本轮交付只支持“text2+G2n1值得作为后备开发点”的判断。真实总效用、最佳副本数、全池最优性与搜索效率均保持未验证。
