# Joint MILP 扩展性与固定部署连续精修研究

**结论：Joint MILP 的优势受网格、界紧度和副本状态影响，并非所有规模都占优；但当前可用真实域中，连续精修尚未提高其效用。固定部署局部精修显著减少了相对 DE+固定路由MILP 的调用成本，纯 DE 精修则主要消除了重复部署求解，没有自动减少预测或总时间。** 继续保留原 Joint 为基线，优先研究结构化构列和共享队列界。

## 研究口径

本研究先执行实验 A，再实现和运行实验 B。原 `JointMilpOptimizer`、`UtilityOptimizer`、预测器、效用和硬约束均保持原样；没有训练、生成共驻测量、启动 GPU 或实现 GP-BO/MADS。源码快照、原始 JSON、逐次预测与 MILP 矩阵记录分实验归档。

主数据仍来自已通过留出条件验证的 `artifacts/static-study-gpu-20261022/search-v2-v5-K8/system-config.json`，模式 `calibrated_replay_v2`。采用原四任务工作负载，各0.0748360842705697 qps、1800s到达窗口、300s排空、六项各1/6；延迟参考 text1000/image250/ocr10000/asr3000ms。它是已冻结数学预测器的 CPU 搜索比较，当前准确性前提不升级为新 GPU 实测或物理最优性。

所有对照都提供现有私有 `SearchSession` 摘要缓存，计入各自建立成本，没有给新算法独占预测器执行加速。模型子池仅删除 `models/capacity_factors/memory_table_mib` 的未选模型，保留被选模型全部原画像、质量文档和验证 spec。副本通过合法 `replica_options` 限制，未改写实测行。

## 实验 A：网格、列数和搜索范围

### K 的实际含义

`fraction_rows(models,K)` 生成所有**公共分母1..K的非负有理比例并集**，按精确 Fraction 去重。K目前合法范围1..16。两模型 K4 的比例包括0、1/4、1/3、1/2、2/3、3/4、1，共7条；K8有23条，K16有81条。四模型 K8有407条，K12有1537条，K16有4195条。额外配置的 pair denominators 只扩展两模型分流；本研究关闭该扩展和 capacity witness，避免把非网格见证混入 K 的效用比较。

`JointMilpOptimizer.columns()` 对每个任务先生成上述路由，再枚举**正比例模型的副本组合**，过滤活跃模型显存必要条件与单任务 rho 必要条件，调用原单任务 FIFO/质量/能耗下界。MILP 保留全模型副本 one-hot 列、任务路由/副本列和一个成本 epigraph 变量；还要满足跨任务聚合 rho、显存和连接约束。不能将候选列数等同于完整联合方案数，也不能把通过显存过滤的部署视为通过全部预测约束。

主实验包含32个问题配置、108次运行；两次重复并轮换次序。Joint覆盖 K1/2/4/8/12/16、2/3/5/7模型、单/双/三副本及全部画像状态。选取同域 DFS 和 DE+固定路由 MILP 对照。另8次补充用于两模型K16完整三算法对照和列/迭代限额。每算法8秒总预算；新 DE 另限32条不同路由，终止范围单列，不能以其提前触顶当搜索完成。

计时采用可恢复的外部函数包装，保留全部原表达式和约束。记录构列、完整预测、`solve_master` 全调用及其中 HiGHS 后端；两者是嵌套时间，不能相加。独立测试确认包装前后完整赢家和预测次数相同。稀疏矩阵行列数逐轮保存，未开始 master 的运行记为“未构建”，不能当成零成本求解。

### 工作负载和任务数的支持域

不能直接把当前 workload 乘0.5/2/4，或只提高 ASR/OCR，就作为已验证算法性能数据。原 `validated_replay_spec` 对低、高、四任务同时高、ASR热点、OCR热点及1/2/3任务子集均返回 `V2_REPLAY_INPUT_CONTEXT_OR_WORKLOAD_CHANGED`。原4任务通过。现存 ASR迁移配置另因 `TRANSFER_SPEC_OR_CODE_CHANGED` 无法直接在当前源码加载；没有重签验证信息。

因此本轮完成的是**合法模型池、副本和路由维度轴**，以及已支持 seed42/43/45 的 Poisson自然轨迹变化，不能声称覆盖了所有低/中/高、热点及受控突发场景。Poisson10秒桶计数仅用于记录自然成团程度，不把换seed称为受控突发压力试验。自定义压缩 arrivals 的 CPU正确性测试也不作为真实负载性能数据。

当前预测器使用冻结 service_multiplier≈1.04035、memory_multiplier≈1.22167，并非随本轮人为增加干扰的模型。没有为制造精修收益改动服务时间、输出质量或显存。补齐任务数量、负载及更强共驻干扰轴，需要可被原门禁接受的已有配置或额外验证数据；本轮未绕过这一条件。

## 实验 B：固定部署连续精修

独立入口 `JointMILPContinuousRefinement` 先调用原Joint，再固定其部署。精修评价器只对当前部署和连续路由调用完整预测器，**不执行部署MILP**；部署中零流量模型仍驻留。路由使用闭simplex的浮点stick参数，支持精确端点、零比例和微小正比例，不重新量化旧网格。

DE复用现有 `DERoutingOptimizer`，增加可选 `initial_shares` 和 x0种群热启动；不传该参数时保留原执行顺序。另有独立命名 `PairwiseTransferSearch`，从初始比例开始作成对质量转移，逐步缩小步长，每步最多32轮；它不称为MADS，也不提供连续最优证书。

缓存只按问题/源码/部署/完整精确比例/轨迹身份命中。Joint初始预测仅在完全相同候选下复用。不同部署不复用旧预测，近邻比例或相同FIFO分配也不合并。全流程共享绝对时间、预测和路由预算；始终保留初始和精修过程中最好的有效方案，UNKNOWN不作为有效目标观测。

可选部署邻域是另一开关：从固定阶段赢家生成有限的一次变化（零流量删除、副本调整、添加/替换专用），先作已有显存必要界检查，再完整预测和精修。它不混入纯固定部署结果；每个阶段的部署、类型、预算和预测数独立保存。

### B的预算与初始解失败消融

主实验105次：7个合法问题×5种配置×3个优化seed（11/29/47）。5种配置为原Joint、DE+固定路由MILP、Joint+局部精修、Joint+DE精修、Joint+DE+独立部署邻域。各8秒总预算、128个连续路由评价上限、10000次完整预测上限；初始解时间、缓存建立均计入。局部精修可以提前完成，DE通常用满时间；两者的停止规则不同，不将更少工作量当作同算法加速。

第一版将初始Joint限为总预算的40%。七模型K8下，初始构列即可能耗尽这部分预算，9次精修配置都没有有效初始解。这是**预算分配失败**，不计入“精修没有收益”的候选证据。

按此发现，最终实现默认允许初始Joint使用剩余总预算；Joint结束后才用剩余预算精修，不重置总截止时间。对七模型K8重跑完整5配置×3seed=15次独立补测。全部精修取得−0.309303初始解并保持它；初始Joint可能已用掉大部分时间，后续只有少量评价，不能据此评价充分连续搜索。原40%预算数据保留，正式比较表仅将这个案例替换为修正后的补测。其他六个案例的40%上限没有阻止产生高质量初始解，表中保留其原实验参数，没有默认为已按新默认重跑。

每个运行保存最终部署、比例、完整预测、初始/最终逐请求FIFO映射，以及每次候选相对初始的映射变化数量。相同输入的模型、状态、负载、画像、评分和轨迹SHA逐例校验。优化seed只影响搜索，不改变trace42/43/45。

### 无连续收益的原因与证据边界

五模型K2固定部署DE在三个seed中均覆盖4个端点、9个支持face中心，并进入DE，不能把无收益都归因于“尚未离开初始化”。当前赢家在K1已可表示，A的细网格也未找到更高U，支持当前案例缺乏明显连续分流收益。

正式B汇总记录2181条网格外候选评价（含缓存命中），2903条改变了初始实际请求映射的评价，168条是网格外但实际映射相同的评价；均没有带来更高有效U。未找到“旧网格未覆盖且更高效用”的方案。

例：五模型seed29的一条网格外路由将image约0.331%和ocr约0.060%给G2，逐请求分配仍与初始相同，但U为−0.309319483，低于初始−0.309302874。期望流量资源项仍随比例变化，所以相同FIFO映射不是完整效用等价条件，也不构成合并预测缓存的依据。

这不证明固定部署连续全局最优：DE/局部精修均是有限预算启发式；更高维、多任务协同变化或其他部署仍可能存在改进。尤其七模型K8大部分时间用于初始Joint，剩余精修不充分。报告分别承认“当前低维实际搜索无收益”和“高K预算不足”，不把两者混为一个结论。

### 部署邻域的独立收益

正式比较中共有72个邻域精修阶段、768次邻域完整预测，实际覆盖副本变化及添加/替换专用。实现支持零流量模型删除，但本轮初始赢家没有零流量驻留模型，因此没有真实删除收益实验。显存必要界失败的候选单独标记跳过，未按零成本可行方案处理。所有改变部署的候选均按新部署重新计算完整预测，没有自动卸载后复用旧资源状态。

本轮邻域没有额外效用收益；五模型K2中位预测数由纯DE精修93增至99，均约8秒。该可选版本给初始固定阶段预留40%剩余时间/路由预算、余下分给最多4个邻居，所以它是独立预算分配消融，不是免费附加在完整128次固定精修之后。两模型没有可用邻居时，只完成预留固定阶段便返回，约3.98秒，不能把这一提前返回称为邻域算法更快。

## 对七个问题的回答与建议

1. **Joint何时明显变慢？** 当前七模型单副本K8开始出现秒级构列/求解；K12在8秒内不能完成认证，K16无法构完列。五模型双副本K16约7秒。两模型K16也会因82次预测/83轮反馈慢于DFS，说明不能只用模型数判断。
2. **K提高是否改善效用？** 全部完成认证的K对照均无改善；赢家为纯路由。未完成的大K域保持未决，不给全局否定结论。
3. **连续精修能否提高Joint效用？** 这批合法真实回放案例中没有，全部有效seed的改进为0。实现和独立CPU正确性反例能找到非网格改进，但测试fixture不冒充真实收益。
4. **没有收益是什么原因？** 当前低维赢家在最粗网格已有表达，端点/face/DE及实际映射变化扫描均无收益；不仅仅是相同映射。启发式预算仍不能排除未找到更优点，高K还有初始阶段和精修不足的独立限制。
5. **是否减少相对C方案的成本？** 固定部署阶段零部署MILP，五模型总MILP90→2；局部精修预测70→17、wall8.01→1.82秒。DE精修只确定减少了MILP，不保证减少完整预测或wall。两者都没有超过直接Joint的当前性价比。
6. **邻域是否有额外收益？** 当前没有；保留独立开关和原始消融，不设为默认。
7. **是否开发GP-BO/MADS？** 暂不以其为默认下一步。A已经证明高K瓶颈可转为构列和HiGHS，B未找到连续效用收益；优先研究任务列缓存/按需生成、共享模型多任务排队的更紧安全界，以及用低K Joint+受限局部精修替代高K构列的适用条件。只有在合法支持域出现可重复非网格收益、且成本主要来自路由候选评价时，再比较GP-BO/MADS。

本轮可保留低K Joint作为初始解来源，连续精修作为显式研究选项，主优化器不替换。高K仅作探索和认证需求的选择，不因“网格更细”自动启用。当前没有观测到新的连续最优收益或可泛化规模交叉点。
