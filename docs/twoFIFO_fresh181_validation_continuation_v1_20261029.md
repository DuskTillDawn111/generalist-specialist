# Full-score CPU readiness to four-candidate native4 validation

This new continuation leaves all frozen training, full-score, native4 and
validation modules unchanged. Preparation and audit use CPU only. No native
controller was started while authoring this document.

## Fixed sequence

1. Authenticate the existing fullscore-v2 preparation, original CPU PID, command,
   start ticks, working directory and exclusive claim. Wait for its canonical
   final. PID reuse is checked before even an already published final is accepted;
   the original process may be dead only when a complete canonical final exists.
2. An upstream HOLD immediately produces downstream HOLD, with no target
   preparation or wait for an independent budget review. A readiness final must
   bind the exact matching15 → kernel3 → resource8 source chain, original fitted
   gates and native quality, complete public181 support, eligibility and the one
   measured full-six-term CPU budget. No fit or benchmark is retried.
3. Wait for the separate independent real-budget readiness review predeclared at
   `artifacts/predictor-public181-full-score-real-budget-v1-20261029-cpu01-independent/report.json`.
   The continuation never writes that review. Root performs the real independent
   audit and publishes it. Current independent source reviews alone cannot
   authorize a target because native4 also requires the exact real budget receipt.
4. Wait for actual disk free bytes to meet the unchanged native supervisor
   `PREFLIGHT` floor (18 GiB), checking sources every 30 seconds. Prepare native4
   exactly once with a fresh namespace. Before each native attempt, wait for the
   same actual free-byte floor before writing its start marker or invoking the
   native executor that writes the attempt claim. The original supervisor checks
   capacity again; no extra reserve or smaller floor is introduced.
5. Execute the four original candidates serially using the literal native4 CLI.
   Its existing exclusive GPU supervisor lease prevents overlap. After each
   completed owned execution, run the frozen independent validation reviewer on
   CPU before starting the next candidate. Keep 181 offered requests, 18 priming
   requests, snapshot+300 seconds, READY settle10, measurement90+drain120, all12
   forecast worlds, original quality and original equal-six objective.
6. Run the frozen validation evaluation once, rederiving every supplied complete
   review. It retains all four candidates, six pairs and twelve QME checks,
   including UNKNOWN and near-zero exact sign disagreements. A legitimate native
   or protocol failure stops further captures but can still yield a partial
   descriptive aggregate from available independent reviews. A source failure
   immediately prevents a trusted partial aggregate.

Every report keeps four `candidate_outcomes` rows with the original181 denominator,
including failed and unstarted candidates. Plans point to `/cases/0/arrivals`;
actual captures, when available, point to `/request_records`. Unstarted targets
have no invented actual ledger. Failed capture raw references are diagnostic;
their actual offered count is not certified. Successful review means conditional
descriptive evidence, not a final deployment gain or general accuracy guarantee.

## Independent real-budget report contract

The report must be a real independent CPU review, not a generated substitute.
Its fields are:

| Field | Required value |
| --- | --- |
| `schema` | `gsdeploy.twoFIFO_fresh181_real_budget_independent_readiness_review.v1` |
| `status` | `PASS_INDEPENDENT_REAL_BUDGET_BOUND_NATIVE4_READINESS_ONLY` |
| `independent_review` | `true` |
| `fullscore_manifest` | Exact currently pinned fullscore-v2 preparation receipt |
| `fullscore_final` | Receipt of its canonical `run-v1/report.json` |
| `budget` | That final's exact `budget` receipt |
| `fit` | That final's `inputs.matching.fit` receipt |
| `resource_manifest` | That final's `inputs.resource.resource_manifest` receipt |
| `resource_reviews` | That final's original ordered `inputs.resource.reviews` |
| `evaluation_protocol` | Exact expected-score-v2 `EVALUATION_PROTOCOL` |
| `test_summary.status` | `PASS` |
| `unresolved_blocking_findings` | `[]` |
| `GPU_started`, `validation_labels_read`, `numerical_fit_invoked`, `final_gain_eligible` | All `false` |

The independent review and existing source reviews together must include exact
receipts for native4, typed4, full-score-budget1, expected-score2, resource-execute1,
validation-review1, validation-metrics1, validation-evaluation1, solo-reference1,
and the exact measured budget. `source_bindings` is a suitable location. The
existing native4 `response._review_bindings` is called unchanged. Every reference
in the independent report is authenticated, then watched continuously.

## Source and failure boundaries

All initial and dynamically published receipts remain continuously watched
through qualification, capacity waiting, target preparation, capture/review,
evaluation, final atomic write and late exit callbacks. Modification and
restoration also fail. A late failure replaces provisional success with HOLD,
moves usable result receipts to explicitly unauthenticated diagnostics and sets
all candidate provenance and accuracy/readiness qualification false. Fixed-domain
rows and all available ledger references remain reviewable.

The 16 CPU author tests cover writer reuse, complete/dead/test-fake publication,
independent review identity and exact source/budget coverage, mutation and
restoration during waiting/acceptance/final writing, false readiness and foreign
training sources, disk floor waiting, serial execution, first review rejection,
second capture failure, fixed-domain partial evaluation, negative pilot findings
and rejection of controller reentry. Injected processes are CPU fixtures; they
provide no native or empirical prediction qualification.
