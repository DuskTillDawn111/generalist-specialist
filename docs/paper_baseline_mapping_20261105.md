[CherryPick 官方页面](https://www.usenix.org/conference/nsdi17/technical-sessions/presentation/alipourfard) · [Proteus DOI](https://doi.org/10.1145/3617232.3624849)。本地原 PDF、逐页文本和 SHA-256 保存在 `artifacts/paper-baseline-references-20261105/`。

CherryPick 的原约束为作业运行时间 ≤ 上限，通过性能 GP 计算概率。当前基准的资格约束可由已知目录直接判断，所以掩码取 0 或 1，**没有复现未知时延约束的 GP**。原论文给出 10% EI 停止示例，在实验中也使用 1%（PDF 第 11 页附近的比较说明）；本批预先设为 1%，至少 6 个观测。特征沿用此前经典基线的五维紧凑编码，模型位置按种子置换，保留类别分箱的局限；不是论文的 VM 物理特征，也不是原 Spearmint 软件。GP 使用标准化目标、各向同性 Matérn 5/2，长度尺度在 [0.05,5] 上用边际似然估计，噪声 1e-6。EI 在每轮 512 个 Sobol 候选和 64 个 incumbent 邻域候选上近似最大化，均只计算代理分数，不免费查询真实效用。

Proteus 的两个版本均使用 SciPy/HiGHS 的实际 MILP，**只规划一次**，不加论文没有的随机重启、迭代换模型或局部搜索。二元状态 z[m,n] 表示模型 m 的副本数 n；连续 q[t,m,n] 表示请求流量。每个模型最多选择一个副本状态；总显存受限；各任务流量和等于需求；一个状态上的所有任务流量之和不超过所选状态容量，未部署状态不能接受流量。候选空间支持所有 33/117 个合法部署和连续分流，包含零流量驻留状态。原系统不考虑单设备共驻，因此这只是资源规划机制适配。

Q 版用目录的任务质量损失系数，保持原目标含义。U-linear 版从共同初始化的全部已付费观测拟合 `−U ≈ intercept + allocation_coeff*z + flow_coeff*q`，采用中心化岭回归（正则 0.001），一次训练后固定；不调用真实效用公式、梯度或参考最优方案。该线性模型可能无法刻画排队非线性或未观测模型，必须报告误差。它是评估“profile 线性规划能否适配总效用”的对照，不可称为 Proteus 官方效用优化器。

## 固定比较协议

- 7/14 合成模型池，11/29/47 三种子，4 个方法（含当前 BO–MADS）共 **24 次 CPU 搜索**。正式运行前封存配置、源码、论文摘要映射和执行顺序。
- 统一完整候选评价上限 64 次（包括共同初始化的 18/32 次）、60 秒、128 次 MILP；外层 256 次循环保护。采用同一效用、负载、候选域、计费器，单进程、单线程 BLAS。BO–MADS 同批重跑以比较时间，轨迹必须与既有封存结果一致。
- 原生停止条件优先：CherryPick 达到 EI 阈值就停止，Proteus 一次规划后结束。预算是**上限，不要求各算法耗尽**。记录实际使用次数，禁止为凑满 64 次给论文算法添加新搜索。
- 共同初始化全部信息可用。按最好已验证 U 汇报统一保底输出；**同时单独报告 Proteus 实际返回方案的 U**，避免共同初始解掩盖原目标结果恶化。质量版不参与同目标胜负断言。
- 本批只有两个合成目录、三种子，候选目录增大但同时最多两个副本；不是真实七模型 GPU、拟合 FIFO 预测器或论文原系统实验。已知静态 profile 系数是所有方法都可读的目录，不引入新的硬件 profiling，也不修改冻结预测器。
- 不修改当前优化器，不重新拟合真实预测器，不扩大 GPU/负载实验，不因结果差而调参、补种子或重跑。

## 为什么不把其它论文硬塞进同一图

InferLine 第 5 页 Algorithm 1–2 保留固定 pipeline，动作是增大 batch、删副本、降硬件等级；当前单 GPU 基准缺少 batch 和硬件类型选择，只留下删副本会严重退化，替换成增删交换也不再是原算法。MuxServe 的 LLM-unit 枚举和贪心 placement 依赖多 GPU 与并行配置，当前域缺失这些关键轴。Cascadia 第 5–6 页的级联路由、质量约束惩罚与阶段时延 MILP，也不同于每个请求仅选一个模型的分流。故本批选择可清楚映射的 CherryPick 和 Proteus，不以名称增加对手数量。

这些论文方法不能替代此前更强的增删交换、SciPy DE/DA 结果。历史失败和胜出全部保留；本文没有普遍优越性或完整系统复现的承诺。
