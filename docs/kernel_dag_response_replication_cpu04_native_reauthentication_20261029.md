# Cpu04: native intake reconstruction before repeated-instance alignment

Cpu03 preparation and source snapshots remain preserved. The new helper `unified_kernel_dag_intake_reauthentication_v1.py` requires explicitly pinned device-attributes and occupancy-audit receipts, both members of the original intake source set. Role and source gates precede reconstruction. The unchanged, independently reviewed unified intake reparses the same strict native SQLite, rebuilds the complete CUDA graph and static mapping, and republishes its catalog, capture and paths inside a temporary directory. The new helper compares the published report JSON (all fields including input source receipts except the output artifact receipt map) and the complete contents of all three exports. It returns the freshly rebuilt catalog/capture, so caller-rehashed matching fake edges or kernels cannot become native authority. In-memory stream-key tuples are compared via their actual published JSON arrays.

The repeated-instance loader first reauthenticates the producer's exclusive claim, guarded execution and matching predecessor, then invokes this helper before using profile nodes or labels. The design therefore needs `device_attributes` in addition to `producer_review`, `intake_report` and `occupancy_audit` for every capture. Original strict review, native timing domains, exact work and full hardware/context constraints remain unchanged. Each temporary reconstruction is removed normally after validation; original native evidence and published exports stay retained.

Two real CPU reconstructions used the existing four-request unified source with 55,891 kernels, without mocking SQLite or the intake. The original catalog/capture/paths passed. A separately preserved catalog changed a native `stream_fifo` edge to `CALLER_REHASHED_FAKE_DEPENDENCY` and published fresh catalog/report hashes; the same reconstruction rejected it with `Fresh SQLite-reconstructed complete native DAG catalog differs`. The evidence is `artifacts/predictor-unified-intake-reauthentication-v1-20261029-cpu02/report.json`, SHA256 `a63eadb541099b2f900583284db09db1f5f9a63636c087b4a4b4d378addedd75`. All 548 source receipts remained unchanged. This is native mapping reauthentication, not new collection, fit or accuracy evidence.

Large new repeated-template exports use compact JSON without dropping fields. Per-kernel original static/allocation evidence is retained once in the original pinned intake capture, addressed by its exact receipt plus native request/node/identity; it is not duplicated inside every new kernel row. Common static equivalence evidence remains explicit in the shared kernel. This reduces new persistent bytes while retaining the original native provenance. Existing artifacts are not rewritten or deleted.

The original collector's 12 GiB disk floor plus 6 GiB collection scenario applies to native collection only. It is not an additional CPU export reserve. The sequential continuation must estimate persistent and temporary export needs using actual saved raw/trace/SQLite/intake sizes, count remaining matching growth separately, and wait for real capacity if insufficient. Temporary reconstruction directories need no permanent duplicate retention. No GPU session, collector, Nsight process or numerical fit was started for this author work.
