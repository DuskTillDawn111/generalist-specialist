# 原生基线与单变量诊断

分类准确率低不能仅由合法类别输出或 CPU 测试判断原因。现有任务仍使用完整 1000 类；不在看到结果后将候选缩到 ImageNet-A 的 200 类，也不改变质量门槛。

`native_image_text_observation_v1` 只用于诊断。模型按原生路径回答图片主体是什么，不加类别词树；结果保留真实 EOS、空输出与长度截断。诊断协议必须显式声明 `diagnostic_only=true`，该类文本标记 `quality_eligible=false`，不能交给正式准确率评分或模型池准入。是否拼接类别目录和是否启用分类解码器分别由协议记录；观察模式不构成分类结果。

`model_generation_controls` 也仅供诊断：允许单独测试 beam 数与重复惩罚。有效设置进入请求指纹，执行器额外记录与原生生成参数合并后的实际值。正式研究协议允许显式选择经过固定源码核验的命名原生预设：`minicpm_deterministic_chat_v1` 为该检查点原生的 3-beam、1.2 重复惩罚；不会静默继承任意模型设置。预设的任务范围、实际参数和版本都必须在新协议中冻结，不能继承旧配置的质量证据。

分类可声明 `assistant_prefix`，在三种原生路径的分词之前追加同一答案字段前缀。完整 1000 类仍留在解码器中；执行前必须验证每个类别的前缀拼接分词边界一致。分类词树按明确的 beam 数逐行约束，并保留真实 EOS。MiniCPM 的临时工作区按“每序列输入预算 × beam 数”分配，而不把多 beam 错当成单序列，也不缩短上下文。用于单路推理的末位投影钩子不能与多 beam 混用。

`gsdeploy.profiling.diagnostics` 在 CPU 上检查每个对照的父节点、模型、修订、完整样本集合和唯一变化设置。允许的变化是量化、dtype、单项内存优化、单个提示词或单个解码参数；不允许将整个任务、协议、门槛或多个变量当成一个变化。所有媒体文件在准备时校验，实际推理前也读取并校验相同字节，记录图像尺寸或音频采样数。诊断分支没有预热淘汰，以便把空输出等失效现象保存到小样本记录；正式实验仍要求预热有效。

GPU 控制器共用仓库级互斥锁，不因结果目录不同而并发争抢同一 GPU。采集结果分别记录“是否完成采集”“有效输出数量”“质量统计”“失败阶段”，不会把正常完成但答错的请求称为测量崩溃。输入、输出和版本身份不一致会直接停止验证。

正式队列新增两道提前淘汰检查：

1. 完整校准显存通过后，重新从原始输出重建校准质量。未通过时不访问独立质量输出，不进入后续画像或成本实验。直接调用单项 CLI 也不能绕过。
2. 独立质量阶段结束后，除绝对门槛外，还必须通过每个专用对三个通用的全部配对质量检验，才进入容量与成本测量。配对成本仍需真实采集，不能由校准替代。

上述检查完善软件与实验流程，不能保证任何候选模型自然满足科学约束。最终模型池仍须独立评价、真实显存与匹配负载能耗/延时证据；不合格候选需要修正适配或更换。
