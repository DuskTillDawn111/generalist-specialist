# Source-bound native-v3 prospective execution

Native-v3 is an explicit new schema; the frozen v1/v2 executors and bridges are
unchanged. A manifest becomes launchable only when it binds an actual saved
matching fit, a real-fit CPU timing report for all original four public181
calendars, and an independent PASS review covering the exact native-v3,
typed-v3 and timing sources plus the timing report receipt. Test fixtures mock
fit/timing boundaries only inside temporary directories. They certify control
flow, never native accuracy or measured execution capacity.

Native execution uses the original supervisor and exclusive, fsynced one-shot
claim. Both parent and child reauthenticate the exact plan, fit, source freeze,
measured budget and review. A failure after claim consumes the attempt. There
is no retry of a started/claimed capture. Source watches cover all four plans
before the claim and both report/gate/prefix bytes from producer return through
acceptance and drain. The final seal uses a fixed report receipt and its outer
watch covers the full independent audit, save, fsync and final verification.

The child opens two separately authenticated law/target sessions before workers
start. It keeps both alive through shutdown. After actual ordered18 priming it
requires a settled owned prefix, persists that prefix and its public calendar,
then executes producer and full independent auditor propagation. The durable
seal and acceptance checkpoint must finish strictly before the predeclared
first-arrival origin. Crossing the origin before acceptance sends zero targets.
The original181, fixed90+120, FIFO runtime, offered denominators, resident owners,
original six utility terms and stability rules remain intact. No global cap1/2
or unimplemented batching/cache/weight-sharing benefit is added.

The CPU budget protocol is queue-hypothesis only; it excludes any new resource/
six-term score producer, whose live replay and seal need a separate measured
budget and contract. It uses the real saved full law and a verified training-only
prior prefix. Each candidate keeps all181 requests, all12 worlds and both complete
numerical passes. It records numerical and persistence stages separately. This
training-prefix timing workload cannot observe the future native target prefix;
therefore a conservative declared margin and the actual live hard deadline
remain necessary. An independent review must judge the measured artifact, not
merely assert a qualification Boolean. Preauthentication is excluded from the
live lead only because both sessions finish it before runtime startup.

A larger live lead requires a newly benchmarked and newly prepared manifest;
measurement and drain stay90+120. A completed execution/prefix receipt binds
native-v3 exclusively. It is narrower than an independent stdout/protocol,
resource, quality or prediction-accuracy review. Matching training10+60 still
does not certify memory/energy or complete utility for90+120. Successful launch,
CPU tests, source-supported hypotheses and completed receipts make no final
spillover-gain claim.
