## 当前机制与已查明的缺项

已有 `paper_profiled_fifo_v1` 可以在活动阶段改变时重新定价剩余工作，沿同一 FIFO/生命周期事件过程继续推进。`calibrated_replay_v2` 的固定服务回放只作历史工程对照。已有机制可运行与其在目标执行协议下预测准确是两件需要分别验证的事。

本轮准备工具 [prepare_c1_qualification.py](../experiments/prepare_c1_qualification.py) 与 [c1_qualification.py](../gsdeploy/c1_qualification.py) 产生了[原始准备包](../artifacts/c1-lite-v2-20261103/qualification/packet.json)，状态为 `PREPARED_NOT_EXECUTED`。

| 检查 | 本次结果 | 含义 |
|---|---|---|
| GPU 探测 | packet 中 PATH 未找到 `nvidia-smi`，设备节点为空 | 当前进程无法启动目标 GPU 采集 |
| 两条目标历史运行 | 178+168=346 个请求；旧字段中的阶段及 READY 均为 0 | 不能用 handler 总耗时拆造阶段或填补 READY |

| 受压容量及输入难度层 | 尚未测量 | 热点 QPS 和 harder 输入清单保持空值 |

字段清点从不授予训练资格；即使字段存在，仍需校验执行身份、时钟、阶段连续性、驻留/活动 roster、请求与生命周期。历史数据已经查看过，标记为历史诊断，不能改成盲确认。

## 能耗与副本权衡

正式目标保持 `six_term_reference_v2`：能耗为完整 `J_episode / J_reference_episode`。episode 包括加载、priming、warmup、相同到达窗口及完整排空，比较相同 offered cohort；遥测缺口、失败和少完成请求不能算节能。

旧回归的 worker 运行功率系数为 0，不能用于确认专用模型/副本没有成本，也不能支持“能耗已经足以惩罚专用”的结论。本轮未强制其为正，未改权重或增添罚项。整卡并发功率需要从整卡测量与完整积分检验，不能直接求和孤立模型功率；副本增加的方向与幅度待实测。

## 接下来如何取得资格

1. 绑定目标 checkpoint/后端/输入协议下的完整阶段捕获生产器及独立 solo 模板；完成时钟、cohort、READY、资源与整板功率核验。
2. 先在短 pilot 内确定稳定容量及可辨识上下文，冻结阶段身份、输入清单、正式参考和角色划分；pilot 不输出跨 horizon 的正式 U。
3. 仅用训练记录拟合。每个拟合上下文至少两个独立轮次；开发数据确定误差阈值、最小有意义效用差与确认重复数，然后锁定确认候选。
4. 在未用于选点的匹配记录上验证同输入服务、FIFO 等待/延迟、READY、goodput、峰值显存、完整能耗、六项效用及排名；分负载、模型、副本报告。
5. 对开发阶段选出的固定内部路由与端点/网格/卸载替代部署做独立配对确认。收益区间覆盖新增部署成本后，才讨论稳定连续路由价值。

准备包预留三个训练到达种子和两个确认到达种子；这些仅是保留编号，尚未采集，不能因数量满足就授予显著性。选点造成的偏差由独立固定候选确认控制，多候选确认另需预声明比较规则。

`paired_route_evidence` 按独立配对运行计算 t 区间，拒绝合成、已用于选择、重复种子或身份变化的声明；其输出明确保留 `physical_qualification_granted=False`。它不核验声明背后的原始日志，不是完整验收器；样本量、独立性与分布假设仍需按开发协议确认。

## Gate 决定

G0 数据/目标、G1 动态预测、G2 场景代表性均待定。不能宣布真实跨模型负载干扰已解决、专用过强已解释完毕，或稳定非网格内部路由已发现。软件正确性与小样例对照单独见[实验报告](c1_lite_hybrid_experiments.md)。
