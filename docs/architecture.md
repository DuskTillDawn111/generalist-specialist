# 系统架构

项目围绕同一份 `SystemConfig` 和一个 `DeploymentSystem` 组织。配置定义已准入任务路径、服务时间、经验容量、显存、负载和效用权重；规划与执行始终使用同一配置。

| 组件 | 责任 |
| --- | --- |
| `config.py` | 可移植配置、能力/副本证据与计划约束校验 |
| `optimizer.py` | 模型任务子集、Pareto 部署优化、固定部署网格路由 |
| `prediction.py` | 原周期 FIFO 服务/排队预测与统一效用算术 |
| `system.py`、`cli.py` | 规划、预测、执行、评估的公开接口 |
| `routing.py` | 将任务流量分配转换成逐请求加权轮询 |
| `runtime/` | 独立副本进程、负载、请求生命周期、排空与遥测 |
| `backends/` | 原生模型加载/任务预处理与 CPU mock 后端 |
| `metrics.py`、`stability.py`、`evaluation.py` | 请求指标、积压重建、稳定性及效用证据 |

## 规划

K=1 的每个任务全部交给一个准入模型。优化器枚举单个模型可接纳的任务子集，缓存局部 FIFO 预测，再按模型依次合并不相交任务 mask。相同阶段/mask 的状态以显存、成本和窗口内完成数进行精确 Pareto 支配剪枝。

最终计划回到完整 FIFO predictor 复验；公开接口再独立检查流量守恒、能力关联、已测副本数、显存和容量。K>1 时需显式给定固定部署，搜索离散分流网格。没有为 K>1 声称联合部署全空间优化。

`a.json`、`b.json`、`c.json` 保留历史单副本域用于回归。当前静态实验使用 `static_replicas.json` 和 `c_replicas.json`，接入已有实测双/三副本容量及显存，不做线性外推。副本容量来自历史代表任务的实测吞吐比；转移到其他任务或共驻留组合仍是规划代理，不能当成新的真机容量认证。具体来源、任务和数量边界保存在模型池的 `replica_evidence`。

`supported_tasks` 表示当前质量政策准入的路由，通用模型的 `capabilities_verified` 另外记录已验证推理能力。二者分别保留：例如 Qwen 能运行 OCR，但历史质量记录未达到旧 OCR 门槛。没有强制保留通用模型的约束；全专用方案只要覆盖所有任务并满足资源条件，就可参与优化。

## 执行

一个模型副本对应一个独立 worker 进程；`model#i` 是传输 ID。路由按流量权重选择传输 ID，任务输入通过 stdin 发送，READY/RESULT/ERROR/BYE 通过 stdout 收集。主机发送队列、请求时间戳和模型 handler 时间分开。

执行分为路径 priming、可选预热、正式请求窗口及有界排空。预热和 priming 不进入正式指标。周期流量和独立 Poisson 流量使用固定 seed。资源采样独立运行，不持有请求运行时锁；进程关闭只处理当前运行拥有的 worker。

## 评估

保留 E2E、提交后耗时、worker handler 时间、排队等待、窗口内完成和排空完成等口径。原积压重建与稳定性阈值保持。任务加权 P95 与 pooled P95 分别报告。

GPU 内存通过进程归属采样；缺少实际内存、质量确认或合法运行证据时，只给诊断效用，正式 U 为空。mock 永不产生正式模型性能 U。预测器的共驻留/尾延迟限制仍成立，迁移不升级任何历史科学 Gate。

## 开发约定

核心代码只依赖 `gsdeploy` 与明确的第三方库。实验仅调用公开 API，不复制算法源码、不写核心模块全局变量、不通过阶段目录导入。原生 GPU 模型依赖保持可选，导入规划 API 不加载 Torch 或 Transformers。

实验输出写入 `artifacts/<experiment>/<run>/`，不覆盖已有观测。新增模型先提供质量准入和实测画像，再登记 backend；新增方法在优化/预测模块实现，再通过实验配置比较。
