# 系统架构

`DeploymentSystem` 贯通配置、联合搜索、逐请求预测、运行和离线评价。核心代码只在 `gsdeploy/` 开发，历史模块不进入依赖。

| 文件 | 职责 |
| --- | --- |
| `config.py` | 质量已准入路径、经验副本域、负载、资源约束和实验条件 |
| `trace.py` | 固定种子周期/Poisson 请求轨迹、轨迹哈希、副本路由展开 |
| `routing.py` | 搜索、预测、执行共用的加权轮询 |
| `optimizer.py` | 部署、副本和分流联合枚举、容量/显存/效用上界剪枝及预算报告 |
| `prediction.py` | 同一请求轨迹上的副本 FIFO 仿真与统一效用算术 |
| `energy.py` | 完整方案能耗画像身份、功率积分和启动成本摊销 |
| `system.py`、`cli.py` | 公开规划、预测、执行、评估接口 |
| `runtime/`、`backends/` | worker 生命周期、输入、测量与模型适配器 |
| `metrics.py`、`stability.py`、`evaluation.py` | 原始计数、延迟、稳定性与正式评分证据 |

## 搜索怎样接入效用

先以负载、种子、到达过程和窗口 H 生成一份完整请求轨迹，之后改变部署或分流都不会重新生成请求。任务按名称确定身份，与 JSON 字段顺序无关。预测与运行都把模型路由均分到 `model#i`，使用同一个加权轮询器选定逐请求副本。

联合搜索枚举模型的零副本及有记录的正副本状态，提前排除显存超预算或某任务总容量不足的部署，再依次分配任务流量。`K=1` 只有单路径；`K>=2` 支持分流，无须先固定部署。固定部署仍可通过 `--deployment` 指定。不存在必须保留通用模型的约束，全专用只受覆盖、质量和资源约束。

网格包含分母 1 到 K 的所有整数组合，K 增大时保留旧网格点。K>=2 额外生成剩余容量边界上的可行性见证，避免只因粗网格错过满足容量的分流。四个及以内接收模型枚举所有填充顺序，更大的集合使用旋转顺序；这是补充见证，不是连续路由完整求解。最终无解状态明确写作 `NO_FEASIBLE_ENUMERATED_PLAN`，不能据此断言物理不可行。

每个完整候选交给整个方案的预测器评分，废弃旧局部任务 bundle 的 Pareto 支配关系。剪枝上界使用：已部署显存成本、已分配任务实际轮询得到的无排队服务样本均值/P95、未分配任务的最短可能服务时间，并令非负的吞吐损失和能耗成本为 0。请求逐个延迟均不小于对应服务时间，均值与分位数具有单调性，因此上界不会低估候选效用；不依赖能耗可加性。

`search_max_states` 同时限制部署枚举、路由生成和递归搜索，防止组合爆炸。完整搜索且评分完整时才报告 `OPTIMAL_ENUMERATED_DOMAIN`。预算耗尽报告当前解、`search_completed=false`、乐观上界和 gap；没有解时也不声称不可行。最优证书只覆盖声明的有限域与 FIFO 代理，不覆盖连续路由或 GPU 实际表现。

缺能耗的候选保留 `U=null`、`eligible=false`。完全缺能耗画像时，搜索可以按已知分项的诊断值给出可运行候选，标记 `DIAGNOSTIC_ONLY_NO_ENERGY`，不重新归一化权重；这不是五项最优。当只有部分候选有画像时，报告能耗域不完整，不给全域五项证书。

`search_policy=nominal` 优化原始服务时间；`robust` 要求同一请求轨迹在 1/1.25/2 倍服务时间下均合法，并最大化三者最小效用。服务压力测试不是到达率压力，也不是统计置信区间。全方案能耗画像必须匹配压力条件，未知压力能耗不填零。

## 实验条件与画像边界

计划保存完整 `problem`，包括 H、seed、到达过程、排空、预算、权重和参考值。运行默认继承这些条件。显式改变时长/种子时重新预测该部署，并记录 `optimality_transferred=false`，原计划的最优结论不会转移到新问题。验收入口先按运行条件规划，再启动。

当前静态入口是 `configs/static_replicas.json`：五项等权、K=4、H=120 秒、seed=42、预算 100000 状态。`c_replicas.json` 保留原单副本参数并使用历史双/三副本测量；代表任务的吞吐比转移到其他任务和同卡组合仍是代理，不是新的容量认证。A/B/C 单副本配置保留显式四项历史权重，输出 `legacy_four_term`。

`supported_tasks` 是质量准入路径，`capabilities_verified` 是已验证的推理能力。Qwen 能执行 OCR 并不表示其旧质量记录通过 OCR 门槛。没有新质量证据时不放宽门槛。常数服务时间没有输入大小、真实服务时间分布或同卡干扰模型，输出持续标注这种不确定性。

## 运行与评价

一个副本一个独立 worker 进程。运行分为加载、priming、预热、正式窗口、有界排空与关闭。预热完全排空后，正式窗口从空队列开始，预测采用同样初始条件。正式请求在发送之前全部登记，失败时未来未提交的请求仍在完整 cohort 中；中止窗口不能拿缩短的时长或已提交子集改分母。

吞吐损失为 `1-N_win/N_off`，延迟包含排空完成的正式请求，权重固定为任务输入请求率比例。GPU 内存用拥有的进程快照，采样峰值另作硬预算检查。整卡功率遥测从加载前开始，带单调时钟时间戳；区间缺失、采样错误或能耗画像缺失时，完整五项 U 为空。CPU/mock 从不调用 GPU 遥测，也不产生正式性能效用。

离线评估复核完整到达轨迹和逐请求路由、质量证明、资源、完成率与稳定性。实际观测与预测分开记录，不把排空成功单独当作稳定性认证。详细公式见 [效用规范](utility_specification.md)，修复验证见 [搜索修复](search_fixes.md)。
