# 下一阶段：专用多副本向通用分流的真实负载发现

前轮等流量实验完整归档于 `artifacts/static-study-gpu-20261022/study-01-archive-index.json`。
其预测器、权重、搜索结果、GPU数据与失败历史保持原样。

## 研究目标

在七模型池和现有显存预算下寻找一个真实静态任务负载，使自由联合优化主动选择：

1. 同一目标任务的专用模型驻留至少两个副本。
2. 该目标任务同时给专用与通用正流量，专用保留主要处理职责。
3. 通用承接该任务产生质量或资源代价，但排队和尾延迟改善使六项总效用更高。

这是负载发现研究，结构是验收目标，不作为自由搜索约束。多副本及分流应由总效用优化产生。
扫描的全部负载及失败结果保留；筛选数据与独立确认数据分离。

## 推进顺序

1. 从现有真实单/多副本画像分析容量、共驻显存、通用可接流余量；先挑目标任务。
2. 保持七模型池、六项权重、质量记录、参考值和显存预算，预先记录负载扫描范围。
   主要提高目标任务到达率，其他任务保留较轻背景流量；允许目标/背景负载一起组成小范围扫描。
3. 用现有预测器做探索筛选。旧低负载校准不自动覆盖高负载多副本干扰，候选仅是待验证发现。
4. 对少数候选做原生GPU开发验证，确认真实多副本排队、共驻干扰及通用余量。
   如需扩展预测器，另建版本、留出验证，不覆盖前轮。
5. 冻结最终负载、预测器和候选；在同一请求轨迹下独立确认，并复核同域DFS与效率。

## 必须比较的方案

- 自由搜索赢家：不限制多副本或分流，要求最终自然出现目标结构。
- 全域最优不分流：重新选择模型、副本和路由，避免仅战胜一个拥塞的固定方案。
- 同赢家部署最优不分流：隔离将该任务分给通用的路由收益。
- 专用扩容的强替代方案：允许选择更多可行专用副本并重新优化；若无法共驻，记录显存原因。
- 最强其他部署/路由及必要的单专用副本限制对照：区分多副本收益与分流收益。

同一物理方案去重；完整方案评价次数、GPU次数、预算状态与最优证书分别报告。
若现有真实画像及资源下找不到该结构，如实报告，不通过强制部署/分流、改精度或改权重制造结果。

## 机制边界

合理机制是专用多副本仍接近高利用率、排队代价明显，而通用有可用余量；少量分流降低总成本。
不要求专用多副本永久超载：若到达率严格超出其容量，不分流可能不可行，仅能证明可行性改善，
比双方可行时的总效用改善更弱，应另行标注。
优化仍为静态路由比例；按实时队长逐请求溢出属于另一类动态路由实验。
