# H600 四组公平候选域与确认准备

本文只定义下一阶段设计，不冻结新计划、seed、预算、预测或统计协议，不启动 GPU，不修改现有程序或进度记录。它不把当前任何 gate、准入画像或收益视为已通过。

现有 shared 与整请求 admission 后端可以组成公平的有限路由比较，但目前还不能开展合格的最终四组收益确认。最先需要完成独立预测门槛和机制诊断，并补齐准入模式的六项资源与容量适用性。固定单路由的准入试点只检查服务迁移、队列与机制激活，不能选出最优禁分流基线，也不能给出优化执行方式的六项收益。

## 1. 四组分别回答什么

固定驻留仍为 `text#0 + text#1 + generalist_2#0 + ocr#0`。原执行方式为 shared；优化方式只能是在后续独立合格后、在最终确认之前锁定的一个明确 controller，例如 global max_active=2 的整请求 admission。不能在最终结果出来后从 max1/max2 中挑最好模式。

|组|执行方式|搜索权限|锁定内容|
|---|---|---|---|
|A|shared|禁 text→G2 分流|该模式禁分流有限域的完整搜索结果、所有并列、预先确定的执行方案|
|B|shared|允许 text→G2 分流|该模式允许域的完整搜索结果、所有并列、预先确定的执行方案|
|C|锁定的 admission|禁 text→G2 分流|该模式自己的禁分流搜索，不能复用 A 的获胜路由作为默认最优|
|D|同一 admission|允许 text→G2 分流|同一模式自己的允许域搜索，不能直接继承 B 的路由|

核心差值是优化方式内部的 `U(D) − U(C)`；`U(B) − U(A)` 是原方式的对应差值。`U(D) − U(B)` 混合了执行机制与策略变化，不能替代核心差值。差分 `[(D−C)−(B−A)]` 可以另行预声明为次级结果，也不能替代核心比较。U 沿用原六项负成本定义，数值越大越好。

“允许分流”必须是允许而非强制：禁分流域应包含于允许域。若允许域的最佳方案仍不分流，两组可以选择同一方案，按相同策略与配对证据报告，不能为了制造差别强制选择一条较差的分流路线。实际发生分流的子域可另列诊断，不作为替换后的主结果。

## 2. 现有路线域及“最优”的边界

当前 native 生成器每模式只有以下四条静态路线，image/asr 固定到 G2，ocr 固定到 OCR；变化仅在 text 的 alias 权重。

|route|text#0|text#1|G2|禁分流域|允许域|
|---|---:|---:|---:|---|---|
|balanced|1/2|1/2|0|是|是|
|skewed|1/4|3/4|0|是|是|
|spill_low|5/12|5/12|1/6|否|是|
|spill_high|1/3|1/3|1/3|否|是|

记 `N={balanced,skewed}`，`A=N∪{spill_low,spill_high}`。**“最优禁分流”只能写成“固定驻留、指定执行模式、上述两路线有限域内的最佳禁分流”。** 当前域没有反向 skewed、其他两专用比例、其他分流比例、其他任务路线、动态路由、不同副本数或其他部署。即使模型完整枚举或八次物理运行都完成，也不能宣称全路线或物理全组合最优。

最小可比设计可以复用这四条路线，前提是两模式采用相同 N/A 与路由生成器，不以“另一模式没画像”为由删掉它的较强基线。每条 route 在两模式使用完全相同逐请求路由，不能只有 family 汇总权重相同。balanced/skewed 聚合后的 family 到达率相同，但 alias 排队不同，不能合并成同一条件。

若需要更强的禁分流结论，应在看到新训练或确认结果之前扩展共同域，例如增加反向 skewed 和一组预先确定的两专用比例；同时明确分流比例/专用内部比例的有限网格。扩域意味着新画像适用性、新候选预算和新验证协议，不能只给已有两条基线补一个“全部”标签。域外仍 UNKNOWN。

## 3. 哪些现有证据可以复用

|证据|可复用的范围|不能据此推出的结论|
|---|---|---|
|H600 shared primary 训练画像、选定 full16 服务模型|原始角色、来源和条件完全匹配时用于 shared 训练/规划；模型选择继续只用训练 CV|不能自动作为 admission 专属训练，也不保证新输入子域或新路线支持|
|shared H600 资源画像|相同 worker/context、shared 资源配置、route、H/drain/warmup、输入生成分布等条件下，按现有来源审计使用|不能复制成 admission 的启动能量、条件功率或拥有进程峰值|
|当前独立 H600 shared 验证|冻结预测器在该验证域的通过/失败证据，保留原结果；验证请求不进训练|不能把验证原始值用来挑选最终获胜路线，不能当作新的独立最终收益 block|
|阶段三 fixed spill_low 的三模式试点|服务迁移诊断、观察到的控制器激活、原稳定性以及该路线的实际完整性|不能证明 balanced/skewed 下的准入容量；不能授予四路线 ΔU/排序、E/M/startup 或最优资格|
|原 catalog、g(n)、rho 与稳定性代码|保留原数学定义、参数、source SHA 和审计接口|不能因资源配置改变而自动继承数值适用性，也不能把“有数值”当作“该模式资格已验证”|

共享服务规律可以在准入下作为明示的迁移假设，但新模式必须独立验证其服务、全过程队列、各任务 P95，以及禁/允许路线之间的 ΔU 符号和候选排序。单路由三模式试点没有路线内决策验证，不能直接跳到最终四组。

admission 的资源与容量缺口需要新的、明确标为训练的数据：按 mode/controller/route 绑定 startup→priming→measurement→drain 的 owned PID 显存、完整 board power、真实 worker service、质量和来源。若复用原两训练 seed×四路线框架，每个新准入模式至少有八个 H600 primary 条件运行；这只是条件覆盖预算，不表示两 seed 已充分校准不确定性。现有验证/机制试点不得在事后改成这些训练运行。

原 `n` 仍按原驻留/副本定义。原归一化服务与原接口保持 `mean(worker END−START) * g(n)/n`，rho 保持 `sum(planned_routing_rps * service_ms/1000)/g(n)`，阈值仍为 `.8 + 1e-8`。max_active=1/2 不是新的 n，不可替换 g(n)。等待、parent tail 不混入 service；有限请求数/H 和事后 busy ratio 不替代规划到达率。

对新确认 seed 的容量证据必须是如实标明的前瞻统计迁移及独立适用性验证，不能添加伪造的 `kind=measured` target catalog key。现有 capacity entry 若只接受 shared 精确条件，就保持该限制；准入需要独立版本的适配/接受政策与新证据。全局 permit 负载与 bounded drain 是补充检查，原 family rho 仍须通过；二者不能互相替代。

## 4. 公平搜索与 CPU 核验

每模式、每权限集合分别枚举完整声明域。候选记录至少包括 route、base worker/context、独立 controller identity、公共 trace/generator、模型及其训练 source、质量证据、startup/功率/拥有进程显存画像、原容量及适用性、预算/稳定性要求。所有原六项权重、量纲归一化、启动摊销、安全因子与阈值不变；显存安全因子只能应用一次。

需区分三种结论：

1. **模型最佳**：在已声明、模型可计算且模型约束通过的有限域中，U 最大。它不是原资格最佳或实际最优。
2. **原资格约束下的有限域模型最佳**：完整域每候选的原 rho/容量适用性、完整六项、显存和 drain 可行性均明确，或以经证明的界排除后，才可在合格子域宣称。存在未排除 UNKNOWN 时不认证这一最优性。
3. **独立实测比较**：最终新请求上的预锁定策略差值与有限候选实际表现。它不把模型最优升级成物理全域最优。

当前 `h600_selected_search_v2.py` 的适用域是精确四条 shared 路线；其继承核心按 model_eligible 更新 incumbent，并把 original rho 单列，明确不认证 original-gate-constrained optimum。不能直接把它的输出称为 C/D 的原资格最优。扩展到准入或正式原资格约束搜索需要新版本入口和对应测试，不能改冻结代码或直接绕过 wrapper 调 generic core 后扩大结论。

plain DFS 与 bounded DFS 应使用同一声明域、完整公共未来到达和相同模型/资源/质量，分别进行 fresh rollout，不从历史预测表或实际 outcome 抄 U。逐项核验最大值和**全部**并列集合，原数值 tie tolerance 保持 `1e-12`。保守界必须对当前六项模型和资格域有效，严格 `upper_bound < incumbent − tolerance` 才能剪枝，不能剪掉可能并列的候选。四路线域太小，剪枝数为零也如实记录，不宣称加速收益。

UNKNOWN 不能作为零效用、已不合格候选或忽略项。资源/质量/容量/执行模式缺证据、未见阶段组合、预测预算耗尽、未完成 drain 均保留原因及全请求分母。若能以独立有效的可行性证明排除候选，应保留证明与适用性；点预测排不完仅是 `PREDICTED_DRAIN_INFEASIBLE` 的预测/执行预检，不是物理不可行定理。被跳过的 mode/route 不得在“完整最优域”中悄悄删除。

每个 best 的所有 tolerance ties 都保留。若执行策略需一个方案，使用事先固定的确定性选择规则，并明确其只是 tie 内选择；或者确认全部 ties。不能在验证/最终观察之后按收益挑 tie。模型 tie 不等于统计等价，观测 tie 也按事先统计规则报告。

## 5. 最终确认如何防止基线偏弱和选择偏差

建议把“训练上锁定的四策略”与“该有限域的实际基线覆盖”同时保留。

训练/规划阶段先锁定每模式的 N 最佳与 A 最佳、全部 ties、tie 选择规则和一个 admission mode。当前独立验证只作 gate 与失败诊断，不能用于回填训练 U、挑 route 或更改阈值。最终确认另用未使用的 seed/request blocks，不能复用 seed627701 的独立验证请求或 seed627801 的机制诊断作为最终收益数据。

为检查“相对最强禁分流”，优先在每个最终 block **完整执行两模式各四条 route，共八个不同配置**。因此 A/C 的另一条禁分流候选也有独立实际观测，不能只测训练预测最好的基线便称其实际最强。相同配置被四组标签重复选中时，在同一 block 复用相同物理结果，不把它当两份独立样本。

对每个 mode、block b，完整报告以下量，不能混用：

- **锁定策略差值**：`U_b(locked_allow) − U_b(locked_no_spill)`，回答训练选出的允许策略能否改善训练选出的禁分流策略。
- **相对完整禁分流有限域包络的差值**：`U_b(locked_allow) − max_{c∈N} U_b(c)`。这是对强基线更保守的事先定义的最终统计量；max 运算和候选全集必须提前写明。
- **完整域实际数值包络诊断**：各路线实测 U、`max_A U_b − max_N U_b`、实测 ties/排序。由于 A 包含 N，该数值包络按定义非负，且利用了当块实际结果选优，**不能当作可部署策略取得的分流收益**，更不能把其非负性当算法成功。

第二项的 baseline max 在完整集合上事先定义，不是事后删除不利数据；它衡量对该块两个实测禁分流备选的保守差值。它仍带运行噪声，不能称为未知总体均值的精确最佳基线。若另需“超过每个禁分流候选的总体效用”结论，必须在新最终统计协议中预声明对各 `locked_allow − c` 的配对估计及适当的多重比较/同时区间，而不是按确认样本均值挑一个 c 后套未调整区间。

不得用 `max_A` 的确认获胜者替换 locked_allow 后继续报告同一块“独立确认”。若确认只测每模式两个已锁定策略，成本可低于八配置，但结果只能针对这些锁定策略，不能声称覆盖两路线中实际最优禁分流。测全部 ties 也不能替代测完整 N。

## 6. 同到达、独立请求与完整记录

同一 block 内，各 route/controller 必须使用同一完整公共输入/到达 trace：相同 task、pool/sample 身份、长度、时刻、H600、drain300、warmup0、驻留和 priming。对应 route 在两模式逐请求 alias 相同；不同 route 之间只按其声明权重/确定性路由改变 alias。质量以同一真实参考和相同请求分母计算，不把长输入、OCR、失败或尾部请求删掉。

不同角色的数据边界必须提前固定：训练只用于模型/资源/容量估计与训练内选择；独立预测验证用于接受/拒绝；最终 blocks 只用于锁定策略确认。新的 seed 只是新抽样序列：若 pool_id 来自同一 known-input 有限池，不能称为未见样本或新输入泛化。应报告 pool 重用、跨角色样本重叠及采样分布；若目标是输入实例独立或未见长度泛化，需先建立不重叠实例域并重新验证支持，当前画像不能自动外推。

“独立”以完整 seed/block 作为运行统计单位，不把每条请求、同一次跑中的四任务或 alias 当作独立重复。两模式与 routes 在 block 内配对，多 block 之间的独立抽样/执行条件需预声明。periodic 固定到达意味着这里验证的是已声明到达过程；不能外推为突发流或未知全过程到达。

启动与测量分阶段保存原始时钟；source/model/resource/容量/最终策略 seal 要早于实际 startup。每次采集记录完整 invocation、READY/START/PHASE/RESULT、controller 激活、owned PID telemetry、等待/响应尾部、原稳定性与退出。相同 priming 和 warmup 逻辑在 admission 中也消耗 permit；不能只给某组额外预热或复用另一组的驻留历史。

候选执行顺序应在结果前固定为配对、跨 block 平衡/随机化的次序，并公开初始空闲/冷却条件，避免所有 shared 总在冷机、admission 总在热机。运行使用 GPU 锁避免并行干扰。不得因一组过慢就在中途改顺序、重试换 seed、减载或延长 drain。硬件/worker 异常、未完成 cohort、缺 telemetry、资源超限或原稳定性失败都保留在该块及总分母中；后续是否停止由预先失败规则处理。

逐任务 P95、E2E、Q/T/L/P/M/E 及 U 均用原定义和完整请求群。预测 handler END 与实际 parent receipt 的尾部差异保留，不能改实际 E2E 起点到 grant 或 worker START。缺一项六项证据不能重归一其余权重；startup 不能因驻留相同就在跨模式比较中自动省略。

## 7. 预算与停止规则的预声明

此处不给尚未评审的 R/seed 一个“已经冻结”的数值。最终协议应在结果前明确训练、模式适用性验证、CPU 搜索和最终确认的分别预算；不能用剩余 GPU 时间决定是否多测一个有利候选。

|阶段|固定四路线域的配置数预算|能支持的结论|
|---|---|---|
|复用 shared 原 primary|已有两训练 seed×四 shared route=8 条，严格条件匹配才复用|shared 训练估计；不自动等于最终资格|
|每个新 admission 模式的训练|两训练 seed×四 route=8 条起始条件覆盖预算|该模式服务、资源和容量估计；重复数是否充分另审|
|每个新模式的独立预测/容量验证|每个预声明 validation block×四 route；不能只用单路由试点|完整 route 的服务/队列/P95、ΔU/排序及容量适用性门槛|
|两模式最终完整域确认|R 个全新 block×两模式×四 route=8R 条|四锁定策略、完整 N 基线覆盖及八配置有限域诊断|
|若 max1/max2 都保留为未锁定优化候选|最终前须解决模式选择；若正式作为多个假设，则共同域/预算/多重比较相应扩大|不能从两套最终结果中事后挑一套冒充预锁定四组|

每 H600 运行测量为 600 s，排空预算最多 300 s，另计真实 startup、priming、shutdown 和预声明冷却；不能把 `600+300` 当精确运行耗时或漏算启动能量。最终 8R 条的时间与显存预算应包含这些额外部分。CPU 候选预算须覆盖完整集合和第二次 fresh DFS 核验；预算用尽而未覆盖的候选保留 UNKNOWN，并输出 evaluated/pruned/unknown/ineligible 数量、有效界与 gap，不能将 best-so-far 写为已认证最优。

一次实际失败不做静默补跑；预声明的替代/重试政策如果将来需要，应另给角色、原因和原失败记录，不能覆盖原始输出或替换 seed。当前准入 pilot 的无重试约束继续有效。若未能测完全部最终 block/候选，保留全部计划分母并报告 INCOMPLETE。任何统计区间或检验以独立 block 为单位，提前给出 R、主假设、实用改善阈值、置信水平及多重比较政策；R 不足就报告统计证据有限，不从请求条数虚构精度。

|阶段三固定路线没有预声明的有利服务/队列结果，或改善未覆盖新增等待|`NOT_ELIGIBLE_AS_DEMONSTRATED_OPTIMIZATION`，当前不能称该模式为已经有效的优化方式。可报告无改善/负结果；这不证明所有未测路线的六项效用都无改善，扩域仍须新前瞻证据。|
|模式专属 startup/E/M/Q、容量迁移或四路线决策证据缺失|`NOT_ELIGIBLE_SIX_TERM_OR_CAPACITY_UNKNOWN`。继续训练/独立适用性补齐，不能复制 shared 数值、缩减六项、放宽 rho/g(n) 或稳定性。|
|预算/完整候选/all-ties 未完成|`NOT_ELIGIBLE_DOMAIN_INCOMPLETE`，只报告 best-so-far 与 UNKNOWN。当前两条禁分流也不能改称全路线最优。|
|最终确认完整但锁定允许策略不优于强禁分流基线|报告 `NO_CONFIRMED_SPILLOVER_GAIN` 或事先定义的负结果状态，不声称分流收益任务成功；保留所有六项、资格与不确定性。正点估计但区间/重复不足同样不能写成已确认收益。|

阶段三 service-only pilot 没有预声明六项收益 gate，不能在看完结果后发明一个宽松门槛宣布成功。若其有利信号足够值得推进，下一步是先补 mode-specific 资源/容量和完整路线验证；“值得继续”与“已合格进入四组”分开记录。
