# GSDeploy 连续路由—离散部署双层优化研究与开发计划书（V3.0）

**项目：** Generalist–Specialist Deployment Optimization

**研究方向：** 单 GPU 资源约束下，基于 GPU 共驻干扰和 FIFO 队列性能预测的模型部署、副本配置与连续任务路由联合优化

**计划状态：** 最终开发方案

**实施原则：** 保留现有算法、独立开发新算法、分阶段验证、以实验结果决定是否替换

---

# 一、研究目标与基本前提

## 1.1 研究背景

当前 GSDeploy 系统研究单 GPU 资源约束下，如何联合部署通用模型（Generalist，G）和专用模型（Specialist，S），在满足任务质量、显存及其他资源约束的情况下，提高系统整体效用。

系统需要决定：

1. 部署哪些 Generalist 和 Specialist。
2. 每个模型部署多少副本。
3. 每种任务分配给哪些模型。
4. 每种任务分配给各模型的连续流量比例。
5. 在 GPU 共驻干扰和 FIFO 排队共同作用下，哪个部署—路由组合具有最高效用。

现有实现主要采用离散路由网格，将候选路由列和模型副本状态共同放入 MILP，再使用完整性能预测器进行反馈优化。

我们希望研究另一种求解架构：

**外层连续路由优化 + 内层固定路由部署优化 + 完整性能预测反馈。**

## 1.2 必须明确的研究前提

本次任务假设：

- GPU 共驻性能预测器已经具有足够准确的预测能力。
- FIFO 队列预测器已经具有足够准确的预测能力。
- 预测器能够评价合法的模型组合、副本配置和连续路由方案。
- 预测器能够返回相应的完整系统效用和约束检查结果。

本次任务**不包括**重新设计、训练、校准或改进上述预测器。

Codex 只负责检查预测器接口，并实现新算法必要的输入输出适配。

如果当前仓库中的 `route_load_replay_v1` 等功能仍是 `UNIMPLEMENTED` 占位模式，需要明确记录，不得将零下界视为实际性能预测。可以使用接口一致的合成预测器开发和测试算法，但必须区分模拟验证与真实预测器验证。

## 1.3 核心研究问题

我们的研究不是证明双层数学表达式与联合表达式不同。

原始联合优化为：

\[
\max_{(D,r)\in\mathcal F}U(D,r)
\]

双层形式为：

\[
\boxed{
\max_{r\in\mathcal R}
\left[
\max_{D\in\mathcal D(r)}U(D,r)
\right]
}
\]

在可行域和评价函数一致时，两者数学上等价。

因此，本次优化算法研究的真正目标是：

**能否利用连续路由、模型激活状态和离散部署的结构，在有限的优化时间及完整预测调用预算下，比现有联合 MILP 更高效地寻找高质量方案？**

重点研究：

- 求解时间。
- 完整预测器调用次数。
- 系统综合效用。
- 约束可行性。
- 不同负载下的稳定性。
- 模型激活边界对求解效率的影响。

不能仅因为采用双层结构就宣称算法创新。

# 二、现有代码的处理原则

## 2.1 暂时不替换原优化器

必须保留现有：

- `JointMilpOptimizer`
- `UtilityOptimizer`
- 原始离散路由网格生成逻辑
- 原始 Predictor Feedback 逻辑
- 原有求解结果和最优性证书语义

新算法在独立模块中开发，不修改现有默认求解流程。

可以复用经过验证的公共组件，但不得为了实现新算法而改变旧算法的输出含义。

只有当新算法经过完整实验，证明具有足够明确的优势后，才讨论正式替换。

## 2.2 两个原优化器的定位

### JointMilpOptimizer

定位为原始联合优化基线。

主要特点：

- 对路由比例生成离散候选。
- 每种任务选择一个路由候选列。
- 模型选择和副本数由同一个 MILP 决定。
- 使用完整预测器反馈真实效用。
- 在满足证书条件时，可以针对限定的有限域提供最优性证明。

### UtilityOptimizer

定位为原始 DFS 基线和小规模验证工具。

主要特点：

- 枚举有限部署状态。
- 固定部署后搜索离散路由。
- 使用完整性能预测器评价。
- 通过安全界限进行剪枝。

新算法不能依靠关闭原算法的约束或改变其评价方式取得虚假优势。

## 2.3 版本管理

建议在独立 Git 分支开发：

`feature/continuous-routing-optimizer`

不要求固定使用该分支名称，但需要保证：

- 原优化器可随时运行。
- 新旧算法可以在同一预测器环境下对比。
- 实验结果能够关联到具体代码提交。
- 原始实验配置能够恢复。

# 三、数学建模

## 3.1 模型部署变量

设模型集合为：

\[
\mathcal M=\{G_1,\ldots,G_p,S_1,\ldots,S_q\}
\]

对每个模型 \(m\)，有一组允许的副本状态：

\[
n_m\in\mathcal N_m
\]

这些状态必须来自当前系统支持的合法配置或有效画像。

部署方案表示为：

\[
D=(n_1,n_2,\ldots,n_{|\mathcal M|})
\]

对于副本状态选择，可以采用二进制变量：

\[
x_{m,k}\in\{0,1\}
\]

表示模型 \(m\) 是否采用副本状态 \(k\)。

约束：

\[
\sum_k x_{m,k}=1
\]

其中可以包含零副本状态。

显存满足：

\[
M(D)\le M_{\mathrm{budget}}
\]

模型选择和副本数由内层部署优化器负责。

## 3.2 连续路由变量

设任务集合为 \(\mathcal T\)。

每个任务 \(t\) 有合法模型集合 \(E(t)\)。

定义：

\[
r_{t,m}\in[0,1]
\]

表示任务 \(t\) 分配给模型 \(m\) 的比例。

满足：

\[
\boxed{
\sum_{m\in E(t)}r_{t,m}=1
}
\]

不能路由到不支持该任务的模型。

若任务到达率为 \(\lambda_t\)，则：

\[
\lambda_{t,m}=\lambda_t r_{t,m}
\]

在最常见的 G/S 二选一场景中，可以简化为一个变量：

\[
r_t=r_{t,S}
\]

\[
r_{t,G}=1-r_t
\]

但实现不得硬编码所有任务只有一个 Generalist 和一个 Specialist。

对于三个以上合法模型，可以采用 Simplex 参数化，并确保能够精确表示边界零值。

## 3.3 模型激活条件

这是本项目必须重点处理的问题。

定义模型接收的总流量：

\[
\boxed{
\Lambda_m(r)=
\sum_{t\in\mathcal T}\lambda_t r_{t,m}
}
\]

若：

\[
\Lambda_m(r)>0
\]

该模型必须部署至少一个合法副本。

若：

\[
\Lambda_m(r)=0
\]

该模型可以不部署。

激活判断必须基于模型接收的总正流量，而不是某一个任务的比例。

尤其要正确处理：

- G-only。
- 所有任务由 Specialist 覆盖时的 S-only。
- G+S 混合部署。
- 一个 Specialist 服务多个任务。
- 多个 Generalist。
- 多任务共享同一个模型。
- 某模型负载恰好为零。

不能通过把零强制修改成极小正数来回避激活边界。

如果实验需要最小使用流量阈值，必须将其作为显式近似假设，并说明它缩小了原问题的可行域。

## 3.4 GPU 共驻与 FIFO 预测

把预测器视为：

\[
\operatorname{Predict}(D,r,\lambda,\tau)
\]

其中：

- \(D\)：模型及副本配置。
- \(r\)：路由比例。
- \(\lambda\)：任务负载。
- \(\tau\)：请求轨迹。

预测器负责综合考虑：

- GPU 共驻执行干扰。
- 模型间资源竞争。
- 服务时间变化。
- 各模型 FIFO 等待时间。
- Mean 和 P95 延迟。
- 吞吐及吞吐损失。
- 质量。
- 显存。
- 有可靠证据支持的能耗。

真实预测必须针对整个共驻部署组合，不能简单把模型的独占执行时间相加。

## 3.5 优化目标

复用现有系统已经定义的效用函数。

Nominal 模式使用相应的 \(U\)。

Robust 模式保持现有 `scenario_U_low` 等策略语义。

不要擅自修改效用权重或归一化方式。

新算法的统一目标：

\[
\boxed{
V(r)=
\max_{D\in\mathcal D(r)}
\widehat U(D,r)
}
\]

外层：

\[
\boxed{
r^*=\arg\max_{r\in\mathcal R}V(r)
}
\]

内层：

\[
\boxed{
D^*(r)=\arg\max_{D\in\mathcal D(r)}
\widehat U(D,r)
}
\]

所有最终结果仍必须满足原有硬约束。

## 3.6 Cascadia 风格 Chebyshev 引导

本研究采用 Cascadia 式双层求解思想，但需区分：

- Chebyshev 或质量惩罚形式：用于定义外层评价目标。
- DE、BO、MADS：用于实际搜索连续路由。
- MILP：用于固定路由的离散部署优化。

它们不是同一种算法。

建议第一版直接优化：

\[
J(r)=-V(r)
\]

作为统一主目标，保证与原算法公平比较。

如果后续希望研究 Cascadia 风格的归一化质量缺口惩罚，可以增加：

\[
J_{\mathrm{penalty}}(r)
=
-V(r)
+
\mu\max
\left(
0,
\frac{Q_{\min}-Q(r)}{\Delta Q}
\right)
\]

作为可选搜索策略或消融。

但必须注意：

- 质量硬约束不能被惩罚函数替代。
- 已计入效用的质量损失不能无说明地重复计入。
- 内层若已过滤掉所有质量不可行部署，外层还需明确如何定义被拒绝路由的质量缺口。
- 最终方案必须单独验证所有硬约束。

不要求第一阶段强行加入额外 Chebyshev 惩罚。

# 四、算法总体架构

采用以下结构：

**外层：连续路由搜索**

DE → GP-BO / MADS → 按实验决定是否引入混合算法

↓

**内层：固定路由部署优化**

Fixed-Routing MILP 或 Fixed-Routing Enumeration

↓

**完整性能预测器**

GPU 共驻 + FIFO + P95 + 综合效用 + 约束检查

↓

**反馈与状态记录**

返回当前路由的部署、效用、可行性、求解界限和计算成本

↓

**外层更新路由**

继续探索，直到预算耗尽或满足停止条件。

## 4.1 两种内层求解器必须同时存在

### Fixed-Routing MILP

固定路由 \(r\)，只优化模型状态和副本数。

保留有效的 Predictor Feedback。

### Fixed-Routing Enumeration

固定路由 \(r\)，枚举有限合法部署组合，使用相同完整预测器计算效用。

用于：

- 小规模最优性参考。
- 验证 MILP 正确性。
- 比较内层算法成本。
- 判断 MILP 是否真的具有加速价值。

不能默认 MILP 一定比完整部署枚举更快。

## 4.2 内层 Predictor Feedback 的安全要求

MILP 的 Master 目标并不自动等于真实非线性效用。

已评估方案的身份反馈割，不能自动推广到其他部署或其他路由。

要求：

1. 只使用有数学依据的安全界限。
2. 未证明有效的共驻独立性假设不得用于剪枝。
3. 未证明跨路由有效的反馈割不得跨路由复用。
4. 预测器返回未知状态时，不得当成真实零成本或真实可行。
5. 只有完成符合证书条件的有限域求解，才能标记内层最优性已认证。

尤其需要统计：

**为了获得当前固定路由的最佳部署，实际调用了多少次完整预测器。**

这将直接决定 C 方案能否有效。

# 五、统一路由评价接口

所有外层算法必须使用同一个评价器。

建议：

`ContinuousRoutingEvaluator`

核心接口：

`evaluate(routing_vector, evaluation_budget=None)`

输出至少包括：

| 字段 | 含义 |
|---|---|
| `routing` | 当前连续路由 |
| `deployment` | 最佳有效部署 |
| `best_feasible_utility` | 当前最佳可行效用 |
| `valid_utility_upper_bound` | 可证明的效用上界；没有则标记未知 |
| `optimality_gap` | 有效间隙；无法计算则为空 |
| `feasible` | 是否找到有效方案 |
| `certified` | 是否完成当前有限域内层最优性证明 |
| `status` | 求解完成、超时、预算耗尽、证据不足等 |
| `milp_solve_calls` | MILP 调用次数 |
| `full_prediction_calls` | 完整预测调用次数 |
| `evaluation_seconds` | 本次评价时间 |
| `prediction` | 完整性能指标 |
| `constraint_violations` | 约束违反情况 |

## 5.1 内层未解完的处理

如果当前路由下，内层只找到一个可行部署：

\[
\underline V(r)\le V(r)
\]

那么返回的是当前最佳可行效用下界，不是准确的 \(V(r)\)。

如果有经过证明的上界，可以返回：

\[
\underline V(r)\le V(r)\le\overline V(r)
\]

否则必须记录上界未知。

不能把内层超时导致的效用偏低视为路由本身性能差。

BO 不能简单将这种单向低估当作普通零均值噪声。

第一阶段优先在能够准确完成内层求解的小规模部署域中验证外层行为。

后续扩大规模时，再研究内层预算分配。

## 5.2 缓存要求

缓存键需要覆盖：

- 路由向量。
- 工作负载。
- 请求轨迹及其摘要。
- 模型画像版本。
- 预测器模式及版本。
- 资源预算。
- 质量约束。
- 目标函数与策略。
- 会改变预测结果的其他配置。

不同路由不能仅凭比例接近就复用完整预测结果。

如果两种路由在固定轨迹下产生相同请求映射，也不能立即假定预测结果相同。

只有当预测器依赖的完整输入语义一致时，才能复用。

# 七、Phase 1：DE + 固定路由部署优化

## 7.1 目标

实现第一套完整可运行的 C 方案：

\[
\boxed{
\text{DE}
+
\text{Fixed-Routing MILP}
+
\text{Predictor Feedback}
}
\]

但必须同时提供固定路由枚举求解器。

第一阶段重点不是追求最强算法，而是验证：

- 双层结构正确。
- 连续路由真正被支持。
- 激活边界正确。
- 内层 MILP 有实际意义。
- 外层搜索评价可信。

## 7.2 固定路由 MILP

建议新增：

`FixedRoutingMilpOptimizer`

输入：

- 固定连续路由。
- 模型池。
- 合法副本状态。
- 显存预算。
- 任务质量约束。
- 预测器配置。
- 固定请求轨迹。
- 求解时间及预测调用预算。

输出：

- 最佳可行部署。
- 完整预测效用。
- 求解状态。
- 有效最优性界限。
- MILP 与预测器调用统计。

MILP 不再选择离散路由候选列。

模型及副本状态仍为离散变量。

允许按现有技术路线采用：

MILP Master → 完整预测 → 有效反馈割 → MILP Master。

任何新反馈割必须验证有效性。

## 7.3 固定路由枚举

新增：

`FixedRoutingEnumerationOptimizer`

枚举合法部署状态。

必须调用同一预测器和相同约束。

它不是最终主算法的预设替代品，而是内层的可靠参照。

至少比较：

- 内层求解结果。
- 求解时间。
- 完整预测调用次数。
- 被安全剪枝的部署数量。
- 最优性认证状态。

如果 MILP 在某些规模上与枚举一样昂贵，或者比枚举更慢，必须如实记录。

## 7.4 外层 DE

使用：

`scipy.optimize.differential_evolution`

连续路由直接表示为浮点比例。

不得重新引入固定的路由比例网格。

建议初始设置：

- `strategy="best1bin"`
- Sobol 或 Latin Hypercube 初始化
- `polish=False`
- 固定随机种子
- 统一评价预算
- 不超过任务合法路由维度的搜索空间

配置应允许替换以上参数。

每个外层候选：

1. 转换为合法路由。
2. 计算模型激活状态。
3. 执行必要的可行性预检查。
4. 调用固定路由内层求解器。
5. 获得完整效用及求解状态。
6. 更新最佳有效方案。
7. 记录该候选的真实计算成本。

## 7.5 Phase 1 必须显式处理激活边界

普通 DE/Sobol 采样几乎不会随机命中精确零点。

因此不能单纯依靠连续随机初始化。

必须包含：

- 全零 Specialist 分流。
- 全一 Specialist 分流。
- 每个任务的合法端点。
- 重要的低维边界。
- G-only。
- 任务覆盖允许时的 S-only。
- 合法的 G+S 混合方案。

对于小规模模型池，允许显式评价全部合法激活模式。

**这不是路由比例网格枚举。**

激活模式是离散的模型使用状态，而每个模式内部的非固定路由比例仍由连续算法搜索。

对于大模型池，可以使用启发式筛选，但必须记录搜索覆盖范围。

Phase 1 要解决激活边界的正确性，Phase 3 才研究如何更高效地搜索这些模式。

## 7.6 连续比例和真实 FIFO 路由的关系

当前系统采用确定性平滑加权轮询时，连续比例变化不一定改变实际请求分配。

因此必须明确：

- 优化的是请求流量比例。
- 预测器如何把该比例落实到具体请求。
- 同一比例和相同轨迹是否产生确定性结果。
- 相近比例是否产生相同请求映射。
- 请求映射改变时 FIFO 是否重新计算。

不能假设连续比例意味着目标函数连续或可导。

## 7.7 多轨迹评价

正式算法评价不能只依赖一条偶然的固定请求轨迹。

建议采用：

**优化轨迹集合**

多条冻结轨迹，共享固定种子。

**验证轨迹集合**

与优化轨迹独立的请求轨迹。

**最终测试轨迹集合**

用于报告最终方案的泛化表现。

所有外层算法使用相同的轨迹集合。

应在 Phase 0 确定效用聚合语义，例如：

\[
V_{\mathrm{train}}(r)
=
\max_D
\frac1N\sum_{j=1}^{N}U(D,r;\tau_j)
\]

这只是候选定义。若项目已有跨场景效用和 Robust 规则，应优先保持其既有数学语义。

特别注意：

\[
\frac1N\sum_j U_j
\]

不一定等于：

\[
U\left(\frac1N\sum_j\text{metrics}_j\right)
\]

必须保证新旧算法采用一致的定义。

## 7.8 Phase 1 核心测试

必须覆盖：

1. 单一模型执行全部任务。
2. G/S 双模型合法分流。
3. Specialist 比例为零。
4. Specialist 比例为一。
5. Generalist 完全不接收任务。
6. 多个任务共享一个 Specialist。
7. 多个 Generalist。
8. 无显存可行部署。
9. 某个路由导致所有部署不可行。
10. 预测器返回未知状态。
11. 内层超时。
12. 固定种子可复现。
13. 连续比例未被量化。
14. FIFO 路由映射正确。
15. 旧算法结果保持不变。

## 7.9 Phase 1 验收标准

必须回答：

**RQ1：固定路由 MILP 是否比部署枚举具有实际优势？**

**RQ2：DE 连续路由是否能在相同预算下找到比旧网格 MILP 更好的方案？**

**RQ3：激活边界是否会显著影响最优部署？**

**RQ4：固定轨迹中的阶梯状效用会不会妨碍连续搜索？**

**RQ5：新算法的主要开销来自外层搜索还是内层完整预测？**

完成阶段报告后才能进入 Phase 2。

若发现内层 MILP 在主要场景中始终不如枚举，不能为维持原计划而掩盖结果，应重新评估内层求解架构。

# 八、Phase 2：GP-BO 与多起点 MADS

## 8.1 目标

Phase 2 只改变外层连续路由搜索策略。

所有算法共享：

- 相同的固定路由内层求解器。
- 相同的预测器。
- 相同的轨迹。
- 相同的约束。
- 相同的评价预算定义。

不得通过为某一种算法使用更快或更宽松的内层评价来制造优势。

## 8.2 GP-BO

新增：

`GPRoutingOptimizer`

建议使用 BoTorch 与 GPyTorch。

基本流程：

1. 通过 Sobol 产生初始路由样本。
2. 调用内层得到真实评价。
3. 使用高斯过程拟合路由与效用关系。
4. 通过采集函数选择下一个连续路由。
5. 进行完整评价。
6. 更新代理模型。
7. 重复到预算耗尽。

可以先使用 Expected Improvement 或 Log Expected Improvement 一类采集函数。

需要处理：

- 部署切换导致的不光滑目标。
- 模型激活带来的跳变。
- FIFO 轨迹引起的平台期。
- 不可行候选。
- 内层求解未完成。
- 代理模型拟合失败。

对于内层未认证的效用下界，不得直接当作准确无偏观测。

初期在可精确完成内层搜索的小问题上训练和比较。

## 8.3 多起点 MADS

新增：

`MADSRoutingOptimizer`

建议优先使用 NOMAD / PyNomad。

不允许把自写的简单坐标搜索冒充完整 MADS。

基本流程：

1. 从多个初始路由出发。
2. 使用 MADS 进行局部无梯度搜索。
3. 调用相同内层评价器。
4. 保留各起点的最佳有效方案。
5. 比较整体结果。

起点可以来自：

- Sobol 初始候选。
- 合法激活边界。
- 已知可行方案。
- 历史优秀结果。

但是必须区分独立 MADS 与热启动 MADS。

若使用其他算法的历史数据，必须把相关评价成本计入公平比较。

## 8.4 Phase 2 对比算法

至少包含：

| 算法 | 外层 | 内层 |
|---|---|---|
| DE + MILP | 差分进化 | 固定路由 MILP |
| GP-BO + MILP | 高斯过程贝叶斯优化 | 固定路由 MILP |
| MADS + MILP | 多起点 MADS | 固定路由 MILP |

如果 Phase 1 证明枚举在某些规模更合适，可以增加：

DE / BO / MADS + 固定路由枚举。

但同一组外层算法对比必须保持内层方法一致。

## 8.5 公平评价预算

建议使用多个预算档位，例如：

- 100 次外层评价。
- 300 次外层评价。
- 500 次外层评价。

以上仅是实验建议，不是固定要求。

同时必须记录：

- 实际总运行时间。
- 实际完整预测调用次数。
- 实际 MILP 求解次数。
- 代理模型训练时间。
- 外层优化器自身时间。
- 内层超时和未认证比例。

**正式比较不能只看外层评价次数。**

一次外层评价可能需要 5 次完整预测，也可能需要 500 次。

总计算成本必须计入。

## 8.6 Phase 2 验收标准

回答：

1. BO 是否比 DE 更节省昂贵评价？
2. MADS 是否更适合阶梯状或不光滑的路由目标？
3. DE 是否在全局探索上更稳定？
4. 算法在不同路由维度下如何扩展？
5. 内层求解误差会不会影响外层排名？
6. 哪种算法在相同总成本下获得最高有效效用？

不能提前宣布 BO、MADS 或混合算法必然更优。

# 九、Phase 3：根据实验瓶颈开展结构性优化

Phase 3 不是必须把所有候选技术都实现一遍。

只有 Phase 1、Phase 2 证明某种瓶颈确实存在，才进行相应创新。

候选方向如下。

## 9.1 Activation-Aware Search

针对模型激活边界建立专门搜索策略。

基本形式：

\[
(A,r_A)
\]

其中 \(A\) 表示实际接收正流量的模型集合。

研究：

- 如何快速判断激活模式是否可能满足显存预算。
- 如何分配不同激活模式的搜索预算。
- 如何优先探索有希望的模型组合。
- 如何避免在不可行激活区域重复调用内层。
- 如何在不同激活模式之间共享安全信息。

这里不固定具体副本数。

副本数仍由内层 MILP 优化。

## 9.2 BO + MADS 混合优化

如果 Phase 2 证明 BO 更擅长探索、MADS 更擅长局部改进，则考虑：

1. BO 搜索高质量候选区域。
2. 选出多个具有多样性的可行候选。
3. MADS 分别进行局部精修。
4. 将真实完整评价反馈给历史记录。
5. 继续优化或停止。

必须与单独 BO、MADS 比较。

如果没有明显改进，不强行采用混合算法。

## 9.3 内层求解间隙感知预算分配

如果内层 MILP 经常超时，可研究：

- 哪些外层路由值得追加求解预算。
- 如何利用已知效用上下界判断候选是否仍有竞争力。
- 哪些候选可以安全停止。
- 如何避免外层因内层欠优化而错误放弃好路由。

重点研究：

\[
\underline V(r)\le V(r)\le\overline V(r)
\]

在有有效界限时，如何减少不必要的预测调用。

没有有效上界时不得伪造。

## 9.4 有效的跨路由搜索加速

可以研究：

- 经过证明的跨路由界限。
- 相邻路由的部署候选复用。
- 历史部署作为启发式热启动。
- 对有限轨迹中实际等价路由的缓存。
- 利用任务能力覆盖与显存约束安全排除部分激活模式。

必须区分：

**数学上安全的剪枝**与**可能漏掉最优解的启发式搜索**。

前者需要证明或验证其有效性。

后者必须明确最优性范围。

## 9.5 Phase 3 验收标准

必须有消融实验，判断新增结构是否真的有效。

例如：

- 基础 BO。
- 基础 MADS。
- BO + MADS。
- 激活感知 BO。
- 激活感知 BO + MADS。
- 加入预算分配或缓存后的版本。

只采用实验能够支持的改进。

# 十、对比实验设计

## 10.1 必须保留的基线

**Baseline A：原 Joint MILP**

使用原始有限有理数路由网格。

**Baseline B：原 DFS**

在小规模问题上进行有限域最优性验证。

**Baseline C：固定路由部署枚举**

检查内层 MILP 的实际价值。

**Baseline D：DE + Fixed-Routing MILP**

连续路由基础算法。

**Baseline E：GP-BO + Fixed-Routing MILP**

贝叶斯优化基线。

**Baseline F：Multi-start MADS + Fixed-Routing MILP**

直接搜索基线。

**Proposed：**

根据 Phase 1–2 的实验结果最终确定，而不是预先指定 BO + MADS。

## 10.2 负载场景

复用现有实验数据，至少覆盖：

- 低负载。
- 中负载。
- 高负载。
- ASR 热点。
- OCR 热点。
- 多任务混合负载。
- 突发负载。
- 不同任务组成比例。

必须使用相同到达轨迹进行配对比较。

## 10.3 模型配置

覆盖：

- G-only。
- G + 单 Specialist。
- G + 两个 Specialist。
- G + 多 Specialist。
- 合法多副本部署。
- 显存接近预算上限的场景。

不人为生成缺乏测量依据的副本状态。

## 10.4 主要评价指标

### 系统性能

- 综合效用 U。
- Mean 延迟。
- P95 延迟。
- 吞吐及吞吐损失。
- 质量。
- 显存占用。
- 有证据支持的能耗。
- 硬约束满足情况。

### 算法性能

- 总优化时间。
- 外层评价次数。
- MILP 求解次数。
- 完整预测器调用次数。
- 达到同一效用阈值所需时间。
- 达到同一效用阈值所需预测调用数。
- 内层求解间隙。
- 不可行评价比例。
- 不同种子的稳定性。

### 部署结构

- 最终选择的模型集合。
- 每个模型的副本数。
- 每种任务的路由比例。
- 模型激活模式。
- 路由变化导致的部署切换。
- 共驻干扰对部署选择的影响。

## 10.5 核心实验曲线

至少生成：

1. Best Utility vs Wall-clock Time。
2. Best Utility vs Full Predictor Calls。
3. Best Utility vs Outer Evaluations。
4. MILP vs Enumeration Cost。
5. 不同路由维度下的优化成本。
6. 不同负载下的模型选择与路由比例。
7. 不同随机种子的结果分布。
8. Phase 3 结构性改进消融。

应提供可复现的原始 CSV/JSON 结果和绘图脚本。

## 10.6 与旧网格算法比较时的注意事项

原 Joint MILP 可以在其有限路由域中证明最优。

新的 DE、BO、MADS 搜索的是连续参数空间，但不保证连续全局最优。

因此不能把：

**新算法效用高于某个有限网格最优值**

直接表述为：

**新算法求得了真实全局最优。**

实验应分别报告：

- 实际最佳可行效用。
- 搜索预算。
- 求解证书范围。
- 实际优化成本。

如果旧算法使用多个网格精度 K，应将不同 K 的成本和效用一并报告。

# 十三、正确性与可信性要求

## 13.1 不得伪造预测结果

不允许：

- 使用零服务时间代替未知预测。
- 使用未知显存作为零显存。
- 使用未经测量的能耗常数冒充真实数据。
- 忽略 GPU 共驻干扰。
- 关闭 FIFO 以提高结果。
- 为某个算法单独放宽约束。

## 13.2 不得伪造最优性

明确区分：

- 最佳已知可行解。
- 固定路由有限域已认证最优。
- 内层预算不足。
- 外层连续搜索未认证。
- 未知或不完整预测证据。

MILP Master 的内部最优解不自动证明完整非线性效用全局最优。

## 13.3 必须保证比较公平

- 使用相同预测器。
- 使用相同轨迹。
- 使用相同质量及资源约束。
- 使用相同效用定义。
- 在相同机器条件下计时。
- 记录完整计算成本。
- 进行多随机种子测试。

## 13.4 预测器误差与算法误差分开

虽然本次假设预测器足够准确，但优化算法仍有自己的误差来源：

- 外层搜索预算不足。
- 内层未求完。
- 启发式激活模式筛选。
- 有限请求轨迹造成的评价偏差。
- 非光滑目标引发局部停滞。

实验必须能区分这些来源。

# 十四、阶段推进条件

## Gate 0：接口与数学正确性

必须完成：

- 代码审计。
- 连续路由参数化。
- 模型激活逻辑。
- 预测器接口检查。
- 测试方案设计。

通过后进入 Phase 1。

## Gate 1：基础算法可行性

必须完成：

- Fixed-Routing MILP。
- Fixed-Routing Enumeration。
- DE 外层。
- 激活边界测试。
- 多轨迹评价。
- 小规模内层正确性验证。
- 内层成本比较。

重点判断：**连续双层算法是否值得继续研究？**

如果主要瓶颈在内层，应优先分析内层，而不是立即增加外层算法。

## Gate 2：连续搜索算法比较

必须完成：

- GP-BO。
- Multi-start MADS。
- 与 DE 的公平比较。
- 求解成本和稳定性分析。

重点判断：**哪种连续优化策略真正适合当前问题？**

## Gate 3：结构性算法创新

只有在观察到明确瓶颈时推进。

候选：

- 激活感知预算分配。
- BO + MADS。
- 有效跨路由界限。
- 内层求解间隙感知。
- 严格等价的评价缓存。

重点判断：**新增方法是否能带来可验证的效率收益？**

## Gate 4：是否替换原优化器

默认不替换。

只有新算法在代表性任务负载和相同预测条件下，证明具备以下优势，才考虑设为正式主算法：

- 求解效用明显更好，或在效用相近时成本明显更低。
- 约束正确性得到验证。
- 对不同负载具有足够稳定性。
- 计算成本在预期使用场景中可接受。
- 原有算法的回归测试全部通过。

即使通过 Gate 4，也应保留可运行的旧算法基线及复现实验配置。

5. 重新设计模型加载与卸载机制。
6. 修改现有综合效用的核心定义。
7. 立即替换现有 Joint MILP。
8. 在尚未验证 DE 的情况下直接实现完整混合算法。
9. 在未经实验支持的情况下宣称算法创新或性能提升。

本次优化得到的是给定负载场景下的部署及路由方案。

系统之后可以根据负载变化周期性重新优化，但**运行时自适应调度与逐请求动态路由不是本次算法研究的必要部分**。

如未来加入模型切换成本、加载延迟和在线调整机制，应单独建模，不能假定静态优化目标已经包含这些成本。

# 十八、最终研究定位

本研究不以“使用 DE、BO、MADS 或 MILP”为主要贡献。

真正可能形成论文贡献的是：

1. 针对 Generalist–Specialist 单 GPU 共驻场景，建立与连续路由相匹配的部署优化框架。
2. 利用模型激活状态与共享资源约束，减少无效搜索。
3. 在有效共驻干扰和 FIFO 评价下，提高联合部署—路由搜索效率。
4. 通过安全界限、反馈复用、预算分配或路由等价结构，减少昂贵完整预测调用。
5. 证明所提出方法在真实负载条件下，能够以更低优化成本找到更高质量的部署方案。

**最终目标：在不牺牲系统约束正确性的前提下，用更少的完整性能预测和更短的求解时间，找到更优或同等优质的 Generalist–Specialist 部署与连续路由方案。**
