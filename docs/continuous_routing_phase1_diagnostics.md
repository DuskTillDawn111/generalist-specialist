# Phase 1 性能诊断与合法域扩展报告

本轮结论：此前 70/76/42 次完整预测来自 `bounded` 有限域安全剪枝，**没有调用固定路由 MILP**。这组改进的非预测开销已超过旧 DFS 的全部运行时间；不能将其落后归因于 HiGHS。本轮改用现有真实数据校准回放模型后，当前 DE+MILP 的主要成本是重复完整预测与身份校验，HiGHS 仅约 0.3%；固定路由内层没有接入该模型已有的有效界，外层在较大域中尚未完成端点初始化。现阶段继续 Phase 1，不开发 GP-BO、MADS 或混合算法。

全部 `gsdeploy/**/*.py` 在主实验首尾 SHA256 相同。本轮只增加独立诊断入口、计时探针、报告工具与测试；没有改变主优化器、效用或硬约束。

## 2. 公平性、预算和计时口径

每个问题内，DFS、原 Joint MILP 和 DE+固定路由 MILP 使用相同模型池、同一完整预测函数、冻结画像、合法副本选项、六项等权效用、显存预算及 rho/排空约束。四任务到达率均为 0.0748360842705697/s，H=1800s，drain=300s，Poisson seed42，共 567 个请求；优化 seed 为 11/29，不改变请求轨迹。没有为新算法提供免费的历史赢家或预测缓存。

旧 DFS 指现有带安全界的正式实现，非 plain DFS。旧两算法搜索同一分母 1..K 网格并关闭附加容量见证；DE 搜索连续闭单纯形。因此联合问题的物理输入和评分一致，但离散/连续路由域不同，各自认证范围分别报告。

主比较是 7 个问题×3 算法×2 次运行=42 次；轮换执行次序，主计时不插探针。各算法配置 8 秒内部搜索预算，DE 另有 16 个路由评价上限；总 wall time 包含优化器/问题构造和收尾，排除共同导入、预加载原配置及落盘。原接口内部截止时间的起点不同，运行中的完整预测不可抢占，故预算运行可略超 8 秒；不把这些中止结果用于同证明工作量加速比。两轮只用于小范围诊断，不作显著性或稳定泛化声明。

另外独立运行 20 次计时诊断：两种规模的 DFS/Joint MILP/DE+MILP 共 6 次，以及 7 个固定路由的枚举/MILP 配对共 14 次。计时在内存中的原函数 AST 上只插入阶段标记，保留所有原表达式、约束与分支；退出时恢复方法。测试验证完整赢家和预测次数保持一致。诊断时间与未经插桩的主比较分列，不将插桩时间混入主中位数。

分项采用互斥归属：外层仅统计路由提议/DE 控制；建模包含列生成、数组/稀疏矩阵及 SciPy 参数处理；HiGHS 为 SciPy `_highs_wrapper` 后端调用；反馈包含 witness 检查、ledger 和约束反馈；完整预测为原 `predict_scenarios`，含其内部证据门禁及三个 stress；其余为构造、身份检查、摘要、缓存、复制等 Python 工作。所有分项和等于诊断总时间，额外列出其余中的身份校验子项，避免重复相加。

旧赢家路由的后补配对处于不同时间段，观测到更慢的单次预测，秒数仅用于该次内层配对，不与早先主比较推算加速。

当前固定路由 master 对这个校准模型只有全局成本下界零，`LegacyPredictorOracle.state_costs()` 和 `memory_states()` 均为空；而原 DFS/Joint MILP 已能通过 `surrogate_bounds` 取得该已验证预测器的界。因此，新 master 对几乎每个部署都需“求解→完整预测→身份 no-good”，然后额外求一次以证明剩余域耗尽。17 轮不是 17 次重复预测同一部署，而是 16 个不同部署与 1 次终止求解；它确实反复重建/求解 master，但后端累计成本很小。

能力审计还发现：上述 16 个部署中已有 1 个违反原有可证明的显存下界，现新内层仍完整预测了它。仅显存预筛选也不足以解决整个问题，还需要该模型已有的服务/质量/能耗成本界及有效排序。此处只统计现成合同，没有把新界加入任何优化器。

五模型完整 DE+MILP 的插桩记录为 23 次实际 MILP 调用、19 次完整预测；前四条路由分别求解 9/5/5/3 轮，第五条求解 1 轮后预算耗尽。HiGHS 每轮中位约 0.92ms，累计 23.6ms。即使这部分降到零，也不足以改变约 8 秒总时间与 1.4 秒 DFS 的比较。

## 6. 路由收益、实际 FIFO 分配与未提高原因

所有有赢家的主运行都保存模型、副本、连续比例、每个请求的时间/任务/worker、分配摘要与 trace SHA。平铺汇总见 `winner-routing-fifo.csv`，原始 JSON 的 `fifo.requests` 是逐请求分配明细。

五模型代表结果（同 seed42 请求轨迹）：

| 算法 | 部署，均单副本 | text / image / ocr / asr 路由比例 | text / image / ocr / asr 实际请求分配 | U |
| --- | --- | --- | --- | ---: |
| DFS | G2、image、ocr | G2:100% / image:100% / ocr:100% / G2:100% | G2#0:131 / image#0:145 / ocr#0:143 / G2#0:148 | −0.309302874 |
| 原 Joint MILP | G2、image、ocr | 与 DFS 逐项一致 | 与 DFS 逐请求一致 | −0.309302874 |
| DE+MILP，8 秒 incumbent | G2、ocr、asr | G2:100% / G2:100% / ocr:100% / asr:100% | G2#0:131 / G2#0:145 / ocr#0:143 / asr#0:148 | −0.389585035 |

原因需要分开判断：

- **搜索尚未到达好路由：** 五模型域有 16 个纯端点，8 秒只完整评价了前 4 个，`seeded_faces=0`；七模型有 256 个纯端点，预算在第一条路由内耗尽。这里“DE+MILP”的名称不代表实际已执行 DE 迭代，记录只说明预算尚不足以完成端点初始化。差效用/无 incumbent 不是连续路由不可能更好，也不是 GP-BO/MADS 的优劣证据。
- **旧网格是否已经足够：** 三模型以上，原 DFS/Joint MILP 的 K2 最优为纯路由，同 K4 五模型最优；旧冻结 K8 历史结果也为该方案。故当前已观察最优根本不需要更细网格表达。有限网格结论不升级为连续全局最优。
- **当前赢家附近是否有分流收益：** 固定赢家部署，分别将 image 或 ocr 从专用分给驻留 G2，扫描 0、1e-8、1e-6、1%、12.5%、25%、50%、75%、100%。18 次诊断均未找到更优 U：image 的 1%/12.5% 分流为 −0.310068/−0.326759；ocr 为 −0.316190/−0.372611，均低于 −0.309303。这个负例只覆盖该部署、单任务扰动及当前负载，不能排除多任务协同或其他部署的连续改进。
- **路由等价：** 1e-8/1e-6 扰动与原路由具有相同实际 FIFO 请求分配，却有不同 U，因为期望流量相关的资源项仍变动。较大扰动连分配也改变。不能将这些路由当作完整预测等价类缓存。

这也解释了早先合成实验的“同 U”：当已发现赢家就在旧网格端点上，增加连续点不会自动提高效用。本轮真实域还暴露了另一个更直接的问题：新内层过慢会使初始化阶段无法访问旧算法已经找到的好端点。

## 7. 下一阶段建议与可能优势范围

按本轮证据，优先级如下；本轮均未实施优化改动。

1. **先完成内层与已有预测器界合同的对齐。** 原 Joint MILP 能用同一模型的有效界只预测 1–2 次，新固定路由 master 还在逐部署预测。下一次受控改进应评估已有合法模型状态预筛选及服务/质量/资源界，继续以独立枚举验证；不把独占显存或当前合成 fixture 公式外推为真实共驻物理界。
2. **优先诊断并验证不可变输入/session 摘要缓存。** 重点是配置身份、证据摘要、重复深复制，复用仓库现有机制的思路；保留源/画像/轨迹失效检查。只缓存已证明同身份的数据，不按相同 FIFO 分配或相邻路由复用预测值。
3. **再讨论 master 更新成本。** 当前 no-good 造成大量求解轮次，但 HiGHS 不到 1%，不是这一批问题的主要瓶颈。若未来更大列域的剖析确实转为 HiGHS 主导，再评估持久模型/增量更新；本轮不提前开发。
4. **内层可承受后才比较外层方法。** 先让合法域内一条路由能高效完整求解，并使基线完成端点/边界覆盖；之后若同预算成本主要来自大量不同 V(r) 评价、且存在可重复的非网格收益，再进入 GP-BO/MADS 对照。当前不因外层控制耗时很小就忽视其评价次数，也不因它调用了很多评价就跳过内层瓶颈。

潜在优势的必要条件是：新方法在**同一合法预测器/问题**上确实减少了完整预测总数，同时节省足以抵消界计算、校验、建模和路由搜索开销。若每次完整预测的共同单位成本为 c、额外开销为 H，则在 N_DFS>N_new 时才有阈值 `c > (H_new−H_DFS)/(N_DFS−N_new)`。不能跨不同画像生成/验证执行路径套用同一个 c。

当前真实实验的 DE+MILP 预测次数比有界 DFS 更多，而且大域未完成一条内层路由；提高预测器成本本身不会使其自动获胜。已观察到的规模优势属于原 Joint MILP（3–7 模型、8–2187 个部署向量、2–12 路由维度）；当前新双层架构的优势规模尚未建立。它未来可能适合路由网格组合极多、连续最优明显偏离旧网格、且固定路由具有足够强界的场景；这是下一步需要验证的条件，不是本轮已有结果。
