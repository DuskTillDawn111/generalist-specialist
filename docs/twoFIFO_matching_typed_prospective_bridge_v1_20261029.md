# Typed matching law to fresh181 forecast bridge

`twoFIFO_matching_prospective_bridge_v1.py` is a CPU-only continuation from a
saved matching fit to a prefix-bound complete181 forecast hypothesis. The
frozen fresh181 CPU01 collector **still holds native execution before claim or
worker launch**. This module is not wired to remove that hold, seal a native
prediction, launch a GPU or rerefit. It is submitted for independent review
before a new collector/prefix version can consume it.

## Authenticated inputs and unchanged mathematics

The slow standalone producer/auditor calls `matching_phase12.audit_fit` and
`with_verified_bundle`. These authenticate the complete15 matching native
attempts, source reviews, macros and immutable saved fit. The exact rederived
intake must equal the saved fit's intake. The fit must belong to the matching
producer bound by the fresh plan. No optimizer is called. A numerically
unqualified root/fold remains12 allUNKNOWN worlds, with full probability one
and all181 public requests retained.

An eligible saved root constructs `matching_joint_law.build_joint_law` with
`heldout_block_id=None`. This retains all three whole blocks and390 measured
request vectors. All16 routed `(owner,task,exact pool input)` keys required
across the original four candidates must have a vector in **every** block.
Missing one of48 support checks makes the entire prospective hypothesis
UNKNOWN; partial donor coverage is not silently renormalized.

The bridge compares whole context bytes, worker specification, command,
environment, checkpoint, thread/device/protocol binding, all15 donor plans'
five physical runtime knobs, policy, residents and ordered18 priming input
semantics with the fresh plan and actual prefix. Target source binding must
contain every matching source. Fresh collector/model source additions and
changed offered rates/routes/windows are explicit. The old physical identity
hash, which includes producer-specific source/priming metadata, is not reused
as if two different producers had identical documents.

The original `generated.compile_case_draws` chooses complete joint vectors by
public key/ordinal, predefined slot and common whole-block latent. All three
blocks retain four slots each at exact weight1/12. The original prospective
adapter's `ensemble.evaluate` then runs the original queue/world and six-term
arithmetic over all181 future arrivals and fixed90+120 boundaries. Q actual
quality, M/E horizon resources and fullU remain UNKNOWN. No quality or resource
labels are inferred and no original stability gate is claimed.

The original prospective wrapper mandates renamed request IDs. Fresh181 uses
the earlier reviewed identity scope `(execution_id, original_request_id)`, so
the bridge calls the **same original compiler and ensemble evaluator** directly
with the actual prefix's181 calendar. It does not relabel source documents or
change the frozen wrapper's contract.

## Owned producer lifetimes and evidence

The original compiler emits symbolic `owner:modeled_stdout_lifetime` labels.
The fresh prefix binds actual stdout lifetimes by execution/owner/PID.
`bind_owned_producers` substitutes only each plan's READY and marks' producer
labels and the corresponding protocol-slack plan key. Work coordinates,
phase marks, protocol slacks, paired transport sets, rates and probabilities
remain unchanged. The actual prefix's sender availability, worker read release,
reader stations, collector stations, issuance/sequence and prior counts enter
the original engine. CPU tests check both those initial history fields and
the exact final per-owner issuance counts.

The typed output binds saved fit, exact execution/plan/candidate, real prefix,
snapshot hash, complete public calendar, boundaries, selection hashes and
every world/query/forecast hash. It retains all12 probabilities and full181
completion projections, queue diagnostics and original six-term score outputs.
Rational completion projection uses the original scorer's upward rounding.
Standalone `audit_report` reauthenticates the15-source intake and deterministically
replays the entire output, so editing caller qualification flags cannot release
a native gate. Source change/restore watchers cover fit, gate, all plans and
training/source references through production and audit.

This is a source-supported **predeclared hypothesis**. Its explicit assumptions
include template and rate stationarity under the changed181 schedule, notice
slack/producer transfer, conditional request draws given a whole block and
paired transport feasibility. These assumptions are not proved by shared
source identity. Independent accuracy is what later validation measures; it
is not falsely presented as a prerequisite for stating a sourced hypothesis.
Actual worker stdout is not independently reparsed by this bridge. The source
of the prefix remains the reviewed owned runtime collector, with the narrow
post-run supervisor/prefix review documented separately.

## Timing and live interface

The standalone slow path is unsuitable as an assumed60-second live budget:
exact15 native source review and full181×12 propagation have not been benchmarked
with the real saved fit. Even two synthetic full-world replays need a measured
budget. The current module never assumes default60 seconds is enough.

`open_law_session` performs saved-fit audit, verified15 intake and full joint-law
construction **before worker startup/prefix publication**. It holds a source
change watcher for its whole context lifetime and caches a full canonical-content
seal of the law/plans/fit. `produce_from_session` and `audit_from_session` each
replay all numerical worlds against the actual prefix but reuse that active
source-authenticated law. Inactive/expired sessions, changed cache content and
changed/restored sources fail. The session is not a serializable caller
qualification. The standalone auditor remains available for independent full
reauthentication. No reduced validation or sampled-world fast path is used.

Before a native collector version can be enabled, the real eligible saved law
must be benchmarked for prefix audit, compiler, full propagation, typed audit,
hashing and persistence. A source-bound predeclared lead budget must cover both
live producer/auditor passes plus persistence and explicit margin. Unknown or
insufficient budget keeps native HOLD; crossing the actual origin keeps the
existing zero-target-send behavior. CPU author timing reports label synthetic
and mocked-authentication timing separately from unmeasured real native timing.
