# New-schema phase12 fit and joint request law

`twoFIFO_phase12_fit_v1.load_complete` audits the frozen campaign and new native
reviews. Missing/ineligible reviews return WAITING without extracting response
documents or fitting partial data. Complete intake requires all twelve attempts,
546 measured requests, eighteen history-only priming requests per attempt and
three whole four-shard training blocks. No validation data is read.

`fit_new_blocks(documents, plans)` uses the existing twelve-coefficient
`own_family_phase_count_global_same` design and new-schema row adapter. It calls
the unchanged analytic `numeric.fit` for the full design and each whole-block
leaveout. Trust minimizations, gradient roots, score, curvature, joint rank and
nuisance-adjusted rank remain the original numerical outputs. No column is
removed and no candidate is selected. Heldout unseen nuisance groups remain
UNKNOWN in the complete denominator. Conditional NLL averages the three heldout
block means equally. A complete numerical root, observed OCR entry support and
prospective queue accuracy are separate gates.

`twoFIFO_joint_request_law_v2.build_joint_law_v2(documents, plans, raws, fit)`
requires the complete matching denominator, qualified full root and all three
qualified whole-block folds with supported heldout nuisance groups. Its CLI
rederives the fit from the same exact native document closure before compilation.
The CLI does not accept the old fit schema or an old baseline merely to obtain
notice slacks.

For generated whole-block evaluation, `heldout_block_id` selects the already
fitted corresponding fold and excludes all four heldout shards from donor
compilation. The complete twelve-attempt authentication gate still applies.
Only the two training blocks receive donor weight, one half each. The full law
uses all three blocks with one-third weight. Heldout vectors never enter a
fold law, and no heldout refit or partial-campaign fit occurs.

Each attempt's original priming and measured START/PHASE/RESULT/READY messages
enter one `protocol_timing_slack_v3.derive` recurrence. Counts are computed from
the original records rather than a fixed message constant. Producers persist
per owner for the whole attempt. Every measured request then keeps all entry,
forward, OCR and READY-tail nodes, query outcomes, protocol marks and paired
notice slacks in one vector. Phase12 rates map occurrence-origin response and
mark locations to rational reference work. Absolute donor START/peer trajectories
are not generation inputs. Slack reconstruction does not identify CPU service,
and startup/control/other unobserved collector work remains a limitation.

`choose_vector` selects one of the three training blocks with equal weight,
then a complete vector under the public owner/task/exact-input key. The draw
slot explicitly carries arrival ordinal within that key. Historical request,
case, attempt and raw IDs remain provenance. A common block latent across inputs
preserves only block-level dependence; conditional independent request draws
within that block do not preserve all cross-request correlation.

`compile_draw_v2(vector, public_key_ordinal, transport_support)` returns UNKNOWN
unless all five transport fields are supplied as an explicit feasible latent
scenario paired with that vector and public ordinal. It checks the observed
paired sender terms and the source START feasibility equation. Neither an idle
donor nor total submit-to-START fills the unidentified line-availability and
worker-continuation components. Scenario probabilities and transport transfer
under changed schedules remain unqualified.

The immutable generated plan has structural dispatch delay zero because the
explicit transport draw owns the submit-to-START boundary. Reader/collector
timing is supplied through the separate complete protocol-slack mapping. These
interfaces do not themselves restore nonempty runtime state or predict missing
startup/priming templates; the generated two-FIFO simulator remains a separate
versioned gate. No physical SM/DRAM demand, generated queue accuracy, independent
validation or final utility gain is qualified here.
