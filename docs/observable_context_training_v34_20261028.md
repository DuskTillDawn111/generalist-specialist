# Whole57 native context training and queue recovery continuation

The execution order remains training captures, frozen independent prediction
validation, mechanism ablations, then the matched four-group routing study.
The original six equal weights, stability rules, 57-request offered cohorts,
arrival windows, four resident owners and 120-second drain remain intact.
No global cap of one or two requests is introduced.

## What the new context candidate actually fits

`whole57_observable_context_v34` reads four separately collected light captures
for balanced, skewed, spill_low and spill_high routes. A four-capture manifest
must bind exact completed adapter reports. Each capture must retain its original
57 measurement and 12 priming requests. Every next-owner label is checked against
the original qualified native adjacency ledger; every paired SAVE endpoint is
checked against the complete physical ledger, including SAVE events without a
next-owner label. Paired exposure and unknown context gaps must exactly partition
the original native observation window. Repeated/unpaired context events remain
explicitly unresolved and cannot become zero-event or fabricated-age training
rows. Driver contexts remain distinct from process owners.

Two statistical candidates are trained. The physical next-owner mark is fixed
capture-balanced multinomial logistic regression with held owner, previous
holder and log attained age. The physical SAVE endpoint uses fixed age bins and
holder features with the original exposure/event-normalized Poisson objective.
All four resident mark classes are retained; absent classes and unsupported
state ages are reported. These are native context-envelope models, not SM
service, DRAM throughput, cache behavior or proof of physical resource isolation.

Native NVTX GS_STAGE presence and engine handler activity are **different
observation variables**. Earlier v31/v36 metadata described a shared true/unknown
projection, but matching output types does not establish equal semantics or
missingness. The v34 candidate deliberately excludes handler/phase status from
its fitted features. Those observations remain available for stratified
diagnosis. A future stage-aware candidate needs a demonstrated common phase
observation contract before fitting those features.

Parameters are fixed before four-route fitting. Evaluation leaves out one whole
raw capture, never individual correlated transitions or request windows. Inputs
and recipes are shared, so this is explicitly a known-family training diagnostic,
not independent content/recipe validation or calibrated accuracy. A final model
is fitted only after all four actual light captures qualify.

## Actual forecast connection and limits

`observable_context_bridge_v38` connects those physical candidates to the original
cumulative SAVE budget and v27 review-propagation scheduler. It retains a separate,
explicitly unvalidated conditional reference-service bridge over engine-visible
owned work. Unfiltered physical probabilities remain in every mark receipt.
Same-holder probabilities are not removed to force a switch. The original
same-holder reacquisition rejection remains, as do no-rewind/no-missed-SAVE
checks and one budget per restoration. No handler field enters the physical
candidate, although engine-owned-work eligibility remains a separate service
hypothesis.

`observable_context_forecast_v38` reuses original DAG work, host release, phase,
initial/handoff, lifecycle/resource/startup providers and six-term scoring.
`observable_context_preflight_v38` runs all four original public cohorts on CPU
and stores each full result as roundtrip-verified gzip JSON. It produces unsealed
cells only. UNKNOWN is retained as a failed prediction outcome; no automatic
permission to collect independent validation follows from a completed process.

The earlier physical endpoint work established counterexamples to deterministic
binary owner gating. v38 still uses that original reference-progress
approximation and therefore does not resolve the physical endpoint modeling
gap merely by improving context transitions. Independent service/queue/P95,
Delta-U sign and candidate-rank gates remain necessary.

## Whole-horizon queue work

The actual forecast includes all declared future arrivals, FIFO waiting and
eventwise remaining DAG reference work through the original drain. The v19 queue
sidecar records current waiting/age/recovery episodes separately from future
offered-work diagnostics. Neither simulated peaks nor an internal forecast state
are treated as actual parent-reader observations.

The separate v31 horizon-recovery candidate uses actual receipt-visible prefixes
and public future arrivals. For positive current backlog, the target is whether
backlog fails to clear within 1, 5 or 10 seconds. Complete observation through H
identifies a positive binary target even when exact clearance time remains
right-censored. Observed clearance within H identifies zero; observation ending
before H without clearance is UNKNOWN. Input size remains an original-unit
covariate, not invented resource work or milliseconds. Four natural captures
must qualify an explicit execution-domain bridge before fitting. Whole-capture
holdout remains known-family training evidence.

The v32 observed-risk sidecar predicts from real reader prefixes with frozen
model/domain/source identities before a separate label-side evaluation. It does
not change rho or add a seventh score term. Host observer state is not a
resumable GPU DAG checkpoint, and this work is not described as completed rolling
forecast correction.
