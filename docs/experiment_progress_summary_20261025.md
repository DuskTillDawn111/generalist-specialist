# 截至2026-10-25的实验成果与证据边界

本总结只读核对既有阶段报告、正式确认JSON、逐请求CSV和CPU交付收据；没有重跑GPU、重拟合或重评分旧实验。日期按北京时间。各轮使用自己的冻结目标，五项与六项U不能横向直接比较。

## 1. 现有基础：模型、任务与评价

冻结七模型池为三个通用模型 Baichuan-Omni-1d5、MiniCPM-o-4_5-GPTQ、Qwen2.5-Omni-7B，以及四个专用模型 Llama3-ChatQA-1.5-8B、SigLIP2、PP-OCRv6、Granite Speech。任务为文本QA、图像分类、OCR、ASR。

保留模型多副本资源画像完成16个模型—任务组合，61个完成档位、三轮测量、15712个正式请求；真实OOM和安全预算边界失败均保留。它证明有限同卡、独立进程、batch=1闭环画像已建立，不等于所有混合部署或开环到达率的稳定容量证明。

按用户最新要求，后续目标恢复为六项等权：`U=-(Q+T+L+P+M+E)/6`。Q为质量损失，T为窗内完成损失，L/P为任务流量加权的平均/P95端到端归一化延迟，M为显存，E为板卡能耗及启动摊销。质量无绝对门槛，原稳定性保持。新契约不追溯改变旧五项实验。

## 2. 第一阶段：静态负载部署优化已完成一次完整闭环

负载：四任务各0.0748360843 rps，Poisson；H1800，开发seed42，独立确认43/44/45；显存预算49140MiB；六项等权。

混合校准先测8条，第一版预测器留出U误差0.284082/0.139401且排序反转，未采用。启用独立封存的逐输入回放v2，再用2条新留出测得误差0.009697/0.004604，通过其预声明验证。

七模型、冻结副本状态、分母1..8的离散路由域中，算法选择：**MiniCPM-o×1＋图像专用×1＋OCR专用×1**。QA和ASR全部给MiniCPM，图像/OCR全部给对应专用。预测U=-0.309303，具有该冻结预测有限域的最优证书；选中方案本身不分流。

竞争者包括重新优化的其他部署、同部署其他路由、不分流、纯专和纯通结构控制，不只比较两个纯部署端点。去重后5个物理方案、每个3种子，共15条GPU正式确认全部完成。

|---|---|---:|
|自由搜索方案|G2＋图像专用＋OCR专用；QA/ASR→G2|-0.312130|
|最强其他部署|自由方案基础上OCR改为2副本|-0.319643|

## 4. 第二阶段：高文本负载、多副本与自主分流

主负载text1.85 rps，image/OCR/ASR各0.01；部分开发测text1.89。H600，warmup30，drain上限300。主部署为ChatQA×2＋G2×1＋OCR×1，图像/ASR→G2，OCR→OCR。文本比较静态比例、仅专用队列均衡与自主分流。

算法已真实实现“专用多副本积压、G2队列为空时自主分流”，通过因果回放检查；这不等于G2独占GPU空闲，也不等于收益已证实。

收益统一定义为**同策略同驻留允许分流U减禁止分流U**。不同冻结批次不拼接为一个总体统计量。

|阶段|已完成证据|关键结果|
|---|---|---|
|细比例开发107/108|四方案×两seed，8条|1/32分流平均看似更好，但两个seed方向反转|
|固定1/32再验证109–112|4完整配对，8条|ΔU四次均负，均值-0.059118；主要损失P95|
|第一版队列感知|14开发＋4验证＋6确认，24条|仅专用文本均衡优于动态分流；5个独立配对，分流ΔU均负，均值-0.064529|
|重新校准路由|实际29条：4校准＋25正式|开发1.85平均ΔU+0.002421；独立205–208为1正3负；209缺合法能耗，末控制未执行|
|共享GPU耦合六项策略303/304|四候选×两seed，8条|新策略ΔU=-0.030327/-0.037269；分流18/31次；开发门禁失败，未做确认|
|去P95五项策略401/402|四角色×两seed，8条|新策略ΔU=-0.006940/-0.011202；原延迟策略也两次负；未做确认|

校准版独立205–208的ΔU分别约-0.007244、+0.001692、-0.012232、-25.146501；严重拥堵208符合原可恢复拥塞规则，保留在评价中。209功率采样间隔超过原上限，E/U未知，按协议停止，不补数据、不把29条写成30条完成。

六项303/304中，增加图像专用的另一混合部署平均U=-1.018114，优于同批其他候选；但它同时改变驻留、背景路由和策略，且缺自身禁止分流臂，因此不能把优势归因于分流。

总体结论：**已经证实算法能自主分流，尚未证实稳定正分流总效用。**

## 6. 机制诊断：分流确有排队收益，但服务代价更大

401/402逐分流输入匹配结果如下。数据来自逐请求CSV的算术平均；服务、worker queue与完整E2E计时边界不同，分项不强行等同相加。

|被分流请求的配对变化|401|402|
|---|---:|---:|
|worker排队减少|495.471ms|422.679ms|
|自身服务增加|1101.469ms|1206.978ms|
|端到端延迟增加|603.104ms|784.451ms|
|独占活动参照G2−专用服务|−192.455ms|−252.854ms|

即：通用在这些输入的独占参照下并不天然更慢，但实际共跑中局部排队收益被服务代价抵消。受控同工作量下G2与一/两份专用共跑的handler时长约为独占参照1.994/2.659倍。相同4007输入、5输出token的G2请求曾出现657ms与3978ms，执行环境差异值得进一步定位。

已有活动时间线与预测失配证据，但尚未采集能确定归因的GPU kernel时序、SM/L2/DRAM计数器。handler内还含准备、同步、回收等；不能把残差全部称GPU竞争成本。仅增加未来到达模拟也不足以修复已暴露的状态粒度问题。

来源：`docs/gpu_contention_forensics_results_20261023.md`、`artifacts/queue-five-term-study-20261023/gpu-contention-forensics-v1/spill-requests.csv`。
