# Fresh181 CPU collector, prefix and prediction barrier

This work prepares the original four public candidates with a matching owned
worker backend. It does not launch a GPU, fit a model or qualify a prediction.
The current native entry points **HOLD before a claim or worker launch** because
the typed matching-law → actual-prefix → prospective-forecast replay bridge is
still missing. A nonempty file receipt, caller qualification Boolean, numeric
completion or `GENERATED_WORLD` string cannot release this hold. Completing
that bridge requires reviewed source changes and a new preparation.

Implementation: `twoFIFO_fresh181_execute_v1.py` and
`twoFIFO_fresh181_prefix_v1.py`, under `tools/predictor_validation_20261027/`.
Frozen matching producers and all earlier collection/review artifacts remain
unchanged.

## Preserved experiment contract

Preparation strictly rebuilds the public preparation and matching producer.
There are four fresh execution IDs, each with the same original181 public IDs,
arrivals, exact inputs and candidate routes. Request IDs are scoped by execution
ID. The original candidate rates, resident roster, worker specifications,
runtime policy, physical runtime configuration and ordered18 prior priming
inputs are retained. Fresh context bytes are identical to matching context
bytes; new provenance is in the plan, not inserted into worker context.

Each measurement remains90 seconds followed by a fixed120-second drain. Waiting
for prior READY and forecasting occurs outside measurement. All181 offered
requests are registered before startup and dispatched independently through
the original runtime enqueue/FIFO interface. This adds no cap of one or two
active requests. Missing or incomplete target results retain their offered
denominators and original cutoff. A successful observation window can contain
incomplete requests; `all_requests_completed` is a separate field.

The immutable objective and public contract bind equal Q/T/L/P/M/E weights and
original stability policy. No actual six-term utility or gain is fabricated.
Training10+60 does not qualify90+120 resource exposure: M/E/fullU support remains
UNKNOWN, and measured native quality/resource review remains separate.

## Causal interface and order

The collector reuses the matching supervisor, exclusive no-retry claim and
lease, owned monitoring, reviewed cleanup and explicit source-change watchers.
Preparation freezes its own transitive source closure. Audit deterministically
rebuilds every plan and the manifest; changing/resealing a route, window,
priming semantic, physical knob, source or eligibility field fails audit.

The CPU executable path demonstrates this order:

1. Run the original18 ordered prior priming requests. RESULT completion is not
   enough: a bounded pre-measurement loop requires all handler READY messages
   to be processed, with an empty queued-event list and no runtime errors.
2. Take an actual locked runtime snapshot containing only those18 records.
   Require all four actual READY PIDs/spec hashes, owned ancestry, exact input
   semantics, sender clocks and every START/RESULT/READY clock at or before the
   snapshot. A busy or unproved history becomes UNKNOWN; it is never coerced
   to a settled seed.
3. Persist and fsync the snapshot/seed prefix and its parent directory. The
   seed rederives from that prefix alone; final target records cannot fill in
   missing clocks or READY messages. Relative tracked-message counters remain
   explicitly conditional, not fabricated native stdout sequence numbers.
4. Persist the public gate. It binds actual prefix, execution/plan/manifest,
   all181 absolute arrivals and routes, fixed measurement/drain boundaries,
   immutable objective, and predeclared model/generator receipts. It contains
   no target raw path or future response label input.
5. A producer writes a forecast and calls `seal_prediction`. The current
   generic format is an unqualified CPU hypothesis interface. Every world has
   the exact181 IDs; positive exact rational weights sum to one, including
   UNKNOWN mass. Each request record permits only its ID and completion, so
   extra owner/task/input/arrival claims are rejected. Numeric worlds require
   declared sources and at least one numeric completion, but that is **not**
   authentication of a native fitted law.
6. The collector verifies the full reconstructed gate, prefix and seal and
   finishes its durable acceptance checkpoint strictly before the first
   target arrival. Missing seal, late persistence/authentication or late
   checkpoint stops before any target enqueue. It watches all sealed inputs
   through fixed drain, without full-copy checkpoints during the window.

An allUNKNOWN forecast is useful only for CPU tests of the barrier, complete
probability mass and all offered denominators. It supplies no timing/ranking
accuracy evidence. The missing typed native transfer bridge must additionally
authenticate the reviewed matching fit/law, replay complete worlds through the
original prospective forecast interface, and bind query/candidate/actual prefix.
No native campaign is scheduled by this module, even if caller-supplied files
appear to satisfy the generic CPU hypothesis schema.

## Auditor scope

`audit_completed_prefix` is a deliberately narrow post-execution source/order
auditor. It checks the fresh canonical plan, exclusive claim, completed owned
supervisor receipt, clean/reaped process group and source audit; checks actual
READY ancestry against that collector; and rederives prefix, full gate and
declared pre-origin seal without reading target raw labels. It does not
independently reparse worker stdout or reconstruct collector acceptance time
from target raw. Its result explicitly records those limitations and never
sets native protocol, accuracy, resource or fullU qualification. No successful
native instance of this auditor is claimed by the CPU preparation.

## CPU verification

`tests/test_twoFIFO_fresh181_execute_v1.py` uses the real preparation/audit and
real collector control flow with injected CPU transport, clock, monitor and
ownership. Prior history contains full ordered protocol clocks and READY
specification/PID binding. Tests exercise complete199-send control flow,
all181 independent target enqueues, fixed90+120 cutoffs, cleanup monitoring
while workers are live, retained incomplete requests, missing/late forecasts,
READY/spec failures, resealed plan/gate/seed mutations, source change/restore,
full probability mass, closed forecast projections and hard native hold before
any environment check, claim or runtime construction. CPU fixtures are marked
CPU_TEST_ONLY and cannot authenticate as native sources.

Prepared plans intentionally contain no observed prefix, no seal, no fit and
no claim/collection directory. The pending next implementation is the typed
review-bound forecast bridge, after matching native evidence and its law are
available and independently reviewed.
