# v3 已接入实际搜索：有限比较与最终选型

2026-11-05。本阶段已完成，范围内的推荐仍为**纯专用路由、五模型全部驻留且各一副本**。新搜索入口默认采用四组 v3，预测器和数值参考保持冻结。六次 CPU 搜索全部完成，未启动 GPU、重训或新增实测确认。

这一步补齐了[上一阶段](utility_tradeoffs_v3_20261105.md)仅实现离线评分的限制：v3 现在实际控制候选排序、搜索反馈、目标边界和最终选择。

## 结果

每种方法使用原种子 11/29/47，同一对开发到达历史。每次上限 300 秒、64 次完整预测、32 个外层路由评估和 128 次 master 调用。六次均因 32 个路由评估上限结束，实际每次约 47 秒，没有追加预算。

|方法|三个种子所选路由|开发预测 v3 U|完整预测调用数|实际耗时，秒|
|---|---|---:|---|---|
|Activation-BO-MADS|四任务均走专用|**−0.5179219273**|44 / 44 / 46|46.77 / 47.35 / 47.71|
|Joint-K2|text 走 G2，其余走专用|−0.5835806104|64 / 64 / 64|47.72 / 46.70 / 46.78|

BO–MADS 在该预算内的预测效用高 **0.0656586830**，完整预测调用更少；实际运行时间接近，没有明显时间收益证据。Joint 的三次重复在这里是同一确定性 K2 搜索，不应当作三个独立随机重复来论证统计显著性。

Joint 的 32 个已访问候选中均没有纯专用路由，因而这是有限预算内搜索顺序的差异。不能声称 BO 找到了连续全局最优，也不能把这次差距推广成算法普遍优势。此前 v2 两种算法都选纯专用，与本次不同；改目标确实改变了搜索过程。

**最终采用 BO 找到的纯专用方案。** 它与已有实测候选 candidate-1 的路由形式、固定驻留和副本数一致；既有两轮实测按 v3 重评的平均 U 为 −0.5143083111。搜索使用开发历史，实测记录使用原确认历史，两者不是同一批到达，不能直接相减当预测误差。v3 是看过这些数据后设计的，复用证据仍属于回顾性分析。

Joint 新选的 text→G2 混合候选没有匹配的独立完整实测，但其预测目标已经更差，因此不触发追加 GPU 确认。算法各自候选的证据覆盖与最终胜者的证据覆盖分别报告：并非六个方法胜者都有实测，但最终选择有既有实测支持。

## 接线与边界

入口：[search_scoped_utility_v3.py](../experiments/search_scoped_utility_v3.py)。它在内存副本中设置 Q/M/E=1/4、T/L/P=1/12，调用冻结的预测与原优化算法。每次预测用独立 v3 评分器核对全部贡献和 U；目标标识、oracle 标识和缓存标识都包含新目标版本。完整性缺失仍返回未知，不补零。

归一化契约继续使用原 v2 数值来源，效用契约明确标为 `gsdeploy.utility_tradeoffs.v3`。目前只支持已复核的默认值：deadline 为参考均值 2 倍，连续延迟尺度为原冻结 deadline，质量/能耗尺度因子均为 1。其他 SLO/尺度敏感性仍是离线诊断，不会悄悄进入这个搜索入口。

成本下界按新权重重新计算：

```text
cost = -U >= w_Q * Σ alpha_t * (0-best_t)/(worst_t-best_t)
```

原因是原生质量损失非负，T/L/P/M/E 非负；归一化 Q 可以为负，不能错误地用 0 作总成本下界。本次实际下界为 −0.1824708601。Joint 的列下界、连续内层的全局界都使用相同新权重；独立服务/显存下界仍禁用，完整候选反馈使用本次 v3 成本。没有复用旧目标的 cut、GP 或缓存。

原脚本与原 v2 结果作为历史入口保留。**本轮后续同范围的 v3 搜索应使用新入口**，不能把旧 CLI 的 v2 结果当作 v3。没有在全项目范围替换所有历史配置。
