# BO–MADS 全局预测预算退出修复

已修复全局预测预算耗尽后仍继续外层调度的问题。修复不增加搜索预算、不重训预测器、不改变效用公式或候选生成参数。

## 为什么会耗尽，其他算法是否一样

前一批跨领域比较为每种方法设置相同的 64 次完整预测上限，包含初始化。四种方法、两个规模、三个种子的 **24 次运行全部使用了 64 次预测**。这是有限预算黑盒搜索的正常停止条件，既不表示预测器失败，也不表示连续全局最优已经求出。

7/14 模型池的共同初始化分别用了 18/32 次预测，留给后续搜索的次数是 46/32。这里一次预测指评价一个部署与分流候选的成本，不是训练一步，也不是评价一个请求的次数。该批使用合成 oracle，没有调用真实 GPU 预测器。

其他三种方法在预测预算耗尽后退出。BO–MADS 的内层原本需要捕获 `BudgetExhausted` 并保存部分结果，供下一次按需精化使用；但内层局部配额与全局上限都可能产生 `PREDICTIONS_LIMIT`。外层只检查时间和外层次数，没有重新核对全局预测计数，因而继续调用无法取得新预测的搜索，直到 256 次外层保护上限。

## 修复方式

修改 `gsdeploy/continuous/activation_bilevel.py`，由基础控制器和 balanced 子类共同使用：

- 在进入搜索、开始新路由评价，以及下一轮选点前，检查全局预测预算。
- 检查放在渐进内层已恢复临时配额的外部，因此内层一小段配额用完仍可以让出调度权；只有全局上限达到时才结束整个搜索。
- 已完成的内层结果、上下界和最好可行方案先保留；不丢弃最后一次预测得到的更好方案，也不把未完成结果改为认证结果。
- 精确内层模式下，全局耗尽返回明确的 `PREDICTIONS_LIMIT`，避免被泛化为 `INNER_EVALUATION_INCOMPLETE`。

balanced 对已认证、已缓存的相同路由仍可直接读取已有结果；新的求解不能继续计费。没有修改原始预测器或渐进内层的证据规则。

## 有界验证结果

67 项相关测试通过，包括新增的全局停止、局部配额恢复、最好方案保留、UNKNOWN 不产生假结果和精确内层终止原因检查。

只复核 BO–MADS 的既有 7/14 模型池 × 11/29/47 三个种子，共 6 次 CPU 搜索；其他三种方法没有重跑。所有六次均满足：

- 修复前后 **64 次付费预测的顺序、候选部署、分流、阶段和效用逐项完全相同**。
- 最终效用、部署和分流完全相同。
- 在最后一个包含付费预测的外层评价结束后停止，返回 `PREDICTIONS_LIMIT`。
- 已有有限部署参考继续用于独立核对，没有重跑参考求解器。

|候选模型池|预测次数：前→后|外层评价次数：前→后（种子 11/29/47）|完整耗时中位数：前→后|
|---|---|---|---|
|7|64 → 64|256 → 70 / 71 / 69|3.953 → 0.714 秒|
|14|64 → 64|256 → 54 / 52 / 52|4.975 → 0.827 秒|

时间来自修复前后不同批次，仅作描述性验证，不给出严格加速比。预测后的剩余收尾约为 7–10 毫秒；仍包含结果整理、最终 GP 统计和序列化准备。不能据此声称 BO–MADS 已比其他三种策略更快；前批的最终效用排名也没有改变。
