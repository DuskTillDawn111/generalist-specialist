# C1-Lite 定向场景包与选点边界

2026-11-03。[准备包 JSON](../artifacts/c1-lite-v2-20261103/qualification/packet.json) 包含 12 个分阶段条件，均为未执行设计，不是通过支持域验证的实测场景。

## 从什么域开始

目标先选现有 G2+image+OCR 部署及匹配输入，text/ASR 给 G，image/OCR 可以分流。它覆盖专用闲置/活动和共享 G 的负载变化，避免一开始扫描全部三/五/七模型。

| 条件组 | 数量 | 目的 |
|---|---:|---|
| image/OCR 两行的联合纯端点 | 4 | 同驻留域的联合端点，不以逐行扫描冒充联合覆盖 |
| image 全给 S，OCR 的 S 比例 .25/.5/.75 | 3 | 初步路由、活动与 FIFO 变化 |
| image/OCR 的 S 比例均为 .5 | 1 | 有限联合内部点 |
| 删除零流量 OCR 专用 | 1 | 将驻留成本与活动成本分开，再比较联合部署 |
| OCR n=2，其余 n=1 | 1 | 同 offered cohort 下比较副本、容量与完整能耗 |
| 容量测量后选择的 OCR 热点 | 1 | 覆盖 S 也承压的合法范围 |
| 真实属性预声明的 harder OCR 输入 | 1 | 将输入难度与到达率分开验证 |

所有记录的 `execution_ready=False`；n=2 只说明容量表存在该状态，实际内存、画像与阶段身份仍须验证。热点 `workload_rps=None`，harder `input_manifest=None`，均未编造可执行条件。

.25/.5/.75 是开发扫描点，并不能证明偏离所有网格。开发阶段还应在合法域选择少量明确偏离预声明 K 网格的比例，冻结实际请求映射及联合候选后，再进入独立确认。当前包没有提前选定这些确认赢家。

## 预算与分批

pilot 最多 3 轮，每轮到达窗口 30 秒、完整 episode 最多 300 秒，总计最多 900 GPU 秒。正式资格补采总上限 3600 GPU 秒，需要根据 pilot 选出预算内可辨识子集；12 条件 × 全部种子不自动执行。

正式 horizon/drain 沿当前系统配置；短 pilot 与正式参考的 horizon 不同，pilot 的 U 明确为空。先核验内存、队列排空、时钟及遥测，失败记录保留。预算不足以识别完整模型时缩小支持域或报告不足，不降低证据要求。

## 怎样回答“专用还是太强”

保留原低压力条件作为容易对照；增加按实测稳定容量选出的 S 受压条件，分别变化输入长度/页数等真实难度属性和 QPS。相同条件下 G/S 使用共同输入顺序及任务协议，记录各模型实际负载和活动重叠。

先比较固定部署中的端点、旧网格与内部比例，再允许卸载零流量模型和改变副本，完整计入启动、驻留、运行、排空与参考归一化。固定部署改善不保证能支付联合激活成本。

内部比例获胜、端点仍获胜、误差遮住差异，都是允许的结论。场景选择依据任务及资源竞争，不能依据确认集谁获胜；不调权重、削弱专用或人为添加竞争保证内部最优。

准备包仍需完成原生采集生产器/模板绑定、正式输入角色清单、容量选择、参考冻结和阈值声明，才能成为可运行的资格实验。详见[预测资格](c1_lite_hybrid_prediction_qualification.md)。
