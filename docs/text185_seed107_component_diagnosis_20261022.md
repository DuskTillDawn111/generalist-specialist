# text 1.85 rps、seed 107：分流尾延迟反转的事后诊断

本诊断只读取已登记且通过独立审计的两份 `run.json`。部署均为 text×2 + generalist_2×1 + ocr×1；背景 image/asr/ocr 各 0.01 rps；比较不分流与 text 向 generalist_2 分流 1/32。600 秒、原始 Poisson、SamplePool、SWRR、稳定性、质量、内存和六项效用口径均未修改。

原始比较是 `artifacts/static-spillover-study-20261022/text185-measured-comparison-v3/report.json`。本轮诊断最终文件为 `artifacts/static-spillover-study-20261022/text185-seed107-component-diagnosis-v2/report.json`，对应工具 `tools/spillover_context_20261022/diagnose_pair_replay.py`。v1 保留。v3 比较器 manifest 的四个工具 SHA 均与本次核验时源码一致，跨 packet 评分契约检查已包含在生成 v3 的源码中。

## 已观察到的结果

分流使 U 从 −1.10904205527422 降至 −1.142799587303698。Q、T、M 相同；L 增加 0.00953999635033，P 增加 0.188919888771，E 增加 0.00408530705524。这里 L、P、E 是原效用归一化损失，增加会降低 U。

原开发场景采用历史持续联合诊断的专用逐输入服务向量，并假设 G2 text 服务为联合向量的一半。它给出 ΔP=−0.477249，实测却是 +0.188920。为了定位反转来源，下面固定原 trace、输入和别名路由，只替换部分服务时间，并做每别名 FIFO 回放。

| 事后回放条件 | ΔL（分流−不分流） | ΔP（分流−不分流） |
|---|---:|---:|
| 原历史 half-G2 场景 | −0.178454 | −0.477249 |
| 仅替换专用为各自实测逐请求 service | +0.028425 | +0.289580 |
| 仅替换 G2 text 为实测 service | −0.195270 | −0.577452 |
| 仅替换背景任务为实测 service | −0.180305 | −0.496816 |
| 全部使用各自实测 native service | +0.009759 | +0.187305 |
| 全部使用实测 handler 时长及实际提交时刻 | +0.009686 | +0.187749 |
| 实际观测 | +0.009540 | +0.188920 |

替换专用服务这一项已经使收益方向反转；替换 G2 或背景服务均未使方向反转。全部使用实测服务时，FIFO 已复现绝大部分 L/P 差异。实际提交时刻相对于原 scheduled 时刻的修正很小。因此，此对实验应首先检查专用输入组合及其条件服务序列，不能把反转归因于 G2 text 比 half-G2 假设更慢，或到达定时器误差。

G2 实际承担 36 条 text，平均 service=3275.676 ms；历史同一输入联合向量均值=7322.033 ms，half 假设为 3661.017 ms。实际反而比 half 假设快。这里没有将此单对观测拟合为新的预测倍率。

## 专用输入混合与条件服务

将不分流实验的服务按 pool_id 求均值，形成一份共享的事后逐输入表，再按分流后的实际输入计数加权，可区分平均工作量的输入混合变化与剩余条件变化。该表跨别名转移服务时间，属于明确的敏感性假设。

| 专用别名 | 不分流实际均值 ms | 按分流输入混合加权 baseline 表 ms | 分流实际均值 ms | 实际−转移表 ms |
|---|---:|---:|---:|---:|
| text#0 | 704.846 | 770.702 | 791.415 | +20.713 |
| text#1 | 817.154 | 718.157 | 755.801 | +37.644 |

原 SWRR 改变了两个副本处理的输入混合；同时，两份实际序列的条件服务也有变化。不能仅比较副本平均服务或平均负载来判断 P95 收益。

两份运行共有 30 个相同 `(text别名, pool_id)` 单元可直接描述性对照。例如：

| 别名、pool_id 后缀 | 不分流均值 ms | 分流均值 ms | 比值 |
|---|---:|---:|---:|
| text#0、739fbf343a62b73fb8d1dfd3 | 1185.038 | 1417.653 | 1.1963 |
| text#1、0d8a82b009261e9e9241a0c9 | 887.412 | 1110.989 | 1.2519 |

这两个单元分别有 36 条 baseline 和 18 条 split 请求；每个单元内部输入 token 数和生成 token 数固定。它们证明逐输入平均服务并非保持不变，不能单独证明变化由 GPU 干扰造成。

进一步将 baseline 的原始逐请求专用服务按相同 arrival_index 转移至两份路由，保留 baseline 的时间波动，并对其他任务使用各自实测服务，得到 ΔP=−0.250980；使用 baseline 逐输入均值或中位数的共享表也分别得到 −0.146180、−0.186983。保持固定基线服务的这些回放均未复现实际正向 ΔP。因此此次反转不能仅用静态 SWRR 输入重映射解释，还需考虑条件服务序列、共享 GPU 上下文和时间漂移。

## 使用边界及下一步

这是事后分解，不是因果归因。所有实际服务在运行前未知；替换服务时固定了其他服务，未重测干扰反馈；两个串行运行无法分离路由作用、共享 GPU 干扰和时间漂移。不得把任何回放所得 ΔP 当作未来方案的实测值，也不得用实际未来 overlap 构造已验证预测器。

保持 seed108 已声明的反向顺序对照，并完成两个专用结构强对照。若 seed108 重现同方向劣化，应优先修正条件服务模型与不确定性处理，减少依赖固定服务倍率的候选筛选。若方向改变，先报告重复差异并设计少量有针对性的上下文校准，避免依照 seed107 事后挑选一个有利比例。

CPU 验证：`python -m unittest tests.test_pair_component_replay tests.test_compare_development -v`，6 项通过。涵盖独立别名 FIFO、提交延迟仍相对 scheduled 计时、非法服务/时刻拒绝，以及比较器契约、cohort、pending 身份保护。
