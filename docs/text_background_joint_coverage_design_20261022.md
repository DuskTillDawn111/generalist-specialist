# 固定 n2 驻留下的背景路径补测设计

日期：2026-10-22。本文件仅为 CPU 设计，不启动 GPU，不改当前四条件持续共同活动包、冻结运行时、模型、评分或预测器。当前四条件的最终审计和共同活动验收仍是前置条件；不因首个 B 完成便判断 C 已通过。

## 先核对真实输入与到达合同

当前包引用的 `system-config.json` 使用 **Poisson** 正式到达过程。诊断 transport 中的 periodic 字段只是闭环脚手架，不能继承成正式负载定义。冻结输入池为 text32、**image64**、ASR32、OCR32；image 不是32。模型池、原副本档、质量入效用、六项等权、49140MiB、rho≤0.8及正式稳定性均保持原合同。

目标部署仍是 text×2、G2×1、OCR×1。正式候选背景为 image/asr/ocr 各0.01rps，分别路由 G2/G2/OCR；text 以0、1/8、1/4分给 G2，其余由两个 text alias 等分。本文件不指定 text 到达率，不选择获胜结构，也不拟合连续服务函数。

需要分开两个缺口：

| 缺口 | 能回答的问题 | 不能替代的证据 |
|---|---|---|
| G2/image64、G2/ASR32、OCR/OCR32完整输入服务与原生输出 | 哪些输入已测、在什么驻留/活动上下文测过，服务、输出、资源是否可复现 | 原生21条priming只覆盖每路径3个最大输入；不能补足整池 |
| 正式0.01背景与压力文本共存的开放响应 | 指定有限trace下的G2共享FIFO、背景等待、文本分流、稳定性和实际Q | 饱和闭环或均衡全池采样改变了流量和输入频次，不能冒充正式背景 |

## 最少增次的分阶段安排

先审计已有路径画像和运行身份。已有完整输入证据可以保留为**其原上下文的历史基线**；仅在驻留、执行协议、输入、解码与活动上下文的适用性全部有证据时复用。现有 text-only 四条件不测量背景；完整 priming 也不提供背景整池服务。如果确有身份等价的当前上下文整池证据，不机械重跑该项。缺口继续标 UNKNOWN。

建议首先准备 **两个开发执行块**，每块 fresh workers，固定四个 resident alias，合并补齐三个缺失背景路径。两块是拟议起始预算，不是保证两次就验证完毕；在封包之前还须做有限时长和支持游标的 CPU 风险检查。若不能在预声明硬界内合理安排，则按冻结输入ID确定性切片另封包，不能现场延长、删慢输入或只保留完成子集。

每块的目标背景 cohort 为 G2/image64×3=192、G2/asr32×3=96、OCR/ocr32×3=96，总计384条 background-primary。每任务每轮完整平衡，输入顺序、角色、任务合并次序和ID预先冻结。重复不是新增独立输入；跨块仍按输入聚类。两个块全部完成才得到各输入在两个独立启动块、每块3次的开发观测。

**同一个 G2 worker 必须串行处理 text、image、ASR。** 给 G2 冻结一条明确的任务tape：平衡的 image/ASR primary按预声明次序合并，并在固定位置插入 text-support；每alias最多一条在途，不设虚构的 image/asr/text 三个 G2并行队列。text-support独立游标、输入只取原32池、不根据答案/耗时选输入。合并次序可在两块使用相反的预声明任务tie次序以暴露顺序依赖，不能读取第一块结果后再选第二块。此人为tape是服务覆盖诊断，任务比例不等于正式0.01背景。

两个 text specialist 持续使用有界、预声明 text-support，直到 G2和OCR所有 background-primary获得终态；G2若先结束自身背景primary，则可按预声明text-support继续维持活动。OCR完成96条primary后可以退出活动但仍驻留，不为了凑“所有alias饱和”而自动补OCR；因此G2请求实际遇到OCR活动/空闲的区间须逐条分开。OCR的96条primary须报告它们与两个specialist、G2各自handler的实际交叠，不能由“G2一直有请求”推定同时忙。若该输入只有弱交叠，缺口保留；不能把不同上下文合成一个已验证服务表。

这个合并方案优先减少启动和重复测量次数，代价是部分上下文随OCR完成而变化。**它不识别同驻留的idle→active因果差异，也不覆盖任意任务混合。** 若两个块显示上下文漂移或无法为下一步风险情景提供可解释输入表，再补明确的最小对照：同部署、specialist空闲的背景tape锚点，或按路径分开的joint条件。需要的对照是条件式追加，不能事先宣称两块已足够，也不预先穷举任务组合。

## 封包前必须写定的运行边界

沿用全resident21条原生priming、30秒有界warmup、request300秒、measurement600秒（含已在途请求排空）、原显存安全因子和监测。每alias支持上限先做CPU工作量检查再冻结，不能无条件照搬1024；若继续选1024，也必须把耗尽视为停止条件而非延长许可。三个background-primary cohort全量预注册，支持请求只登记实际发布前缀；任一primary缺失、原生失败、资源失败、支持耗尽或超时均停止，保留原始失败，不自动重试或换序。

还需在启动前冻结：每条路径/输入的重复性容差、背景handler与两个specialist的最低实际共同交叠、OCR与G2重叠的单列要求、输出/质量差异报告、停止/排空边界、跨块比较及资源/能量独立审计。当前text诊断的0.90、2/3和0.5–2容差不能在看完新背景数据后变成背景“恰好通过”的门槛。handler交集只用于事后诊断，不能作为未来候选可事先知道的预测特征。

完整成功与可评分输出、真实安全显存、整卡功率积分、进程身份和干净退出均独立核验。primary质量按task原生口径分别重算，support单列，均不写正式U。上述观测最大值只是已测开发情景，不能称概率容量上界；背景服务也不能按闭环吞吐倒数代替。

## 正式低背景响应不额外穷举

在有可解释的完整输入开发情景、无关键UNKNOWN后，按既有条件式门禁选择两个text开发负载；本文件不提前给率。后续原计划的两档×三份额六个开放开发条件直接携带正式0.01背景，复用相同seed的route-independent任务cohort作比较，**无需为每一个背景任务或每一种任务组合另开GPU实验**。先跑低档三路由，触发预声明失败条件则暂停高档。没有两档共同可比较可行区间则停止，不用删除零分流来凑结果。

这六个开放条件检验的是其精确有限正式cohort：G2 image/asr/text的单worker共享FIFO和host队列、OCR与text的真实活动、窗口尾段积压、排空依赖、原生质量与六项效用。低频背景碰巧没有和某路径重叠时，直接报告暴露不足，不强造背景、换输入或挑seed；完整输入诊断补“服务覆盖”，有限正式运行补“目标暴露”，两者不会互相变成对方的证书。没有证明的服务context迁移继续UNKNOWN。

六点用于开发，不直接解锁正式搜索。随后须冻结新预测器的公式、逐输入服务/输出假设、适用负载与部署/副本/路由域、M/E及rho实现、误差与可分辨排序标准，再以保留seed做完整背景的独立开放验证；验证数据一旦用于修模型即转为开发，不能再叫独立验证。H600支持不自动覆盖H1800。

即使固定n2情景通过，也只支持该声明域。七模型全池仍需覆盖其余模型/任务/副本与竞争部署；未知路径不得静默删除或填零完整服务。新模型的搜索下界须重新证明，缺证分量只能取乐观零界。MILP、有界DFS、plain DFS在同一完整域、同一trace/效用/约束下完成并比较最优值与证明成本，才能声称该冻结预测域同最优；真实GPU候选强对照仍需另外完成。固定n2的少量诊断不等于七池全域最优。
