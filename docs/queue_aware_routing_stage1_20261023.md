# 感知队列的路由：本阶段即开始研究

## 研究目标与边界

静态任务负载限定任务到达分布与速率，并不要求每个请求的目的地提前固定。本阶段开始研究在线感知队列的路由，同时保留已经启动的固定比例 GPU 对照；两者使用独立代码与实验身份。

最终目标仍是由算法自主选择部署副本与路由策略，以原 Q/T/L/P/M/E 六项总效用比较候选，并在明确的有限候选域内与 DFS 验证最优解和效率。新增路由原型只是其中一个候选策略，尚不是该目标的完成证据。

本阶段产物：

- `tools/queue_aware_20261023/policy.py`：独立在线路由原型。
- `tools/queue_aware_20261023/replay.py`：保留原始到达与输入的因果 CPU 闭环诊断。
- `tools/queue_aware_20261023/runtime_window.py`：在实际到达时决定目的地的独立 host dispatch 适配器；尚未接入 native launcher。
- `artifacts/queue-aware-study-20261023/cpu-closed-loop-v1/`：10 组回放、逐请求结果、逐决策队列快照和来源哈希。
- `artifacts/queue-aware-study-20261023/cpu-stage1-review-v1/`：合并检查和审计记录。

未修改冻结源 `execution-source-v5`，未接管正在运行的 GPU 实验。

## 路由如何识别分流机会

对新到达的请求，在已部署且支持该任务的副本中，计算：

`局部代价 = wL × (前方预计剩余工作 + 本请求预计服务时间) / 任务延迟参考值 + wQ × 模型在该任务上的历史聚合质量损失`。

`wL`、`wQ` 使用原总效用权重；质量消融将局部 `wQ` 设为 0。这个代价只近似新请求的延迟与质量，不能代替完整总效用，也不保证全局 P95 最小。

队列包含 host 尚未发送以及已进入 worker 管道的全部未完成请求，包含通用模型正在处理的其他任务。不能仅查看 host 队列长度。已提交 FIFO 队首的开始时间不可直接观察，使用 host 提交时间与最近收到完成结果的时间估计；超时仍未完成时保留 5 ms 的剩余工作下限。其后的请求计完整预计服务时间。

决策不读取未来服务时间、未来完成事件、参考答案或本请求是否正确。质量只用冻结历史聚合值；按最终实际路由计算历史样本质量发生在全部决策之后。不迁移已经提交的请求。

策略可以先选较空闲的另一个专用副本，也可以在通用模型的预计完成代价更小时向它分流。通用模型一旦忙碌，之后的新请求可以重新回到专用副本。没有强制分流比例，也没有绝对质量准入。未知路径不填零，审计中保留 UNKNOWN。

## CPU 回放设计与结果

固定部署：ChatQA 文本专用 ×2、G2 MiniCPM-o 通用 ×1、PP-OCR 专用 ×1。负载：text 1.85 req/s，image、ASR、OCR 各 0.01 req/s；测量窗口 600 秒。使用原冻结到达轨迹、SamplePool 和已观察过的开发 seed 107、108。背景路由不变：image/ASR 到 G2，OCR 到 OCR 专用。

比较五种策略：原 SWRR 不分流、原 SWRR 固定 1/32 分流、仅专用副本感知队列、专用与通用感知队列但不计局部质量、专用与通用感知队列且计局部质量。所有策略使用相同请求与输入，以及同一份冻结服务时间场景。

下表的 L、P 是原任务加权归一化延迟与尾延迟项，越小越好；Q 是历史质量损失，越小越好。

| seed | 策略 | 文本分给 G2 | L | P | Q |
| --- | --- | ---: | ---: | ---: | ---: |
| 107 | SWRR 不分流 | 0/1156 | 0.843886 | 1.850794 | 0.280347 |
| 107 | SWRR 固定 1/32 | 36/1156 | 0.817322 | 1.789318 | 0.280347 |
| 107 | 仅专用感知队列 | 0/1156 | 0.790903 | 1.600541 | 0.280347 |
| 107 | 专用＋通用，仅局部延迟 | 67/1156 | 0.736894 | 1.536269 | 0.286306 |
| 107 | 专用＋通用，局部延迟＋质量 | 60/1156 | 0.739644 | 1.561295 | 0.284604 |
| 108 | SWRR 不分流 | 0/1127 | 0.877109 | 2.069453 | 0.280593 |
| 108 | SWRR 固定 1/32 | 35/1127 | 0.855709 | 2.058207 | 0.296310 |
| 108 | 仅专用感知队列 | 0/1127 | 0.794230 | 1.654466 | 0.280593 |
| 108 | 专用＋通用，仅局部延迟 | 68/1127 | 0.737819 | 1.583057 | 0.280593 |
| 108 | 专用＋通用，局部延迟＋质量 | 59/1127 | 0.740201 | 1.583057 | 0.280593 |

质量感知策略自主分流 5.19%、5.24%。相对于仅专用均衡，L 额外降低约 6.48%、6.80%；P 额外降低约 2.45%、4.32%。因此，在这个冻结服务场景下，除了专用均衡，还存在额外的分流机会；但 107 的质量损失有所增加，不能只按延迟判断最终好坏。局部质量先验也不会保证每条实际轨迹的质量改善。

这些结果只用于原型诊断：服务场景来自既有 19 组开发数据拟合的点预测，策略预计服务与模拟环境服务默认一致；不是新的 GPU 实测。G2/text 在选定不分流参考上下文中属于外推。模拟没有复现动态路由导致的共享 GPU 干扰、host 发送延迟、采样质量变化。M/E 与完整 U 均为 UNKNOWN，物理稳定性也为 UNKNOWN。seed 107/108 不能充当独立验证。

## 验证与接入顺序

CPU 测试覆盖拥堵分流、通用后台阻塞、专用均衡、质量权重、未知路径、超时剩余工作、未来标签不影响决策，以及 host 快照与入队原子性。闭环测试还验证估计与真实服务不一致时仍不读取未来、同刻完成事件可见、host 提交与 worker 开始时间区分，以及原不分流 Q/T/L/P 的复现。

独立合并审计逐次从此前请求的实际完成记录重建可见队列，再重算动态决策及静态 SWRR，核对原始 cohort、来源哈希与 UNKNOWN 的保留；不是部署最优性或 GPU 收益审计。

接下来依次完成：

1. **动态实验身份与核验。** 现有 evaluator 会重建静态 SWRR 并检查每个目的副本，直接替换路由将被判 cohort 不一致。需要给冻结的策略、参数、服务估计和质量先验建立独立身份，按原到达与输入检查 cohort，再按可见快照复算动态决定。保留六项效用的数值口径与原稳定性判定。
2. **动态准入与计量。** 明确策略允许的路径及路由负载边界，沿用 rho≤0.8 阈值；实际分流比例只能作为事后暴露量，不能伪装成事前静态准入证明。接入原内存、功率、排队尾段、drain 与错误记录，形成可评价的完整 U。
3. **相同部署上的 GPU 对照。** 当前固定路由批次结束后，串行比较五种策略；固定到达、输入与背景任务，按预先声明的成对顺序执行，保留所有无收益和失败结果。优先核对“质量感知分流”相对“仅专用均衡”的增量，而非把全部改进算成分流。
4. **部署＋策略联合搜索。** 搜索变量扩展为副本部署 x 与有限策略参数 θ，包含原静态策略。算法和 DFS 必须共享候选域、评价器及预算口径。原静态分任务界限不能直接套到动态队列策略；界限未证明可用之前，只能声明有限枚举核验，不能声称完整动态域最优或搜索加速。

此路线保持“算法可以主动识别并选择专用向通用分流”为当前目标，同时允许完整总效用最终选择不分流。
