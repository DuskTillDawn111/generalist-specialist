# 静态效用审计（2026-10-14）

审计保持现有 Q/T/L/P/M 权重、质量门槛和预测器不变。读取当前模型池 C、历史质量矩阵、多副本实测表、历史 20 个 GPU 效用记录及本次 21 请求真机验收；另用公开 API 运行 39 个负载/域组合、6 个权重配置、5 个任务比例配置。无新增 GPU 测量。CPU 结果只说明声明的预测器和候选域内的行为。

**现有效用适合作为可解释的性能与显存比较基线，但还不足以表达任务服务价值，也不足以可靠预测真机小收益。** 不强制保留通用，不预设低负载一定纯通用或高负载一定纯专用。部署结构应由能力、质量、负载、资源与真实收益共同决定。

## 目标的合理部分

`U = -0.25T -0.30L -0.30P -0.15M`。质量为硬门槛，避免直接相加 accuracy、WER 和 OCR exact match；未完成、资源不合法或证据不足的实测运行不能获得正式 U。延迟按任务参考值无量纲化，任务权重固定为输入流量比例，避免靠丢弃慢请求改善平均值。显存既有硬预算，也有占用惩罚。求解器按角色中立地比较方案。

## 低负载表现与资源事实

相同六任务比例，以 LOW18 流量为 1 倍：

|总请求/秒|当前 C 最优部署|预测 U|安全显存 MiB|
|---:|---|---:|---:|
|0.175|Phi、RoBERTa、ConvNeXt、PARSeq、Whisper Small 各 1|-0.460273|17645.54|
|0.7|同上|-0.424559|17645.54|
|1.4|同上|-0.424559|17645.54|
|3.5|同上|-0.424559|17645.54|
|7|同上|-0.424559|17645.54|
|14|同上|-0.430366|17645.54|

0.7→7 请求/秒，吞吐损失为 0，延迟没有显著排队变化，因此效用几乎不变。服务收益采用流量比例而不是总服务价值：在不拥塞区间，维持比例并缩小绝对流量，不会显著降低专用的延迟收益。

在无排队、确定性服务、保留通用并增设一个专用的近似下：

|任务|专用|任务占比 10% 的延迟收益|新增显存惩罚|收支平衡任务占比|
|---|---|---:|---:|---:|
|Text|RoBERTa|0.234176|0.003357|0.1434%|
|Image|ConvNeXt|0.289570|0.002068|0.0714%|
|ASR|Whisper Small|0.048451|0.005480|1.1310%|
|LID|Whisper Small|0.088774|0.005480|0.6173%|
|OCR|PARSeq（相对 MiniCPM）|0.757244|0.001940|0.0256%|

这些不是普遍准入阈值：实际路由会改变排队，移除空闲通用会节省显存，ASR/LID 共用 Whisper 时只能收费一次。它们说明现有归一化尺度下的边际倾向。

但不能把所有专用选择都归为错误偏向。0.7 请求/秒时，两通用合法覆盖的预测 U=-2.508391，安全显存 42059.15 MiB；四专用加 Phi 的 U=-0.424559，安全显存 17645.54 MiB。后者在当前画像下同时更快、更省显存。把显存权重从 0.001 扫到 0.7，专用仍被选择；高权重甚至更偏向小模型组合。因此，只增加显存权重不能自然产生低负载纯通用。

Qwen 单模型可执行六任务的诊断配置需要安全显存 20350.84 MiB，仍比上述混合组合多。该诊断不是合法质量方案：Qwen OCR 历史 exact match=0.94，旧门槛=0.96。不能用它作为已准入基线。

## 评价与预测的问题需要分别处理

1. **没有服务目标下的收益饱和。** 已足够快的任务，继续缩短毫秒数仍线性得分。固定参考延迟不是用户 SLO。
2. **指标尺度不等价。** 合法部署的 M≤1，而 L/P 可以远大于 1。权重之和为 1 不意味着实际影响按权重比例分配。平均延迟与尾延迟也可能同时奖励同一项服务时间下降。
3. **总流量的服务价值缺失。** 相同任务比例、无拥塞时，0.7 与 7 请求/秒的评分近乎一样。是否合理取决于目标是平均请求体验还是单位时间服务价值，需要明确。
4. **质量政策不完整。** 达标后不区分质量改善；LID/VQA 的历史政策又没有数值阈值。先明确各任务业务门槛，不能为制造部署阶段随意降低门槛或直接混合不同质量指标。
5. **显存只代表部分代价。** GPU 服务时间、同卡干扰、CPU/解码开销和能耗没有完整进入资源成本。显存少不意味着同卡计算代价低。
6. **低负载有限窗口伪不可行。** 同一合法部署在 0.007、0.035、0.0875 请求/秒通过能力、预算、rho 校验，预测器却因 120 秒窗口中某任务无观测返回 MISSING_TASK。0.175 请求/秒的 T=0.142857 也包含有限到达计数效应，并非真实容量不足。应修正稀疏任务的预测覆盖与吞吐分母，不能把它解释为闲时不应部署。
7. **服务画像不足以认证真机收益。** 历史 20 个记录的实测 U 全比预测差；同负载/种子的 A/B 六个独立配对中，排序一致 4 个。B 预测 ORACLE 优于 COMPETITOR +1.444254，三个独立实测差为 -0.508905、-0.617697、+1.383982。样本少且场景单一，不能推广成整体排序准确率。

本次 21 请求真机验收同样存在画像偏差：Whisper ASR worker mean=793.87 ms，而画像 s0=190.17 ms；RoBERTa=29.90 vs 5.51 ms；Phi VQA=196.34 vs 160.12 ms。每任务仅 3 条、VQA 6 条，GPU UUID 与历史不同；输入、环境、冷启动和共驻留均可能影响结果。这是重新标定的证据，不能直接认证长期 P95 或唯一归因于 GPU 干扰。

## 多副本与分流边界

历史已有真实多副本测量，主目录此前沿用 A/B/C 后期冻结的单副本候选域。此次通过 `configs/catalogs/c_replicas.json` 接回当前十个模型有记录的数量，保持单副本值、质量准入和效用原值；`configs/static_replicas.json` 是静态实验入口，六任务验收默认使用它。

典型容量因子：RoBERTa g2=1.9011；ConvNeXt g2=1.8507、g3=2.7949；PARSeq g2=1.8079、g3=2.4370；Whisper Small g2=1.2378、g3=1.3199；MiniCPM g2=0.9615。副本并非线性扩容，MiniCPM 的测点甚至没有增加容量。只放行已记录的数量，不填充更高副本。代表任务的吞吐比转移到其他任务/混合组合仍是代理，不冒充真机认证。

21 请求/秒时，单副本 C 无合法完整路由；实测副本域可以选择 Phi 双副本等组合，预测 max rho=0.5871、安全显存 35296.27 MiB。35 请求/秒时，K=1 即便开放这些副本仍无解；构造一份 Whisper Small 双副本、VQA 分给 Qwen/Phi 的合法路由，可得到 max rho=0.7846、安全显存 43964.64 MiB。这只是可行性见证，没有联合最优证书或新 GPU 验证，说明联合分流搜索仍需接入。

## 改造依据

保留质量、覆盖、流量守恒、实测数量和资源预算等硬条件。效用应明确业务目标，考虑按固定窗口的任务服务价值计收益、以各任务明确 SLO 定义有界满意度，再扣除有依据的资源成本。不添加强制通用、强制专用或用于保证阶段顺序的角色奖励。质量优先使用业务门槛；如需超门槛质量奖励，要先校准其实际价值。

本轮没有修改核心效用公式、质量阈值或历史原始记录。当前仍需解决：稀疏任务预测、联合部署/副本/分流搜索、通用缺失路径的质量政策与必要实测，以及新效用的独立正负收益验证。
