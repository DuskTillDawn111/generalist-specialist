# Stable native response replication producer and instance adapter

The new producer is `tools/predictor_validation_20261027/kernel_dag_response_replication_producer_v1.py`; the downstream CPU adapter is `kernel_dag_repeated_instance_alignment_v1.py`. They do not change the frozen unified collector, strict native reviewer, mapping audit, occupancy resolver or response compiler.

The concrete matrix has eleven actual runtime jobs per native session: four solo owner jobs, all six pairs, and one all-four job. Each session records twenty measured requests and twelve original priming requests; three independently claimed native lifecycles total sixty measured and thirty-six priming requests. Every owner contributes five responses per capture and fifteen in total. Initial offsets are zero. The all-four request cohort is checked against one actual runtime batch, rather than inferred from overlapping names or separate SSG/OCR jobs.

CPU preparation calls the original unified preparation once, retaining its single nonce and complete context. New wrapper/adapter implementation dependencies are frozen into a new context shared byte-for-byte by the three capture directories. Capture IDs remain separate plan/provenance fields. The seed light/natural directories are preparation evidence only and are not scheduled. Full context/source/hardware identity is never normalized or stripped.

Historical source preparation now rejects two planner changes (`gsdeploy/milp.py`, `gsdeploy/optimizer.py`). The new source packet retains the old plan/context and every old frozen receipt, authenticates the complete unchanged direct dispatch/native/model source cohort, permits only those two explicitly classified planner changes, and freezes every current historical source again. It preserves old/new drift receipts in `current-source-packet/source-rebind.json`. Historical runtime smoke applies only to unchanged direct bindings; it grants no new whole-domain native qualification. Each new capture must still pass actual READY/spec, ownership, output/work, trace and strict review checks. Cpu01 failed preparation and cpu02 earlier preparation evidence remain preserved. Cpu03 is the final prepared version after the complete module-closure audit was added.

`audit` checks canonical run/plan/context paths, all three exact plans, complete static import closure, source/resources, full context equality, exact matrix/input bytes and lifecycle/campaign bindings. `execute` requires an explicit CLI flag and the pinned matching producer's complete fifteen-attempt native completion report. An exclusive wrapper claim is created once; the unchanged collector then enforces its GPU experiment lease, no retries, exact source guard, disk reserve, process-tree Nsight configuration, continuous watchdog and owned cleanup. An outer inotify guard covers the campaign, all three plans/contexts, matching completion and every source through execution. A changed-and-restored source fails qualification and leaves the no-retry claim in place. No existing waiting chain is modified.

The original native reviewer remains the authority for exported SQLite and collection correctness. The wrapper's CPU `review` consumes that already exported strict report and authenticates the exact outer claim, guarded execution, matching predecessor and all twenty distinct owner/job/input instances. Request-instance identity includes capture provenance; repeated exact work is not collapsed into a single observation.

The repeated-instance adapter accepts exactly three wrapper reviews plus their authenticated unified intake reports and explicitly pinned occupancy audits. It reauthenticates the exclusive execution chain, native review, complete sixty-instance cohort, exact full context/hardware, one distinct native SQLite clock per capture and absence of unassigned overlapping peers. It reuses the strict complete launch/API/dependency/static template core. Each exact owner/input/actual-work cohort must contain fifteen full equivalent observations before sharing a canonical node baseline. A changed OCR output, input, launch, edge, boundary assumption, configuration, unknown static value or incomplete cohort stays UNKNOWN; no partial subset is exported. Native timestamps and original evidence remain separate, and the compiler receives three independent native session domains. No fit is run and no rank, natural timing, prediction accuracy or deployment qualification is promised.

CPU tests cover complete 60-response compilation with four common templates, exact observed batch denominators, context/hardware/raw alias rejection, changed work/dependency rejection without partial export, role checks before label access, source rebinding restrictions, canonical paths, complete matching predecessor, claim-chain reauthentication and an actual inotify change-and-restore counterexample. These fixtures are synthetic CPU declarations and are not native training evidence.

Intended execution order after independent review: wait for the pinned matching report, execute each declared capture once, run the original strict native export/review, run CPU wrapper review and exact-source occupancy/unified intake, then run the new repeated-instance adapter. Only subsequently measured support/rank and existing numerical qualification gates can determine whether a response-law fit is identifiable. This work prepares interfaces and evidence; it has not started GPU, CUDA, Nsight, a collector or a fit.
