# Matching exact15 numerical downstream, CPU preparation only

The matching producer owns a different context and input domain: union22,
three whole blocks, five attempt shards per block, 171 cases, 390 measured
requests and 270 priming history rows. It must not impersonate the older
exact12 producer, whose 150 cases / 546 measured / 216 priming are frozen.
The producer's four files and its CPU01 / CPU02 evidence remain unchanged.

This adapter chain consumes matching producer/intake evidence and passes
validated numerical objects to the existing original math and queue engine:

1. `twoFIFO_matching_phase12_adapter_v1`: matching native review and macro
   rederivation, processed-prefix covariates, complete contiguous entry,
   forward/OCR and final READY paths, all twelve original features and nuisance
   groups. Request counts and variable macro counts are checked separately.
2. `twoFIFO_matching_phase12_v1`: matching source-bound intake and original
   `twoFIFO_phase12_fit_v2.fitted_rows/evaluate`. Full fifteen-attempt model,
   three whole-block leaveouts of ten donor / five heldout attempts. Missing
   roots, nuisance support or OCR exposures never qualify the law. All failed
   heldout rows remain UNKNOWN. CPU preparation and WAITING never call a fit.
3. `twoFIFO_matching_joint_law_v1`: complete matching raw/macro/priming source
   roles, all fifteen unique raw provenance identities and 270 actual priming
   IDs. Original request-vector, protocol recurrence and paired transport
   feasible-set algebra are reused. The returned numerical law uses the
   existing queue compiler's mathematical schema; the source documents retain
   their matching native and macro schemas, with explicit source provenance.
4. `twoFIFO_matching_generated_v1`: unchanged original finite draw catalog,
   queue engine, queue-envelope companion and six-term scoring. Three blocks
   times 57 cases / 130 requests gives all 171 / 390. Each leaveout uses eight
   fixed donor worlds; unqualified fit produces 1368 UNKNOWN worlds without
   removing requests or renormalizing probability. Each prediction and bound
   is persisted before that case's synthetic/native evaluation labels.
5. `twoFIFO_matching_resource_v1`: original resource-state/history lookup and
   equal-block averaging math, now requiring all five shards. Per-attempt
   priming request IDs are excluded from physical worker identity while exact
   ordered input/model/task/pool/content semantics remain bound. All 270 IDs
   remain mandatory history provenance in upstream intake and joint law.

OCR support is derived from every actual OCR input in the matching calendar,
not an obsolete case-name prefix. Empty OCR target sets are rejected. Positive
calendar offsets are not evidence of actual positive-duration observed
language BEGIN overlap; missing n0/npositive or phase combinations remain
UNKNOWN. The actual complete twelve-feature rank is unchanged and may fail.

Resource support is explicitly restricted to the observed matching context,
10-second measurement and 60-second fixed drain, supported donor states and
exact ordered prior memory history. The public provider preserves every idle,
active and drain slice. A 90+120-second target, altered physical context or
missing resource domain returns full-duration UNKNOWN with no lookup. A
missing explicit initial memory history does not reset allocator history to
priming. Startup is counted once per attempt, then original scoring alone
amortizes it by 3600 seconds; the original scorer alone applies memory safety.
No 90+120-second resource support or full-U gain is inferred from short labels.

Source preparation seals its own downstream closure without changing the
frozen producer closure. A preparation may explicitly be unreviewed; native
intake/fit still requires completed independent PASS receipts covering the
current producer, intake, row adapter and phase12 entry sources. No default
fit occurs. Explicit future fits require a complete matching final, authentic
sources and exclusive persistent no-retry claims. Saved fit audit authenticates
the exact manifest, final, intake and design without rerunning the optimizer.
The matching final must live under this exact producer root; a foreign final,
a duplicate/missing attempt or old saved fit is rejected before native labels.

CPU tests use synthetic data and mocked optimizer outputs. They execute actual
feature/path math, original protocol and request-vector algebra, original
queue forecasts/envelopes, durable persistence, original six-term scoring,
resource means and timeline math. A synthetic qualifying root in a test is
only a supplied fixture, not a real fit or evidence of prediction accuracy.
The full 171-case fallback is useful for denominator and UNKNOWN accounting;
it is not validation of interference or routing gain. Preparation may read
frozen scoring-plan and quality-expectation inputs, but reads no new native
resource/response labels. No GPU, collection child, optimizer, real response
fit or real resource fit is launched by this CPU assignment.

CPU prepared paths are listed in the author report. These are unreviewed
numerical preparations and must be superseded by source-reviewed preparations
before authenticated native fitting. They do not authorize or launch a second
GPU campaign. Global admission cap1/cap2, batching, shared-weight/cache reuse,
physical SM service identification and USHER/Roomie physical qualification are
not supplied by this adapter. Equal six-term weights, rho and stability remain
the original contract.
