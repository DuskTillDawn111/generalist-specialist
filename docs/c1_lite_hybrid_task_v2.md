## 一、问题、架构与研究目标

单 GPU 上联合决定模型集合、合法副本数和连续任务路由。对同一冻结预测器及效用契约：

\[
\max_{r\in\mathcal R}V(r),\qquad
V(r)=\max_{D\in\mathcal D(r)}\widehat U(D,r).
\]

- 外层提出连续路由 `r`，在闭 simplex 上搜索，允许精确零比例。
- 内层固定 `r`，搜索模型集合与副本配置 `D`。
- 共驻阶段执行、共享 FIFO、生命周期、质量和资源预测共同评价完整效用；内层反馈后，向外层返回方案、界与求解状态。
- Joint 初始解只用于初始化，不取消后续固定路由部署搜索。固定部署精修属于 C3 分支，不能替代上述双层定义。
- 内层证书只覆盖当前固定路由、声明的有限部署域、冻结模型和数值容差；外层 DE 不提供连续全局最优证书。

研究目标分开报告：

1. **预测资格：** 是否能预测路由及实际活动重叠改变引起的执行服务、排队、资源和效用排序变化。
2. **场景代表性：** 是否覆盖任务/输入差异、专用也承压、共享 G、不同副本及实际资源竞争。
3. **算法效率：** 候选池和按需 MILP 能否降低达到同等方案质量的总成本。
4. **连续路由价值：** 在合法真实支持域内，内部比例能否稳定超过端点/旧网格，并覆盖激活成本。

第 4 项是待检验假设，出现内部最优不是预测器或场景通过验收的必要条件。真实端点占优也是有效结论。

| B：最小实测及参考冻结 | 优先复用匹配记录，仅定向补齐共驻、能耗、生命周期、负载及输入覆盖 | 数据完整可对齐，参考合法，拟合参数可辨识；不完整项明确 UNKNOWN |

| D：C1-Lite 软件原型 | 候选池、渐进内层、触发器、支持不完整观测的独立 DE 控制器 | CPU 正确性与枚举核对通过 |

阶段 D 的软件设计与 CPU 正确性开发可在 B/C 等待外部资源时推进；只能声称软件或冻结模型工程结果，不能绕过 B/C 发布真实效用、场景代表性或算法优势结论。预测失败时先缩小支持域或修正模型，不用继续增加搜索机制掩盖。

GPU 不可访问时，完成可执行实验包和缺项清单，记录实际阻塞；不将 CPU 样例充作真实验证，也不自动启动长期扫描或定时恢复。

## 四、阶段 A–B：匹配数据、能耗与定向采集

### 4.1 身份、分组与共同输入

绑定 GPU、驱动/软件、checkpoint、后端、精度、batch、资源控制、驻留名单、副本、输入/输出协议、解码参数、warmup/priming、到达窗口、drain 和时钟。一次比较内固定这些条件；变化后建立新身份。

训练、模型/场景选择开发、归一化参考开发和最终确认的角色预先声明。已用于选模型、比例或场景的记录不能重新作为盲测。相同比较条件使用共同请求轨迹及按任务预先冻结的输入顺序，不随路由更换输入。

先检查既有记录是否满足合同。只有 handler 总耗时的记录不能拆造 GPU/host 阶段；缺 READY 不能用 receipt 代填；执行身份或队列前史不匹配不能直接拼接。

### 4.2 最小采集矩阵

先选一个有执行支持的 G/S 部署，优先复核既有 G2+image+OCR 或其匹配热点任务，不从三/五/七模型全池全面展开。至少设计以下轴，按可辨识性和先导结果分批执行：

| 轴 | 最小覆盖及目的 |
|---|---|
| 路由 | 同驻留部署的合法端点与少量内部比例，如 0、0.25、0.5、0.75、1；多任务还需联合纯路由及有限联合内部点 |
| 驻留与活动 | S 零流量但仍驻留、S 活跃；合法删除 S 的另一个部署，区分驻留与活动竞争 |
| 副本 | n=1 与至少一个合法、有容量和画像依据的 n=2 条件；同 offered cohort 比较，容量提升另作实验 |
| 到达负载 | 原负载作对照；增加一个按真实容量确定的 S 接近受压档位，覆盖 G/S 均有竞争的区域 |
| 请求混合 | 平衡混合与一个定向热点/突发；记录各模型实际请求、忙碌区间和排队，而非只记录总 QPS |
| 输入难度 | 用真实数据的长度、页数、分辨率、音频时长或预声明难度分层；所有模型使用相同输入/输出任务定义 |

上述为实验设计要求，不是对未测容量的数值承诺。不能直接将旧门禁拒绝的数倍负载当作有效域。高档先进行短容量/内存/排空检查，在现有稳定性规则下选择可比较档位；失败条件也保留，不只展示成功点。

每个拟合上下文至少两个独立训练轮次，同时满足参数可辨识性；同轮多个请求不充当独立重复。计划至少三个开发到达种子、两个未用于选点的确认种子；小样本只作初筛，不自动获得显著性。实际重复数、短运行时长、每阶段 GPU 秒数上限及提前停止标准写入实验包后再运行。

输入难度和到达率分开变化：增加 QPS 不证明任务更难；改变输出长度或预处理协议也不能伪装成同条件实验。若采用限速或资源隔离，作为明确的新资源配置，不能冒充原场景的自然竞争。

### 4.3 每条记录保留什么

- 完整 offered cohort、计划到达、输入/请求/协议摘要、模型/副本分配、成功/失败/拒绝及排空情况。
- 入队、handler 开始/结束、真实有序阶段、receipt、permit release、READY；完整 resident/active roster 和初始队列前史。
- GPU 时间若来自设备时钟，保存时钟对齐证据；host 事件不能直接宣称为 GPU kernel 边界。
- 同步的整板功率序列、startup 到 drain 的 owned 显存、活动重叠；能取得时保存 SM/DRAM/L2 计数器及采样口径，缺失不能填零。
- 原始日志及来源摘要；训练、开发和确认标签隔离。

### 4.4 完整能耗合同

正式目标沿用当前 `six_term_reference_v2`：

\[
E=J_{\mathrm{episode}}/J_{\mathrm{reference\ episode}}.
\]

episode 覆盖启动加载、priming、warmup、相同到达窗口及完整 cohort 排空；保留功率积分边界和遥测缺口。参考部署与候选保持相同任务工作量和测量协议。冻结工具及共同参考文件复用现有实现；参考未齐时 U 保持未知。

同时报告原始 J、窗口平均 W、启动/稳态/排空分量、完成工作量及每请求能量；失败、早停和少处理请求不能表现为节能成功。

整卡并发功率不直接等于各模型独占功率相加。专项检验模型身份、驻留、活动阶段和副本变化的作用；可采用有辨识依据的小模型及残差分析，不能为追求内部最优任意添加罚项。副本或专用模型能耗是否增加由测量决定，不预设严格单调。

## 五、阶段 C：共驻预测与场景资格

### 5.1 改进范围

复用已有阶段进度、生命周期、FIFO、完整资源及训练链路，优先解决匹配和可辨识性。原任务书“不重新设计 GPU 共驻与 FIFO 预测器”改为：**允许针对已确认缺陷定向改进共驻/资源规律，独立版本化并验证；不另造 FIFO 语义或同时大规模改动所有模块。**

必须检查：

1. 同输入、同部署下，另一模型由闲置变活跃或负载上升时，执行服务能否正确变化；输入子集差异不能当作干扰。
2. 阶段重叠变化后是否重新定价剩余工作；由此产生的队列和后续活动应由同一事件引擎继续演化。
3. 当前活动特征是否足够；持续竞争、缓存、资源控制或可观测前史造成系统残差时，明确补特征或限制适用范围，不宣称瞬时活动集合覆盖一切干扰。
4. 默认精确查表与可选凸插值分别验证；相同资源特征不保证相同物理速度，不跨未支持的执行/驻留身份泛化。
5. 预测阶段只能使用到达轨迹、已知输入特征和模拟产生的活动，不能使用待预测条件的实测服务或留出标签。
6. 原 rho/g(n) 及硬约束保持；声明容量服务与动态执行规律的关系，不能把原静态 rho 检查当作实测稳定容量证明。

训练秩不足、覆盖不足、域外、阶段缺失或资源未知应返回具体 UNKNOWN。训练残差小不代表留出精度合格。若新尺度可能产生负 Q，全部界重新核对，禁止继续默认 U≤0。

### 5.2 独立验证指标

分开报告同输入执行服务、Mean/P95 等待及端到端延迟、READY、goodput、峰值显存、完整能耗、六项 U、候选排序及成对效用差的误差。给出分模型、分负载和分副本残差，不能只报全条件平均误差。

在查看确认结果之前，依据开发数据声明绝对/相对误差阈值、决策所需最小效用差、重复数及不确定性计算方法。小差异要比较误差尺度与区间；预测排序不确定时输出未解决，不把点估计名次当确定结论。多路由探索带来的选择偏差须通过独立固定候选确认控制。

资源或服务的经验误差范围不能自动用作优化安全界。数学模型内部的证书与真实预测资格分别输出。

### 5.3 场景是否适合研究连续路由

至少保留容易、接近容量、热点/突发及输入难度变化的开发场景，明确每种场景的合法支持域、压力、固定资源成本和活跃竞争。场景开发依据负载、实际竞争及业务任务特征选择，不根据某算法在确认集胜出后反向挑选。

对固定部署，比较所有能覆盖当前任务的联合纯路由端点、旧 K 网格及开发阶段选出的非网格内部点。多任务中每行单独扫描不等于覆盖联合端点或连续空间。

再允许改变模型集合和副本，比较包括卸载零流量模型的合法替代部署。分别报告：

- 固定部署内部比例相对端点/旧网格的收益。
- 计入模型激活、驻留、副本及完整能耗后的联合部署收益。
- 独立轨迹上固定候选的重复性，以及开发训练得到的选择策略的确认表现。

有限轨迹会产生请求映射台阶；“稳定”关注可复现的收益区间、实际映射及分流，不要求各种子返回同一个浮点比例。偏离 K1 端点不等于偏离任意更细网格；每次明确比较的 K、候选域及比例。同映射并不保证质量、rho 和完整 U 相同。

若真实端点仍最佳，保留结论；若误差遮住小收益，结论为证据不足；若出现固定部署收益但不能支付激活成本，明确报告。不能通过改权重、削弱专用、改测量或制造干扰保证连续方法成功。

## 六、阶段 D：跨路由共享部署候选池

建议独立模块 `DeploymentCandidatePool`，不替换原优化器。

每个条目保存规范副本键、合法状态、执行/画像身份、任务能力、显存证据及其范围、发现来源/路由、历史最佳可行路由及 U、评价次数、最近改善序号、精确缓存引用。去重键例如 `tuple(sorted((m,n) for m,n in D.items() if n>0))`，不同副本不能合并。

池只复用部署结构和经证明可静态复用的事实。新路由下检查所有正流量模型有合法副本、任务可执行、simplex/QPS 守恒、原硬约束和证据适用范围，再评价当前 `(D,r)` 的完整预测。

显存必要下界通过不等于真实峰值通过；缺资源证据不认定合法或不可行。零路由不会自动卸载已驻留模型。

\[
LB_{\mathcal P}(r)=\max_{D\in\mathcal P\cap\mathcal D(r)}\widehat U(D,r)
\]

这里只取完整可评分的可行方案。无可行方案时 LB 为 `None`，区分池无兼容部署、已测不合法、未测和 UNKNOWN。池覆盖不足不等于全域无解。

配置 `pool_max_size`、`pool_selection_policy`、`pool_diversity_enabled`。保留全局 incumbent 的完整方案和结果，池淘汰不能抹掉它。以模型/副本多样性、近期性及历史表现管理容量；淘汰属于启发式，记录原因，不产生安全剪枝或全域证书。

记录 `pool_version`。淘汰、扩池及同一路由的新结果需要更新版本，防止旧下界被误当作当前池精确结果。

## 七、渐进式固定路由求解器与界

建议 `ProgressiveFixedRoutingSolver` 四层：池评价 → 有效界检查 → 限额固定路由 MILP → 对少量竞争路由继续求解。

统一结果至少包含：

`routing_shares`、`routing_qps`、`deployment`、`best_feasible_utility`、`valid_upper_bound`、`optimality_gap`、`feasible`、`constraint_state`、`certified`、`inner_search_completed`、`evaluation_kind`、`termination_reason`、`pool_version`、`milp_calls`、`full_prediction_calls`、`elapsed_seconds`。

`evaluation_kind` 至少区分池下界、有限预算内层下界、已认证固定路由值、已证明无解与证据未知。保存未知身份、未访问域、合法剪枝和历史 ledger。

### 7.1 上界、停止与证书

始终维护 `LB(r) ≤ V(r) ≤ UB(r)`；无界时 `UB=None`，不能使用经验潜力当上界。池中最好值是下界，不是全域上界。

固定路由全域 UB 必须覆盖已知可行值、未访问部署和已移出主问题的 UNKNOWN 身份。只覆盖剩余 master 或当前候选池的对偶界不够；数值余量和适用范围必须记录。

`UB-LB ≤ epsilon` 只在全域、证据及数值条件满足时给指定误差证书。发现 UNKNOWN 身份默认阻止全域认证，除非有独立安全界证明其不影响结论并明确实现该证明。全域无解需要穷尽/有效排除，池无解不能认证。

复用新效用尺度下已证明的界；缺少新证明的旧任务列界禁用。放宽为零只允许作为有依据的数学松弛，不能当服务、显存或能耗预测。

### 7.2 追加预算与状态复用

同一路由可追加预算，保留已评分结果、incumbent 和有效 ledger；所有次数和时间累计，不重置总预算。跨路由仅复用静态约束、部署及完全相同输入的缓存，不复用未经证明的反馈割。

先审计当前固定路由 MILP 是否暴露可续求解状态。若 SciPy/HiGHS 不支持暂停恢复或 MIP Start，明确采用重建 master、精确缓存和历史候选优先评价，并计入重建开销；不能宣称原生续解或真正 MIP Warm Start。

局部限额退出、全局预算耗尽、预测 UNKNOWN 和已证明无解分别返回；部分可行解始终保留，证书不能由状态合并凭空产生。

## 八、按需触发与外层 DE 的必要适配

### 8.1 三种可解释策略

- `Always-MILP`：每个新路由调用完整内层，作为原 C1 对照；相同全局预算下允许预算退出。
- `Gap-Aware`：先池评价，合法 UB 收敛则结束；与全局 incumbent 比较可证明无改善时跳过；缺 UB 用显式探索配额，不能声称数学排除。
- `Budget-Aware`：给各路由有限池评价，对未覆盖激活区域、未认证且可能竞争的路由追加 MILP，预留探索预算。

所有启发式停止保存原因；记录触发的是一次内层会话还是多次 master 求解，分开计数。池很大时允许评价子集，但相应结果仅为子集下界，不能伪称池最优。

### 8.2 现有 DE 不能直接接收渐进结果

当前 `DERoutingOptimizer` 遇到未完成/未认证内层会停止，且会记住已访问的精确路由。**仅增加状态字段不足以让 C1-Lite 正确运行；不得取消检查后把 LB 当精确 V 交给原 SciPy DE。** 保留原 DE 作为 exact-inner 基线。

第一版实现独立的渐进 DE 控制器，复用现有 simplex、DE 提案和端点逻辑，采用以下明确语义：

1. 主问题仍为 `max V(r)`；预算不足时，外层使用当前池/已发现部署给出的启发式可行下界排序，结果标记 `lower_bound_guided`，不声称精确 V 优化。
2. 每次 DE 选择记录 parent/trial 的 LB、UB、池版本和认证状态。区间重叠且有预算时，按触发策略细化；区间仍未分离时使用预声明的可行 LB 比较规则，记录为启发式选择。
3. 池扩展后，参与下一次选择的旧种群成员及 trial 必须更新到同一比较版本，或有完整已认证结果；重评成本计入预算。预算不足则保留 incumbent 并明确停止，不能拿陈旧低估拒绝新候选。
4. 已访问路由若未认证，允许重访与预算升级；缓存包含精确路由、版本和求解精度，不能被原 DE 的一次访问去重永久冻结。
5. UNKNOWN 没有数值目标，不填零/负无穷，也不等同已证明不可行。只把已确认可行结果用于 incumbent。

该控制器是独立启发式，不称为 BO、MADS 或具有 DE 收敛保证的精确替代。另保留“小域全部内层解完”的模式，与原 DE 对照结果和成本。

## 九、激活边界

\[
\Lambda_m(r)=\sum_t\lambda_t r_{t,m}.
\]

严格正流量要求合法正副本；总流量恰为零允许不部署，但不强制删除驻留模型。不设隐藏 epsilon，也不只按某一任务行判断激活。

支持多 G、多 S、共享任务及多任务共享模型。显式调度合法端点、重要低维面和内部提案，避免全部预算耗在端点初始化；预先配置各部分预算，报告总覆盖、实际访问和截断原因。比例始终连续，不量化回旧 K 网格。

激活基础处理与高效激活区域搜索分开验收；当前不提前开发 BO/MADS。

## 十、C1-Lite 与 Hybrid C1

### 10.1 C1-Lite

不调用 Joint 初始化。从合法声明部署或固定路由内层建立池；外层每个提案先查兼容池及缓存，再依策略调用渐进内层。发现的新可行部署扩池；记录其他已知/未知结构时保留其状态，不能赋予可行资格。

始终返回整个搜索过程最佳可行 `(D,r,U)`，不因当前池淘汰、内层超时或最后一次提案失败而丢失。报告内层下界引导程度及未解决区间。

### 10.2 Hybrid C1

在 C1-Lite 验收后，使用低 K Joint 初始化少量不同部署，默认从 K1 开始，允许配置。优先一个 seed，额外候选按已有排除接口和剩余预算生成，不把重复残余 Joint 成本藏起来。

Joint 初始方案及精确原路由主动进入外层候选；初始化、构列、MILP、预测、画像会话和缓存建立全部计费。初始解失败时采用预声明的 C1-Lite 回退或明确失败，不能用诊断分数充当可行解。

Hybrid 与 C3 的区别是：连续路由期间可以按需搜索池外部署。对池外发现记录来源、发现时刻、当时剩余预算、重新预测、激活成本及新增 U。发现不同部署本身不证明动态扩池有用；通过关闭扩池的同初始池对照判断价值。

是否继续 Hybrid 由 C1-Lite 的效率/质量证据决定；未通过时给原因，不自动追加复杂机制。

## 十一、精确缓存与统一预算

完整结果缓存绑定问题/效用及参考摘要、预测源码/画像/执行身份、部署及副本、精确连续 QPS、全部轨迹和输入映射、场景策略、H/drain、资源和原容量规则。路由级求解缓存额外绑定部署域、池版本、界版本、认证及未完成精度。

区分结果身份和预算：改变预算不能让未完成结果变成已认证；同一完整候选预测可在身份相同时复用，不必因剩余预算变化重跑。近邻比例、相同请求计数都不构成完整等价。

若复用已有精确 FIFO 映射缓存，必须保持完整活动/输入/部署/情景身份，并对每个比例重算 Q、rho 和相关完整成本。不能把整个 score 当映射缓存。

统一配置至少包括总秒数、完整预测数、外层提案数、master 求解数、内层会话数、局部时间/预测限额、池容量、Joint 初始化候选数、端点/内部探索份额和种子。非抢占调用超时计入实际 wall，不截成预算值。

初始化、构界、重建、HiGHS、预测、池管理、重评、缓存和外层搜索全部计时；互相嵌套的计时扣重。预测 bundle、压力叶子和实际事件引擎次数分列。离线训练/实测成本与在线优化成本分开报告，优化前付出的各算法准备成本仍须可追溯。

## 十二、公平比较、消融与输出

### 12.1 基线

| 算法 | 用途 |
|---|---|
| 原 Joint K1 及预声明更细 K | 有限域基线；保留容易场景 |
| 原 C1：DE+每路由固定 MILP | exact-inner 基线 |
| C1-Lite | 池复用及按需搜索 |
| C3：Joint 多候选+固定部署连续精修 | 候选覆盖与固定部署对照 |
| Hybrid C1 | Gate 通过后研究 Joint 初始化和动态扩池 |
| 小域固定路由完整枚举 | 内层正确性和界的独立参考 |

同一比较固定模型池、合法副本、能力/质量证据规则、稳定性、显存预算、效用/参考、预测器、轨迹、输入和种子集合，采用可比总时间与完整预测上限；各算法都能使用相同公共预测缓存能力。旧域结果、新实测预测结果、合成软件结果分别报告。

先小域，再按资格扩展三/五/七模型；模型数本身不是难度证明。记录有效部署数、路由维数、竞争下界、共驻覆盖及实际负载，不用不受支持的规模制造比较。

### 12.2 必须消融

1. 无池、每路由完整 MILP；有池、仍完整 MILP；有池、按需 MILP。
2. 启发式 LB 引导与小域 exact-inner；旧种群重评开启，任何关闭版本仅作失效反例。
3. 三种触发策略；池容量/多样性；探索配额；固定路由预算升级。
4. Hybrid 阶段：有/无 Joint 初始化，同一初始池有/无动态扩展。
5. 预测诊断：旧固定服务、新精确阶段上下文、可选插值；只在各自合法域比较误差，不把预测器换代收益归功于算法。

至少先用两个开发优化种子和一个未用于参数选择的确认优化种子做小范围检查，再按不确定性决定重复数。到达种子、优化种子和采集重复轮次分别记录。确认集不得反馈赢家选择。

### 12.3 指标与图

输出最终最好 U、六项原始量和贡献、固定部署/联合收益、达到共同 U 阈值的时间及实际是否达到、总 wall、预测/叶子/FIFO 次数、master/内层会话数、触发比例、池评价成本、池命中/兼容/评价比例、扩池与淘汰、认证率、UNKNOWN、启发式选择数及稳定性。

未达到阈值的运行标记未达到，不用预算秒数冒充达标时间。最终 U、成本、覆盖和证据资格一起比较。

保存 Best U–时间、Best U–预测数、MILP–外层评价、池规模、触发策略、池外发现与 U 改善、路由–服务/等待/能耗及各副本负载图。原始 JSON/CSV、协议、失败记录、源码/数据摘要和绘图脚本一并保存。

## 十三、验收与停止标准

| Gate | 必须回答的问题 |
|---|---|
| G0 数据与目标 | 执行身份、数据角色、完整阶段/资源及 v2 参考是否合格？缺项能否定位？ |
| G1 预测资格 | 是否独立预测了动态服务、FIFO、完整能耗及决策相关的排序？支持域和误差是否清楚？ |
| G2 场景资格 | 是否覆盖专用受压、共享 G、输入难度和副本/资源权衡？内部收益存在/不存在/未确定能否区分？ |
| G3 软件正确性 | 池去重/淘汰、缓存、界、UNKNOWN、渐进恢复、DE 重评、激活及全局预算是否通过反例和枚举？ |
| G4 C1-Lite 价值 | 同预算解质量是否保持或改善？达到共同 U 的端到端成本是否下降？代价转移到池评价没有？ |
| G5 Hybrid 价值 | 初始化是否值得？是否发现池外有效部署？同初始池扩展对照是否支持收益？ |

软件验收允许合成反例，真实结论必须通过 G0–G2。必须覆盖：负 Q 下界、新路由使旧部署不可行、零流量仍驻留、多任务总激活、不同副本去重、池淘汰不丢 incumbent、未认证缓存升级、UNKNOWN 阻止假证书、全域 UB、局部限额与全局限额、扩池后旧 DE 成员更新。

若 C1-Lite 节省 MILP 却增加预测或总时间，不能算端到端加速；若更快但解质量下降，报告权衡。若真实连续收益未成立，不宣布新算法失效或成功，先区分场景、预测和搜索覆盖。没有明确收益时停止扩复杂机制，保留负结果。
