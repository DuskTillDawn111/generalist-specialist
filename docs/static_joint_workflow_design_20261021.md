# 保留模型池的静态联合部署流程设计

本文是基于现有代码和本轮资源画像的下一阶段设计，不是已实现功能或已完成的系统实验。
本版按用户追加的五项要求修订：质量进入总效用、移除绝对质量准入、限制 GPU 比较次数、
用同域 DFS 核验最优性和效率，并联合优化通用/专用的任务分流。
按已确定的七模型、四任务保留池推进，不重做模型筛选。历史准入结果保留为历史证据。

目标是在每个给定配置池、同一个静态任务负载下，联合选择部署模型、副本数和任务分流，
输出该声明搜索域内的最优方案及可核查的最优性差距。纯通用、纯专用、混合由求解结果决定。

## 1. 现有架构可以保留什么

- `system.py::DeploymentSystem.plan` 已统一配置、联合 MILP 和完整方案预测。
- `milp.py::JointMilpOptimizer` 已有副本状态变量、任务路由列、完整方案反馈、上下界与预算状态。
- `trace.py`、`routing.py`、`prediction.py`、`runtime/` 已共享到达轨迹、副本展开与加权轮询。
- `performance.py` 已支持完整部署/路由条件下的冻结共驻服务画像。
- `energy.py` 已按整方案查询能耗；`evaluation.py` 已实现旧五项效用与实测证据检查，需扩展质量项。
- 现有搜索允许模型零副本，没有必须保留通用或专用的条件。

因此延续“联合 MILP → 完整方案评价 → 反馈 → 再求解”，增加新画像转换和实验调度层。

## 2. 每次求解的输入与输出

固定问题身份：配置池 P、允许的模型配置及经验证可执行的任务路径、四任务绝对到达率 λ、
任务输入池与输入顺序、GPU/软件环境、显存预算、H、排空时间、到达过程、种子、
预热规则、效用权重与参考值、启动摊销 A、副本域及路由域。

静态负载指部署期间 λ 和任务组成不变；固定种子的 Poisson 到达仍可属于静态负载。
不同部署必须接受同一批计划请求，不能按各自最大吞吐重新设定需求。

决策保持为：

```text
x_m ∈ {0} ∪ 本轮声明允许的副本状态
r_tm ≥ 0
sum_m r_tm = λ_t
r_tm > 0 ⇒ x_m > 0 且模型 m 可以服务任务 t

minimize C(x,r) = w_Q*Q_loss + w_T*T_loss + w_L*L_norm
                  + w_P*P_norm + w_M*M_norm + w_E*E_norm
U(x,r) = -C(x,r)
sum(weights) = 1
```

建议首版六项等权，即各 1/6；这是待采用的研究参数建议，不是用户已确认的权重。
也可事先指定 w_Q=β，其余五项各 (1-β)/5。参数在候选比较之前固定，不能追着胜出结构调整。

移除 EM/accuracy 下限、CER/WER 上限等绝对质量准入，低精度路径通过 Q_loss 影响排名。
路径可执行、质量记录可追溯、数据/协议匹配与运行有效性继续检查；缺质量记录不能当作零损失。
专用相对通用的质量优势是模型池的实测性质，不再为每个部署附加一次质量优势准入条件，
也不能依据模型角色直接赋予更高分数。

约束包含输入覆盖、可执行路径、显存、运行有效性和稳定性。
`rho<=0.8` 在现有独立服务模式中是规划边界，不能由单任务闭环结果直接升级为混合部署容量认证。
共驻模式需使用适用的容量证据，并保留实际积压和稳定性检查。

输出至少含部署、副本、逐任务分流、六项原始指标及贡献、U、运行/证据有效性、
搜索域身份、画像版本、最优性上界与 gap、停止原因。结构类型只在求解后统计。

### 质量项的定义和路由相关性

使用任务原生误差统一为“越低越好”的损失，百分比先除以 100：

```text
text:  e_tm = 1 - EM_tm          # F1 继续单独报告
image: e_tm = 1 - accuracy_tm
ocr:   e_tm = CER_tm
asr:   e_tm = WER_tm

α_t = λ_t / sum_t λ_t
p_tm = r_tm / λ_t
Q_loss_proxy = sum_t α_t * sum_m p_tm * e_tm
```

CER/WER 可以大于 1，不在计算中截断。六项等权不保证六项实际贡献同样大，需报告分项尺度。
该混合公式用于同分布、与输入难度无关的路由预测。固定轨迹的精确质量应重放实际路由，
按每个输入被分给的模型查询已保存输出并评分：QA/图像按请求计数，
OCR/ASR 分别汇总编辑错误数与参考字符/词数后计算 CER/WER。
不能对不同样本长度的 CER/WER 简单取算术平均，也不能用完成请求重新选择任务权重。

质量表可复用已有离线输出，不需为每个 CPU 候选重新跑模型。
路由执行看不到标准答案；标签只用于离线评分。随机输出或副本输出不一致时，
记录质量变异并验证复用范围，不能无条件把单次 n1 输出当成所有部署的确定输出。

若专用质量损失低于通用，给通用分流会增加质量成本，但可能降低排队、尾延迟和能耗，
算法通过六项净收益决定分流比例。

当前实现需要同步更新：`config.py` 强制 Q=0；`prediction.py::components` 未计算质量；
`evidence.py`、`evaluation.py` 及 profiling 的系统入口仍检查旧绝对阈值。
需新设质量证据验证契约，并将 `supported_tasks` 从“旧质量已准入路径”改为本研究的可执行路径。
旧实验不覆写；新六项目标使用独立 schema、目录与证书。

## 3. 把新画像接入时必须处理的差异

本轮 `artifacts/retained-replica-profiles-20261021/combined-summary.json`
记录了 16 个模型—任务组合、61 档完成画像和 6 档实测失败。
它测量的是同模型、同任务、每进程一个在途请求的闭环资源曲线。

### 任务相关的副本收益

现有 `capacity_factors[m][n]` 假设同一模型各任务共用副本容量系数。
新数据中 MiniCPM QA 的两副本吞吐约为单副本 0.87 倍，ASR 却约为 1.55 倍。
不能把 ASR 的系数套给 QA，也不能取最好一条曲线代表所有任务。

新目录应保留 `(模型配置, 任务, 副本数)` 的原始服务样本、吞吐、驻留、峰值和适用输入身份。
初始独立预测可以使用任务相关曲线辅助提出候选；多个任务共用通用副本时仍需混合任务画像。
在缺少混合画像时，由独立曲线推导的压力只能用于预测和实验优先级，不能排除潜在最优共驻组合。

### 通用副本共享

同一通用模型的四任务 execution 配置经核查一致，可以据此准备一个支持四任务的 worker，
同时合并并核验各任务的协议、提示词、解码和输入绑定。
同一副本共享任务队列、只加载一份权重、显存只计算一次。
不能把四条单任务画像展开成四份通用权重后称为一个通用副本。
多任务预热后的缓存驻留和峰值需要重新测量。

### 副本域与显存

单任务可行副本数不等于混合部署可行副本数；单任务失败也不能无条件排除其他任务组合。
吞吐平台停止的更高副本档位属于未测状态，不是已证明无益或不可行。
如果首轮只研究单副本或有限副本域，应在所有配置池中按预定规则声明域，再逐步扩展。

显存评分的驻留成本与加载/运行峰值约束分别记录。
单任务驻留表之和可以辅助准备实验，不能替代完整共驻的资源核验。

### 能耗与尾延迟

闭环饱和功率或 J/request 不能直接当作固定开环负载的整方案能耗，也不能跨模型相加。
沿用完整 GPU 板卡积分和统一启动摊销：

```text
E_norm = (J_run/H + J_once/A) / P_ref
```

现有 `performance_mode=profiled` 仍用任务常数服务时间进行 FIFO 预测。
即使该常数来自实测均值，也没有保留输入相关服务尾部。
若要研究实测六项最优，应直接接入完整方案的实测统计；若研究预测最优，
应扩展到按输入关联的服务样本或冻结的分布模型，并单独报告其误差。

## 4. 增加方案评价与补测闭环

建议增加一个可替换的完整方案评价接口，统一返回如下语义：

```text
evaluate_plan(problem, deployment, routing, evidence_version)
  → SCORED: 完整六项分数与适用证据
  → INFEASIBLE: 对当前条件有效的失败证据
  → NEEDS_MEASUREMENT: 缺少哪些证据、待测方案身份
  → UNRESOLVED: 运行基础设施失败或测量无效，需重试/处理
```

通用请求错误不自动等同物理不可行；缺失画像不自动等同分数低。
继承现有 no-good 约束的作用域：一条失败路由仅排除证据支持的完整方案身份。

调度流程：

1. 冻结保留池目录和一个静态问题，预生成到达与输入清单。
2. 用已有画像与离线质量输出生成候选优先级，补充适用的混合任务/共驻测量。
3. MILP 联合提出部署和路由，由评价接口查冻结的适用证据。
4. 缺证据时保存待测队列、候选界和求解检查点；GPU 串行运行对应的固定开环负载。
5. 保存原始请求/输出、整卡功率、驻留与峰值、积压、错误及启动成本，使用六项公式评分。
6. 在新证据版本中加入结果，重建或恢复相应主问题，再求解。
7. 达到预设 gap 后结束；预算耗尽则保留最佳已知方案和未决范围。

当前求解器对未知画像只登记 `unknown_lower` 并移出当前可评分子问题，尚未实现步骤 4–6。
补测后应重建/恢复候选，不能永久沿用因“未知”加入的排除约束。
画像或预测模型发生变化时，旧评价切割及上下界也必须按版本失效或重算。

未知候选仍保留在全域最优性计算中。已无竞争力且有有效界的候选可以不测；
若界不能排除，必须补证据或保留未决状态。
只实测预测排名前几名，可以得到经验证的候选，但不能单凭此证明真实全域最优。

不要求穷测混合部署，也不建议完全跳过混合部署实测。
至少应验证胜出的混合方案及其关键分流对照；否则共驻干扰、排队和能耗的主要结论仍仅来自预测。
已有画像和最终验证可以覆盖部分条件，只补缺少且影响决策的证据，不重做全部单模型画像。

### 混合补测的首轮内容和预算

首轮只针对已固定的静态负载，先给全模型池共用的 6–8 个完整运行条件作为探索性校准预算，
每条件先运行一次；这些单次运行不是最终独立重复验证。正式比较另按第 7 节计数。
校准优先覆盖以下缺口，并对相同实验身份去重：

- 单个通用副本同时服务多任务：检查跨任务阻塞、任务切换、预热缓存及实际工作集。
- 通用与专用共驻并同时接流：优先选 CPU 初步搜索认为有竞争力的组合，覆盖不同任务开销和副本数。
- 同一候选部署的不同分流：选择专用接近拥塞、通用尚有余量的条件，比较不分流和候选分流。

先用已有单任务画像及少量参数的干扰/功率代理描述新测条件；不以 6–8 个点拟合任意全组合
独立参数或完整两两交互表。可按负载、活跃进程数、任务组成等固定特征挑覆盖点，
后续由验证误差和可能改变最优解的候选决定补点。
该预算用于先检查模型是否足够，不保证一定足以覆盖全池，更不是严格物理最优证明的测量上限。

每个完整运行使用相同绝对到达率、输入绑定、H、预热和排空规则，保留请求队列时间、
端到端延迟、任务混合、运行峰值与驻留、整卡功率和启动电量。
校准点用于建模，最终排名用未参与拟合的运行检验。
校准结果跨配置池复用，但不能超出其适用任务、负载和部署条件。

在进入 MILP/DFS 一致性和计时实验前冻结代理版本；自适应补点若更新代理，
所有候选、搜索界和算法对照都应在新版本下重算。

### 搜索界需要随质量目标更新

保留损失形式使 C>=0，现有基于非负成本的反馈结构可以扩展。
任务列加入该路由的精确质量成本或可证明的质量成本下界；未确定路由使用可行接收路径的
最小质量损失下界。若不能证明某个更强下界，放宽该项为零只用于数学界，不能用于候选评分。
精确列质量、显存和服务下界可共同收紧主问题，提高排除低质量低时延候选的效率。
MILP 与 DFS 的最终评分、剪枝界、诊断状态、缓存身份和最优性证书必须统一改为六项目标。

## 5. 两类最优结论分别如何取得

### 冻结预测模型下的有限域最优

冻结完整的性能/能耗预测器及其适用范围，在声明的副本与路由域内运行现有 MILP。
下界和反馈必须对该预测器有效；预测不确定性在实测验证中单独评价。
通过证书后，可以声明“该冻结预测模型、有限搜索域内最优”。
未经测量的独立服务均值、显存或能耗拟合不能直接充当实测问题的严格界。

### 冻结实测表下的有限域最优

先定义完整方案的重复测量、统计汇总和失败处理规则，再把实测 U 作为评价返回值。
候选必须被完整评分、有适用证据排除，或被数学有效的界剪枝，才能给出该实测表上的证书。
对成本 C=-U，非负分项允许从零构造安全但较弱的下界；更强的内存/服务下界需要另外证明。
物理实测目标下，现有常数 FIFO 的服务下界、容量约束和跨部署路由反馈不能直接照搬。

```text
U_best = 当前最佳完整可评分方案
U_upper = 全部未决候选的有效效用上界与已知最优值的最大值
gap = U_upper - U_best
gap <= 预先约定的 ε ⇒ 声明域与评价规则下 ε-最优
```

噪声实测表的数学最优不等于硬件真实期望效用的无误差证明。
最终候选应使用未参与选择的种子/运行独立复测，报告排名是否稳定及差异的不确定性；
每个复测种子内各方案仍使用相同输入和到达轨迹。

### 推荐的两层验证与有限实测停止

完整候选域在 CPU 上搜索并与 DFS 核验；少量 GPU 运行验证胜出组合及强竞争组合。
CPU 证书证明冻结评价器和有限域的最优，GPU 比较验证评价器选出的方案能否在硬件上保持优势。
两类证据分别报告；DFS 与 MILP 得分一致不能自动证明预测器准确。

如果需要进一步声明实测期望效用的 ε-最优，需有对全部未测候选有效的界。
记胜出方案实测效用的保守下界为 L_best，其他候选有效上界为 UB(c)，仅当
`max_c UB(c) <= L_best + ε` 才能停止并给出该意义下的声明。
统计界应采用预先约定的同时覆盖或适用于自适应选择的规则；普通预测残差区间不自动具有全域保证。
如果这些界仍允许某个未测方案更优，应优先测它；预算用尽则保留未决 gap。

少量黑盒实测无法无条件保证任意未知组合都更差。可控实验预算与严格物理全域最优之间，
必须通过有效结构假设、经过验证的评价模型或更多测量建立联系，不能靠挑几个对照替代证明。

## 6. 不同配置池的公平比较与搜索审计

以已经约定的配置池定义为输入，不用历史 A/B/C 目录中的旧模型和旧任务参考代替新池。
每个池允许部署其任意合法子集；扩大候选池不要求增加实际部署模型。
所有池共享静态负载、质量评分协议、参考值、硬件、路由规则和相同配置的副本域。

对同一池，可额外求“仅通用”和“仅专用”两个受限问题作为对照；混合类有需要时也单独求解。
全池自由求解的结果应不劣于任何可行受限解。受限解可以作为初始可行解，但不限制自由搜索。
受限类不可行就报告不可行或证据未决，不通过更改条件制造可比得分。

需要自动校核：

- 小规模冻结域：MILP 与独立穷举的最优分数一致，兼容并列最优。
- 嵌套池：P1⊆P2 且同一方案评价不变时，应有 U*(P2)≥U*(P1)。
- 路由细化：域真正嵌套时，扩域的最优分数不得下降。
- 对实测失败、未知证据和预算耗尽，分别给出正确状态，不能误报完整最优。

现有容量见证是每次求解生成的额外路由点，不天然保证跨配置池/不同 K 的域嵌套。
严格审计时可先关闭见证使用纯网格；正式比较则冻结并继承适用的见证点。

当前 `energy_key` / `profile_key` 将完整 catalog 纳入身份，裁剪配置池会改变同一部署的键。
应另设按“实际部署配置 + 实验条件”绑定的测量身份，完整绑定 GPU、输入/轨迹、
worker/协议/代码、预热及测量窗口等条件，再将测量结果适配到各池的规划键。
这样既能复用同一方案的合法测量，也避免把未部署候选的增删误当成性能变化。

## 7. 少量 GPU 对照的选择规则

对照从全部合法候选域中产生，不能只在纯通/纯专两个结构标签中选择。
建议每个“配置池 × 静态负载点”先选至多 4 个去重方案：

1. 自由联合搜索的胜出部署与路由。
2. 部署向量不同的最强竞争方案：排除胜出部署后，重新优化副本/路由。
3. 同一部署下、路由不同的最强竞争方案：排除胜出路由后重新优化。
4. 禁止同任务跨模型分流后的全域最优，作为分流消融。

第 2/3 项允许与其他项重复，重复只测一次；第 4 项若与胜出方案相同则不增加作业。
分流消融可另在胜出部署固定条件下重算，通常由 CPU 评价先解释；
需要直接验证队列分流时，可在相同预算内优先纳入该固定部署对照。
最多再留 1 个自适应名额，给仍可能击败当前方案、有效上界最高的未测候选。
因此初始最多 4 个、含自适应最多 5 个不同方案；这是建议的首轮预算，不是最优性保证。

“第二名”必须经过额外搜索获得，不是取求解器访问历史中的第二个分数。
必要的排除约束只能改变对照子问题，不影响原自由问题的证书。

建议每个方案使用 3 次配对的独立运行，并预先统一 H、输入、到达种子和测量顺序规则。
最多 5 个方案 × 3 次即 15 个完整运行，另计事先明确的资源校准作业。
报告不同方案数、完整运行次数、GPU 时间和实测总成本，不能把重复次数藏在“5 次对比”中。
所有池对相同实验身份共享测量记录，避免重复 GPU 作业；算法效率比较中的缓存规则另行统一。
若复测后胜者变化，选择流程需要重新验证，不能反复挑选同一份确认数据而仍称独立确认。

## 8. 同域 DFS 正确性与效率基线

现有 `optimizer.py::UtilityOptimizer` 是带剪枝的 DFS 参考，可作为改造基础，
但目前只支持独立服务；其额外容量边界路由与 MILP 见证的生成规则也不同。
不能仅把配置的 solver 改为 dfs 就称为完整公平对照。

新增共享的不可变域清单：模型配置、允许副本状态、路由有理数网格和预先生成的公共见证点。
首轮可关闭两边额外见证，仅比较纯网格；以后使用同一冻结见证集。
两边共享六项评价契约、输入/轨迹、可行性条件、画像版本、数值容差和并列最优规则。
DFS 独立遍历部署及任务路由，避免直接复用 MILP 的列生成器作为唯一正确性来源。

小域同时跑简单完整 DFS 和主算法，比较最优 U 与并列解等价性；
中等域用已有思路实现有效界剪枝 DFS 作为更强的效率基线。
最优 U 一致即可，存在并列最优时不要求部署字典完全相同。

记录总墙钟时间（包括建模/建列）、首次可行解时间、首次达到最终最优值时间、
完成最优性证明时间、完整评价次数、访问状态、峰值内存、固定时间下的 gap。
完整评价缓存采用相同规则；使用各自新建的冷缓存比较主结果，热缓存作为补充，
不能让后运行的算法无偿继承先运行算法的全部缓存。
GPU 运行记录按实验身份共享，搜索效率不通过重复 GPU 作业衡量。

逐步增加可用模型数、副本档位和分流网格精度，重复计时并报告中位数与离散程度。
同样有限预算耗尽时比较当前最好 U 和证书 gap；DFS 未完成就不能说已经验证全域最优。
MILP 小域可能因建模开销更慢，优势是否出现、出现在哪个规模由结果决定，不事先设定结论。

## 9. 通专联合分流能力

现有 MILP 在 K>=2 时枚举同任务多个接收模型的正流量列，FIFO 预测会计算共享队列等待，
所以能够主动选择将部分专用任务交给通用的固定比例，而无需先写死“优先专用”。
K=1 只能选择单路径；固定部署后只优化路由和部署/路由联合优化均应验证。
通用同时处理其他任务，须把这些任务的等待代价也纳入完整六项评分。

对候选分流量 δ，用完整方案评价 U(r+δ) 与 U(r)；只有减少的性能/能耗成本
超过增加的质量/资源成本，才应选该分流。可行性约束还应防止把拥塞简单转移给通用。

2026-10-21 CPU 合成检查（不是新池 GPU 结果，也尚未包含质量项）：
固定一个通用副本和一个专用副本，QA 到达 4.8 req/s，图像 3 req/s；
QA 的通用/专用服务常数分别为 200/160 ms，图像仅通用可执行，服务常数 50 ms。
Poisson、seed=42、H=120s、K=4、关闭 MILP 容量见证。
现有求解器主动选择 QA 给通用 1.6、专用 3.2 req/s（通用接走 1/3），
四项旧目标 U 从同部署全给专用的 -0.253116 改善至 -0.152641。
该检查说明已有静态搜索能识别“较慢但空闲的通用接流”；新六项最优比例需加入真实质量后重算。
另用独立递归 DFS 枚举完全相同的固定部署路由网格，7 个叶子中 5 个通过容量检查，
所得最优 U 与 MILP 完全一致。单次计时约 MILP 1.28s、DFS 0.12s，仅说明此小例子的
建模开销较明显，不作为正式效率基准或新六项目标的正确性结论。

补充的等权五项目标检查与六项离线算术保存在
`artifacts/static-design-check-20261021/synthetic-quality-split.json`。
固定部署与服务条件同上，给所有候选设相同的合成整卡能耗；七个有理数网格比例中五个满足容量约束。
现有 MILP 在五项目标下选择通用接走 25% QA，请求路由独立枚举得到同一最优 U，状态为
`OPTIMAL_MILP_FINITE_DOMAIN`。
再假设 QA 通用/专用错误率为 20%/5%、图像通用错误率为 10%，以六项各 1/6 离线重算所有合法路由，
最佳比例仍为通用 25%。相对全部 QA 给专用，QA mean 从 367.50 ms 降至 222.56 ms，
P95 从 882.40 ms 降至 387.81 ms，六项离线 U 从 -0.236821 提高到 -0.223655。
这里的质量与能耗是说明权衡用的假设值，不是保留模型的新测量；六项重算在求解器外进行，
不能据此声称生产求解器已支持质量目标，也没有验证完整部署域或效率优势。

当前 `routing.py::Router` 是固定权重轮询，不读取实时队长。
本阶段先做静态负载下的最佳固定分流；运行时实时感知队列是另一个策略扩展，
必须重新定义路由策略域并同步预测与执行，不能将现有功能描述为已实现动态卸载。

## 10. 建议实施顺序

1. 接入新池目录、worker 与任务相关画像；将旧绝对质量准入改为质量证据验证。
2. 实现六项质量效用，更新 MILP/DFS 的目标、界、证书与运行评分。
3. 固定共享候选域，完成 DFS 最优一致性、质量/排队权衡及主动分流的 CPU 验证。
4. 接入评价接口与去重实验队列，在预定小预算内验证完整部署及关键分流对照。
5. 对各池输出自由最优、强竞争方案、六项指标、gap、效率和实测不确定性。

本阶段先完成一个固定负载下的闭环与可审计最优性。后续负载强度或任务比例变化时，
每个负载点建立独立静态问题并沿用同一流程。
