# 预测器转向整体决策验收：文献与实测复核

用户最新指令是“整体的预测差不多就行”，不再以消除每个阶段的波动为目标。本文文件名沿用会话日期 2026-11-05；采集机器 UTC 时间与会话日期不同，实际执行时间见 JSON 收据。本次是已查看历史数据的描述性复核，不是新盲测，也不修改任何旧 FAIL。

## 判断

**已有部分预测足够支持限定范围的候选筛选。继续把逐阶段误差全部压过门槛，收益已不明确。** 真正需要补的是当前五模型运行域、持续到达、完整生命周期能耗及方案选择效果；无需先证明每次 first-forward 都能准确预测。

尤其要区分两个量：

- 逐请求相对误差的 P95：`quantile(abs(pred_i-obs_i)/obs_i, .95)`。
- 整体 P95 时延的预测误差：`abs(quantile(pred,.95)/quantile(obs,.95)-1)`。

前者可能很大而后者很小。二者分别衡量逐请求配准与尾部统计，不能互称。聚合误差又可能掩盖任务退化，因此仍按任务、负载、候选及独立运行分别报告。

## 我们已经有的证据

重新读取三个历史独立验证包、核对其六份 raw SHA-256，并检查全部 4868 条请求身份完整无重复。使用线性经验分位数；旧报告自己的分位算法和判定单独保留。可复跑工具为 `experiments/review_activation_aggregate_accuracy.py`，输出为 [aggregate-review-v1.json](../artifacts/predictor-practical-review-20261105/aggregate-review-v1.json)。不能把 4868 条相关请求当成 4868 次独立实验。

下表是单 OCR、terminal-time-scaled 候选两轮共 1424 请求的合并描述；误差取绝对值，未平均两轮 P95：

| 路径 | 平均时延预测误差 | 整体 P95 时延预测误差 | 逐请求 MARE |
|---|---:|---:|---:|
| ASR | 0.03% | 1.57% | 5.58% |
| image | 4.29% | 1.54% | 9.28% |
| OCR | 1.95% | 4.60% | 9.84% |
| text | 1.41% | 4.37% | 16.88% |
| 全部 | 1.37% | 0.97% | 10.40% |

两轮分别看：整体 mean 误差 1.66% / 1.07%，整体 P95 误差 2.29% / 2.09%；所有单任务单轮 mean 误差不超过 4.38%，P95 不超过 5.58%。所以结果不只是两轮合并后抵消。text 逐请求误差尾部仍较差（原报告约 55.35%），但整体 text P95 没有相同幅度的偏差。这是应该减少局部过度优化的直接证据。

原有界年龄单 OCR 候选合并 mean/P95 时延误差也仅 3.96% / 0.90%；不是只有最后一个候选聚合后看起来较好。双 OCR 候选合并为 8.08% / 9.43%，但 image 分任务达到 18.86% / 21.15%，显示仍需保留任务分层。双 OCR 的第一、二轮 image mean 偏差分别 16.26%、21.65%，不以总体平均遮蔽。

能耗也已有可用部分：

- terminal-time-scaled 单 OCR 的条件 FIFO 能耗两轮误差 **3.54% / 1.21%**；双 OCR 为 **5.66% / 6.39%**。它们使用真实 priming 前缀、固定 controller gaps，预测批次及后续 idle-age，因此不等于从冷启动起的自主完整 episode 预测。
- 更早的独立条件能耗模型使用真实阶段暴露，整段误差 **11.58% / 11.48%**，长空闲窗口误差不超过约 **5.61%**。它证明功率/空闲模型的一部分有效，不能代替 FIFO 时间预测。
- 当前五模型观察器四轮 656 请求已通过观测和输出一致性检查，属于测量基础可靠；当前新 runtime 的完整共驻预测精度仍未知。不能把观察器重复性或稳定 band 比例叫作预测准确率。

适用范围：以上主表是旧“四专用、单 OCR”受控批次运行；“独立”指原实验声明的独立采集轮次，并未在本次新增审计其全部训练输入隔离。历史数据已看过，后续协议按开发证据处理。当前五模型域、连续到达吞吐、完整启动能耗和候选排序仍需新证据。

## 论文实际上做到什么

1. **[iGniter](https://arxiv.org/html/2211.01713v1)，TPDS，DOI [10.1109/TPDS.2022.3232715](https://doi.org/10.1109/TPDS.2022.3232715)**。Sec. V-B / Fig. 13 报告四工作负载共驻时推理时延预测误差 **1.53%–5.02%**；改变资源份额或 batch 时也有约 **7.61%、9.29%** 的误差。其条件是 V100、Triton、MPS 资源份额，以及 AlexNet/ResNet-50/VGG-19/SSD 等四类模型。不是动态生成任务、任意输入与任意共驻的逐请求精度保证。模型显式考虑 GPU 调度、L2 与功率/频率竞争；系统另有监控 P99 和 shadow process 的纠偏机制。可学“低维可测干扰模型 + 实测纠偏”，不应复制硬件系数或把论文误差作我们的强制目标。

2. **[InferLine](https://arxiv.org/abs/1812.01776)，SoCC 2020**。Sec. 4.2 用单模型画像、到达 trace 和离散事件模拟预测含队列的端到端分布；Sec. 7.2 / Fig. 8 比较四个实验中的实测与预测 P99，并关注可行方案是否满足延迟目标。在线 tuner 用多时间尺度流量 envelope 应对到达变化。论文没有据此保证任意 FIFO 请求的等待时间都精准。可学“验证最终尾部与可行性 + 已知到达表优先 + 偏离后滚动校正”。本项目多进程/READY/reader 等额外语义仍需自己的测量。

3. **[Clockwork](https://www.usenix.org/conference/osdi20/presentation/gujarati)，OSDI 2020**。Sec. 4.4 明确每张 GPU 同时只运行一个 EXEC；通过控制内存与执行调度减少不确定性。摘要的 **99.997% 满足 100 ms 目标**是服务达标率，不是干扰预测准确率。Fig. 10 另报告动作及排队完成时间误差。可学执行边界明确、性能画像更新和异常恢复；不能要求我们的同时共跑系统具有它的隔离条件，也不能为追求重复性直接取消研究所需的共驻。

4. **[AlpaServe](https://www.usenix.org/conference/osdi23/presentation/li-zhouhan)，OSDI 2023**。Sec. 6.1 / Table 2 比较模拟器与真实系统的 **SLO 达标率**，论文称误差小于 2%，表中最大差为 **1.6 个百分点**；并非逐请求时延误差低于 2%。其论文脚注明确主要研究单次前向的非自回归模型。可学“以系统决策结果验证模拟器、广泛搜索用模拟、重点结果用实机”，不能无条件外推到当前生成模型。

前三篇已核对全文；AlpaServe 的来源及摘录保存在同一 literature 目录。引用数字各有不同指标、模型、硬件与统计粒度，不能横向当排行榜。没有证据支持这些论文已经解决任意动态共驻与 FIFO 的精确预测。

## 后续验收改为有限、面向决策的流程

新的工程标准单独版本化，旧结果不回判。建议/后续采用的策略参数：每个候选、负载和任务的**整体 mean 误差 ≤15%、整体 P95 误差 ≤25%**；同一 offered cohort 和固定窗口定义下吞吐误差 ≤10%；完整 GPU board episode 能耗误差 ≤15%。这是项目工程容差，不是论文公认标准。完整 episode 包括启动/priming/warmup/正式到达/排空；不宣称主机总能耗。

六项效用仍保持原归一化和权重。先冻结有限候选面板，再比较选择损失，不要求任意相邻候选 100% 排序正确。以实测效用 `max(U_panel)-U_selected` 衡量面板内 regret；候选近似并列容差和可接受 regret 均采用 **0.02 个原效用单位**，不除以可能为负或接近零的 U。预测 top-3 连同原基线、预声明端点和代表性网格方案实测；对未测候选不声称全局最优。实测不确定性跨过该容差时记为无法区分，不强行宣布赢。用于选方案的运行与最后固定方案的确认运行分开。

阶段 work、逐请求误差、queue-depth 和低层 CUDA/主机诊断继续输出，**不再单独阻断整体评估**。仍须保留完整 cohort、无未来信息泄漏、输出质量、真实能耗/显存边界及原 `safe_factor=1.110854`、`rho<=0.8`。缺证据写 UNKNOWN，不能由新宽松指标补出数据。

执行顺序：

1. 完成已启动的最小 CUPTI 探针并保存结果；无论其机制归因是否成功，不自动追加 profiler 链。
2. 选定目标 runtime，构建面向端到端统计的共驻服务分布/低维残差候选，保留现有 FIFO 事件引擎；不得因少数 solo band 不重复就拒绝开展整体开发评估。旧四专用模型仅作匹配域基线。
3. 新增一次有边界的整体开发评估，分别检查目标负载、驻留、副本；若失败，只修对整体结果影响最大的因素。预测 top-3 加基线/端点实测形成闭环，避免为小误差继续无限排障。
4. 模型、候选、输入和运行协议冻结后，使用未参与开发的运行/输入进行确认。当前保留的 6110491/6110492 不因本次重算而消耗；随机种子不同本身不能证明输入独立。
5. 验收通过的适用域即可进入优化器等预算比较，并按用户原顺序再开展总效用改进；域外未知不否定域内可用，也不伪造全域资格。

本次只冻结验收**策略**，尚未绑定新模型、候选面板和输入，故不是已冻结可启动的独立验证 campaign，也未取得整体资格。目标从“所有底层误差都过关”调整为“在声明范围内选出的方案足够好”；不承诺一个尚无实验依据的完成时间。
