# Module 21D：LOW Utility Variance Diagnosis

决策：**`LOW_COLOCATION_OR_MODEL_MISMATCH`（C）**。当前 LOW 候选暂停，不直接延长其 GPU 效用实验。已观测到显著的服务时间画像偏离和背景任务运行状态变化；三次配对不足以证明总体系统性负收益，也不能把全部问题归结为样本少。没有建立可迁移修正模型。

本阶段只读取历史文件、进行 CPU 计算，未启动 GPU、未修改历史请求、权重、归一化、质量准入或模型池。保护并核验了 Module20、Module21、Module14F 结果及样本/质量文件共 782 个文件的前后 SHA256；全部一致。冻结引用的源码、原始结果及参考文件 SHA256 也全部匹配。

所有差值均为 **Proposed（LID 交给 Qwen，不驻留 MMS）减 Control（驻留 MMS 并处理 LID）**。“G-only”仅指 LID 路由；两边均有 Text/Image/OCR Specialist。

## 六个直接回答

1. **三次 ΔU 为什么波动大？** 主要是 Text 的配对 mean/P95 延迟差异变号，加上 OCR、Image、VQA 和 LID 尾部波动。按包含协方差的方差分解，Text 占总 ΔU 方差约 **79.46%**，LID 仅 **4.37%**，ASR **0.11%**。LID/ASR P95 的确稀疏不稳定，但不是总波动的主要来源。能定位到指标和记录，尚不能确定 Text 状态变化的物理根因。
2. **哪一项使均值为负？** mean 损失 **−0.023014**、P95 损失 **−0.021942**，合计 **−0.044955**，超过显存收益 **+0.026138**。逐任务最大的平均延迟损失是 **LID −0.030138**，其次是 **Text −0.011852**、OCR −0.004447。仅 LID 加显存已为 **−0.004000**，背景任务净变化再贡献约 −0.014817。
3. **显存收益与理论一致吗？** 节省方向一致、数量不完全一致。理论 safe memory 节省 **6380.745 MiB**，实测三次 **5105.485 / 5698.681 / 5934.182 MiB**，平均 **5579.449 MiB**，比理论少 **12.56%**。理论显存效用收益 +0.029892，实际平均 +0.026138。计算口径核验通过。
4. **存在真实共置退化吗？** 存在真实服务画像偏离和可追溯的共享 Qwen 队列阻塞。不能证明“移除 MMS 导致背景模型持续退化”：Text 的配对服务时间差异为 **+2.775 / +0.217 / −1.281 ms**，方向不一致。缺少同条件单模型基线、时钟/温度及内核/预处理时序，无法分离共置、稀疏空闲状态和画像输入差异。
5. **延长还是放弃？** **不延长当前候选；暂停这一未经条件匹配的 LOW 效用预测候选，先诊断画像。** 这不是 B 类“已证明系统性负收益”，也不支持为了过关只追加请求。若后续条件匹配的独立证据仍不能支持原始效用优势，应放弃该 LOW 候选；不能承诺增样本会获得正收益。
6. **MID/HIGH 是否仍值得探索？** 可以后续独立探索，尚无 GPU 验证。MID 的 CPU 预测裕量约 +0.595139，较值得独立检验；HIGH 仅 +0.043004，且争用/容量风险更高，优先级低于 MID。均需先考虑当前画像失配，重新冻结独立协议，不继承 LOW 的结果或自动继续原 campaign。

## 稀疏尾部与真实共享队列事件

采用与原结果一致的 NumPy linear percentile，位置为 `0.95*(n−1)`。LID n=10/9/9、ASR n=12/6/7，P95 均由最大的两个请求插值决定。LID rep1 对最大值的插值权重为 55%，rep2/3 为 60%；ASR 分别为 45%/75%/70%。即使假设 iid，9 个请求没有抽到总体最慢 5% 的概率为 63.0%，6 个为 73.5%；这些概率仅用于说明尾部证据稀疏，不作为独立部署样本推断。

可追溯事件：

- Proposed rep1 `measurement:305`，LID `lid_001326`：E2E **777.334ms**，服务 **256.156ms**，排队 **520.857ms**；上一同 Qwen worker 请求 `measurement:303` 是 ASR，其完成晚于本请求提交约 **520.756ms**。该真实碰撞明显抬高 LID P95。
- Proposed rep3 最大两个 LID 请求分别被前一 VQA 阻塞约 **179.786ms / 178.478ms**；rep2 LID mean 排队只有 **0.253ms**。这解释了 LID 尾部差异的部分来源。
- VQA 本身只有 25/27/20 个请求，P95 由上端约 2–3 个请求决定；rep2 两边都有较长 Qwen 队列尾部，配对后大部分抵消。

全部任务的 P95 支撑请求、sample ID、服务/排队及前驱请求保存于 `statistical_diagnosis.json`。没有发现持续积压、未完成队列或失败运行；原分析的 27 个 fresh worker 均 steady。

## 公平性、口径及证据限制

- 两边 warmup 和 measurement 的任务、sample、offset、routing/replica uniforms 全部相同，并逐记录匹配冻结轨迹；120s 计划/实际测量窗口一致。arrival seed 分别为 21101、21202、21303，执行顺序为 P/C、C/P、P/C。
- 三次每边正式请求为 1016、1008、1009，总计 **6066**；offered=submitted=completed=窗口内 completed，无截尾，无 drain 后补完成。warmup 和 path probes 都在正式测量之前完成，规则为 10s warmup、最多 60s drain、2s idle。
- 同一 probe 规则按驻留模型的准入路径执行三次：Proposed 24 个，Control 27 个，额外三个是 MMS LID。因此正式 offered trace 公平，但前置 probe 的工作量并非完全相同。稀疏 warmup 也未强制每任务相同最小数量，日志不能证明缓存/频率状态一致。
- 同一 GPU UUID/driver，fresh PID、不存在日志观测到的 foreign GPU PID，退出与释放正常。但 0.5s telemetry 不能证明不存在瞬时干扰；没有记录 clocks、temperature 或内核时序。worker handler wall time 不等于纯 GPU kernel time。
- `safe_memory = safe_factor * max(postwarm_owned_idle_mean, postmeasurement_owned_idle_mean)`，safe_factor=1.110853955254881，预算 32019.2544MiB。重算、idle 采样、峰值及预算均通过；该定义是冻结的安全余量画像，不是未采样瞬时峰值保证。
- MMS 实际 idle 分别为 **4596 / 5080 / 5226MiB**，冻结表为 **5744MiB**；共同 Qwen allocation 的配对变化也影响节省量。这解释显存实际收益略低于理论，并非把权重或预算换了口径。
- 吞吐按原定义使用固定 expected offered=1002，而非实际 Poisson offered。三次计数均高于 1002，`T_loss` clamp 为 0。本次没有窗口后完成，所以该口径没有造成配对误判；其他实验中额外到达可能掩盖少量边界延迟完成，不能修改本次定义来追求收益。
- 同一原质量准入与模型池，所有 routed path 合法且无 invalid closed-set output。小样本 observed accuracy/WER 不用于改动原先完整质量评测的准入；例如 Text 此冻结小池 descriptive accuracy 低于历史 0.925，不另设门槛或填充质量值。
- 冻结池存在循环复用：每次 Text 只有 30 个不同输入，重复约 16–17 次。各 repetition 的到达及 fresh 进程不同，但请求不是独立部署实验，推断也不自动推广到不同输入总体。

## 三次独立配对的统计可靠性

|效用分项|配对均值|样本 SD|样本方差|nominal paired 95% CI|
|---|---:|---:|---:|---|
|Memory|+0.026138|0.002000|0.000004002|[+0.021169, +0.031107]|
|Mean|−0.023014|0.033991|0.001155416|[−0.107453, +0.061426]|
|P95|−0.021942|0.054599|0.002981084|[−0.157574, +0.113691]|
|Throughput|0|0|0|[0, 0]（仅本次观测）|
|Total|−0.018817|0.090498|0.008189834|[−0.243626, +0.205992]|

以 **n=3 GPU repetition 配对、df=2** 为单位，未把请求数当成部署实验数，未用请求 bootstrap 构造假精度。CI 是探索性的，正态、独立及稳定状态假设未验证，亦未作多任务比较校正。原 Module21 effective acceptance 是三次有效 ΔU 均>0.01；CI 仅报告，没有重写该 gate。

**无法可靠区分总体 ΔU>0.01。** 对 `H0: E[ΔU]≤0.01` 的 nominal 单侧 paired t p≈0.6817；无正收益证据。总体负收益同样未被证明，所有背景任务的配对差异 CI 跨零。配对 SD 的正态 iid nominal 95% 区间为 **[0.0471, 0.5688]**，反映仅三组数据的规划不确定性。

以下是成本敏感性计算，**不是推荐执行的延长方案**。假设当前 SD 估计正确，所有方差按 `120/window` 缩小、无状态漂移/共置方差下限，目标检出真实均值 0.02 相对门槛 0.01，单侧 α=0.05、power=80%，使用非中心 t 分布求固定独立配对数：

|每边窗口|预期 ASR/LID 请求|80% power 所需固定配对数|95% CI 半宽≤0.01 配对数|power 方案纯测量 GPU 时间|
|---|---|---:|---:|---:|
|120s|6 / 12|508|318|33.87h|
|1200s|60 / 120|53|34|35.33h|
|4000s|200 / 400|17|12|37.78h|

4000s 的尾部数量启发式为预期 ASR 最慢 5% 约 10 个、LID 约 20 个，并非精度保证；Poisson 计数随机、输入仍可能循环。如果 Text/运行状态方差不随窗口下降，长窗口仍可能需要接近 508 个独立配对，而不是 17 个。上述成本不含加载、probe、预热、idle/drain，且当前 SD 不确定，不能据此承诺足够样本或正收益。

在任何效用延长之前，应先获得同样样本/稀疏空闲条件的单路径服务证据，以及分离 MMS residency 与 Qwen 新增 LID 争用的对照。仅举成本例子：四条单路径×三次 fresh repetition×120s 是 24 分钟纯测量；三组额外 residency 对照至少再需 12 分钟。加载开销、LID 稀疏样本及因果设计可能增加成本。这里只估算，**未安排或运行补测**。
