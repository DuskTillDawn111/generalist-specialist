# 新实验的事前 CPU 验收协议建议（本轮不执行 GPU）

这是一份后续新实验的协议建议，不覆盖 Module 32G 的冻结协议或失败 Gate。

1. 保留在线路由 P95 ≤ 1 ms、控制检查 10 ms 原门槛及代码原有 `elapsed >= 10 ms` 即停止的边界。统计完整样本，不扣除观测开销，不剔除长尾，不替换失败随机种子。
2. 把“历史倍率”和“到达时间压缩倍率”分成两个明确的字段。历史倍率增加已终结的记录数量；到达压缩改变每秒事件量，两者不得再统称为 8 倍加速。
3. 首先执行同历史队列、同真实到达间隔的完整 2400 秒 CPU 在线回放，在真实 sender/collector 并发、0.5 秒遥测、10 秒 checkpoint/fsync 条件下验收。这一阶段仍未证明真实 GPU 推理下的表现。本轮 120 秒原速前缀不能替代该阶段。
4. 历史长度压力另设 8 倍历史、原速到达的完整测试。保留增量路由器与所有合法历史语义，禁止在计时期间逐请求持共享锁做全档案 oracle 扫描。用真实状态增量事件和冻结投影快照，在性能测量之外进行完整历史 oracle 对照。每个状态提交都需记录顺序及 enqueue/submit/complete 的实际提交时刻，避免混用 reader 时间和 collector 更新时间。
5. 8 倍及 50 倍到达压缩另列为压力诊断，不冒充部署实时验收。仍报告同一 10 ms 门槛下的所有失败。若加速组超限，保留失败，先区分计算、锁和 off-CPU 原因；不得将其宣称为通过，也不得追溯性豁免旧 Gate。
6. 控制检查不做同步落盘。超限异常离开原计时区域后，立即将探针和上下文持久化，随后由 `finally` 输出完整样本、线程状态及异常栈并清理线程。正式验收遇硬失败停止；本轮诊断的继续采样仅用于保留分布，该组仍应判失败。
7. 分段计时使用同一进程 `perf_counter` 墙钟；线程 CPU 起终点须包含在墙钟区间内。分别记录 state_lock 等待/读状态/释放/判断条件、原生线程 TID、锁占有者区间、上下文切换与遥测 JSON/fsync 重叠。检查采样端点一致性，避免墙钟停止后继续取 CPU 终点。
8. cgroup CPU throttling、线程 CPU 和自愿/非自愿切换均需保留。`sched_schedstats=0` 且 `perf_event_paranoid=4` 时，不能把 wall−threadCPU 全部叫作 OS runnable delay。若要区分 OS 与 GIL，需要在具有权限的隔离环境增加只读 sched_switch/GIL 观测；本轮不改系统内核设置。
9. 通过新协议 CPU 工程验收后，才可在另行授权的实验中重新进行 GPU 工程预检，并使用实际传感器。不能用 CPU 假传感器记录、32F 历史 GPU 成功或本轮结果替代新的真实 GPU 运行。

不改变模型、负载、质量、驻留、副本、路由阈值、背压或正式效用；不自动开始正式长窗口。
