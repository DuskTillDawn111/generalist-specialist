# Runtime bottleneck and repair

Original DeploymentRuntime.pending accumulates completed requests to support archival diagnostics, duplicate detection and late responses. Module32B/32C phase scans the entire archive before every arrival for backlog age, then scans it again under the existing RLock on every dynamic ASR decision to project Phi/Whisper queued/submitted state. The projection also repeatedly evaluates max(cost_bins) as dict.get's eager default. These scans grow with cumulative history, although most records are already complete. Original policy counters are constant-size; the policy itself is not the measured performance bottleneck.

Module32C full-wrapper P95 in successive300s blocks was0.287837,0.431514,0.550984,0.701872,0.880027,1.042435,1.151796,1.334800ms. Overall1.221860ms failed the original1ms acceptance rule. Pure historical decide replay P95 was0.004684ms. CPU projection profiling supports history growth; historical lock/GIL scheduling was not separately timed, so these observations cannot precisely apportion all GPU-run overhead.

The old SafeMonitorV2 also deep-copied every planned/live/terminal record under runtime.lock on every0.5s sensor sample BEFORE checking its10s checkpoint interval. It creates history-dependent lock and GIL work even when no durable checkpoint is due. Disk and sensor I/O were already outside the routing lock. Router decision logging is appended after the timed lock block, not synchronous per-decision fsync.

router_optimized.py is an isolated copy of the native transport, with an OrderedDict active index and per-worker active dictionaries updated at enqueue, submit, successful/error completion, send failure, queue overflow, worker exit and drain timeout under the same RLock. Each transition/count/oldest lookup is O(1). Completed records are removed only from the active index; archival pending remains intact for native result matching, duplicate and incomplete/late-response semantics. Original backlog thresholds remain300/120s. Projection preserves original archive insertion order and original policy sort, hysteresis, share/risk budget, cooldown and floating-point sum order. Projection costs O(A), original decide O(AlogA), with A bounded by the existing safety limit rather than cumulative history N. Full snapshots necessarily emit the A active records; no claim of unbounded-queue constant cost is made. The eager default is cached once per phase. No new external routing lock is added.

The incremental monitor gates checkpoint time BEFORE snapshot work, consumes terminal transitions once, snapshots only new terminal and currently active records under runtime.lock, and builds/serializes the complete coherent planned cohort outside that lock. Immutable worker payloads are never changed in place. The final annotation snapshot occurs after arrivals stop. Archive and output storage remain O(N) by design; the router's active-state storage follows concurrent backlog, not elapsed history. The terminal-change queue is consumed by the journal and tested separately from durable archival memory.

Exact same-state replay uses all saved32B/32C dynamic warmup/formal decisions. Collector-applied time was not logged historically; reader receipt and worker END are not treated as an oracle for host visibility. Saved past_state_snapshot is the authoritative observed reference. Actual native collector fixtures check error, duplicate, timeout, late and exit behavior. The paced2400s historical cohort benchmark runs real sender/collector threads, original0.5s telemetry cadence,10s fsync journals and1x/8x retained archive. It accelerates arrivals50x; it is explicitly not a2400s wall-time soak or GPU acceptance. The complete lock+projection+decide+enqueue time is measured and the original1ms threshold applies again during actual GPU windows.

An initial CPU stress fixture allowed its synthetic completion thread to overtake submission, which is impossible in the native worker transport. It caused a state mismatch before GPU/freeze. The fixture was repaired with a per-request submit-before-response barrier; the failed log is preserved in cpu_fixture_initial_failure/. This changes neither policy nor runtime thresholds and is not a discarded GPU outcome.

## Engineering preflight failure and CPU-only revision

The frozen v1 GPU preflight E0_S completed281/281 requests in180s, steady, with valid native timestamps/full journal/residency and no sampled thermal slowdown. It nevertheless failed the original10ms nonblocking-control check: max monitor.check19.360993ms, max phase publish0.488940ms. The incremental snapshot's runtime-lock sections were short (maximum0.244403ms), but coherent_records incorrectly kept state_lock held through full-cohort deep-copy. Monitor.check also acquires state_lock, so its key-path delay remains exposed even though the pure routing wrapper is fast. No dynamic GPU arm or formal arm was executed; the frozen no-retry stop remains in force.

monitor_cpu_revision.py captures phase/cache references under state_lock and releases that lock before runtime snapshot updates and deep-copy. Phase publication replaces cache containers; the sensor sample_lock serializes producers, so a captured old phase/cache pair remains coherent during a phase transition. This v2 is CPU-only, preserves policy semantics and is tested with per-arrival monitor.check timings under the same paced concurrent2400s-scale workload. It was NOT used for any GPU inference and must not be substituted for the failed v1 frozen GPU source. Original v1 files/manifest/raw and failure are retained. Results live separately in cpu_repaired_v2/.

The initial CPU fixture also failed to redirect inherited telemetry output globals, affecting only Module30's ephemeral live_progress.json and two newly created CPU journals. The journals were relocated here; the original progress was reconstructed from untouched historical checkpoint data, not byte-exactly restored. No historical raw requests, Gate, source or model weight changed. The strict all-files preservation check remains false, and formal validation is cancelled independently of the engineering failure. See cpu_output_namespace_incident/incident.json; the original fixture is retained for evidence, and safe reruns explicitly redirect all outputs.
