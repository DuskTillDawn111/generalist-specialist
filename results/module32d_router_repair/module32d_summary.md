# Module32D：路由运行时修复与受控验证

最终 Gate：`DYNAMIC_VALIDATION_INVALID`。工程性能修复有 CPU 证据；独立效用验证没有执行，三组 ΔU、均值和置信区间均为 NULL。没有把预热、短时预检或历史 U 当成正式收益。

1. **为什么开销随时间增长？** 原 wrapper 每次扫描保留全部已完成请求的 `pending` 表；遥测也在检查10秒日志间隔之前，每0.5秒在共享锁下深拷贝完整 cohort。修复以增量活跃索引维护状态、O(1) 更新计数及最老请求，并缓存代价默认值。完整历史仍保留供审计、重复及迟到响应处理。投影 O(A)、原决定 O(AlogA)，A 受原300/120秒背压保护，与累计历史 N 脱钩；没有假称任意并发规模均 O(1)。

2. **是否满足1ms？** 最终 CPU 修正版在真实 sender/collector/遥测/10秒 fsync 并发下重放完整2400秒请求规模，分别保留6838/30771条历史记录：路由 P95=0.102856/0.133722ms，P99=0.170911/0.230985ms，最大=0.612312/10.264605ms；控制检查最大=0.089180/0.105960ms。P95<1ms及原10ms控制门槛均通过。回放50倍加速、每次约48秒，**不是2400秒壁钟/GPU验证**；真实长窗口仍未验收。最大值仍有调度尖峰，不承诺每次均小于1ms。

3. **是否保持原语义？** 1381次32B/32C历史决策的全部返回字段逐项精确相等，数值容差0；原策略源码、阈值、预算及滞回/背压规则字节一致。测试原生完成、错误、队列溢出、重复、超时、迟到响应及worker退出，并通过旧快照跨阶段延迟时不丢新阶段终态的测试。历史 collector 生效时刻未单独记录，使用保存的实际可见快照；不以 worker END 或读入时间冒充当时可见状态。更快运行时可能改变实际看到的状态，不宣称未执行过的在线轨迹路由相同。非抢占 ASR 仍可能阻塞随后到达的 VQA。

4. **GPU 环境是否控制成功？** 唯一GPU预检 E0_S 完成180秒、281/281请求，steady；原38°C/40°C启运与驻留冷却、显存、原生时钟、完整日志和采样降频检查通过。但 `monitor.check` 最大19.360993ms超过原10ms，冻结方案停止；E0_D未执行，故5°C配对温差、15%频率差及长窗口环境可比性未验证。原因是 v1 快照仍在深拷贝期间持有控制状态锁；v2释放该锁并完成CPU验证，**未进行GPU补跑**。温差不被单独当成降频证据。预检源码/清单/raw/失败结果均保留。

5. **Dynamic 有真实独立正效用吗？** 未知。正式GPU运行0次；没有动态GPU执行、独立配对、Text/VQA尾延迟对比、Whisper配对等待收益或Phi干扰的32D收益证据。六任务效用公式与归一化参考保持原20A定义，禁止截尾、换种子或用诊断U通过Gate。三个新测试种子320401–403和所有匹配轨迹保留为NOT_EXECUTED。

6. **是否进入正式优化器集成？** 不进入。现阶段支持原策略的CPU工程修复，尚不支持长窗口合法效用或独立复现。没有修改正式优化器、模型权重、32B/32C Gate，也没有自动启动下一Module。
